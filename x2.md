# Accessible Libraries Integration

I would make **open-first integration** a formal principle for QUILL:

> QUILL should prioritize services that permit public catalog access, require no commercial agreement, and allow lawful direct reading, listening, or downloading before pursuing closed partner integrations.

## Recommended priority

| Priority | Provider                            | Search |                 Direct access in QUILL | Account or agreement       |
| -------- | ----------------------------------- | -----: | -------------------------------------: | -------------------------- |
| 1        | LibriVox                            |    Yes |           Audio streaming and download | None                       |
| 2        | Project Gutenberg                   |    Yes |     EPUB, HTML, text and other formats | None                       |
| 3        | Standard Ebooks                     |    Yes | High-quality accessible EPUB downloads | None                       |
| 4        | NLS BARD Public API                 |    Yes |                 Catalog only initially | None for search            |
| 5        | Open Library                        |    Yes | Public-domain books; handoff for loans | None for search            |
| 6        | Internet Archive                    |    Yes |                Unrestricted files only | None for public items      |
| Later    | Bookshare                           |    Yes |    Protected books after authorization | Partner approval and OAuth |
| Later    | CELA, RNIB Bookshare, Learning Ally | Varies |                 Restricted collections | Partnership or membership  |

## Release 1: the best open-content experience

### 1. LibriVox

This should probably be the first complete provider because it connects naturally with the QUILL media and radio infrastructure.

LibriVox provides a public catalog API with XML and JSON output, and its catalog is explicitly intended for developers building services on top of its audiobooks. ([LibriVox][1])

QUILL could support:

* Search by title, author, reader, genre, language and identifier
* Stream without downloading
* Download an entire book
* Download individual chapters
* Resume playback
* Playback speed and sleep timer
* Chapter navigation
* Narrator filtering
* Save books and chapter positions through QuilleSync
* Bookmark exact chapter and time positions through QuilleBeacon
* Send books into a QUILL audiobook library

This gives QUILL a genuinely complete result rather than merely opening a website.

### 2. Project Gutenberg

Project Gutenberg should be the first major ebook source.

We should **not scrape its normal website**. Gutenberg specifically directs automated applications to its machine-readable catalogs, feeds, mirrors and robot-harvest facilities. Its catalog metadata is granted to the public domain. ([Project Gutenberg][2])

QUILL could offer:

* Title, author, language and subject search
* EPUB with images
* EPUB without images
* HTML
* Plain text
* Audiobook formats when available
* Open directly in the QUILL editor or reader
* Save to the user’s library
* Convert between permitted formats
* Read aloud using QUILL Speech
* Generate navigable heading and chapter structures
* Search within downloaded books
* Create bookmarks, notes and annotations

We should maintain a local searchable catalog index rather than calling Gutenberg for every keystroke.

### 3. Standard Ebooks

Standard Ebooks has a smaller collection but exceptionally strong production quality. Its books are carefully formatted, accessible, open source, free of cost and released without U.S. copyright restrictions. Standard Ebooks also publishes OPDS catalog feeds for browsing and downloading through reading applications. ([standardebooks.org][3])

It is ideal for demonstrating how polished the QUILL reading experience can be:

* Semantic EPUB navigation
* Proper chapter structure
* Footnotes and endnotes
* Accessible tables of contents
* High-quality typography
* Clean read-aloud extraction
* EPUB, advanced EPUB, Kindle and XHTML choices where available

When the same title exists in Gutenberg and Standard Ebooks, QUILL could label the latter:

> **Recommended edition — professionally proofread and formatted**

## Release 2: open discovery services

### 4. NLS BARD public search

NLS should remain a very high priority because of QUILL’s audience, even though its protected books cannot initially be downloaded through QUILL.

The public API requires no password and searches metadata for the entire BARD collection. Access to the actual BARD files remains limited to eligible patrons through the password-protected service. ([The Library of Congress][4])

QUILL should provide:

* Full BARD catalog search
* Audio, braille, magazine and music filters
* Author and narrator search
* NLS book-number search
* Recently added materials
* Save to a wish list
* Copy the book number
* Open the official BARD record
* Announce whether the result is audio, braille or another format

The result should clearly say:

> **BARD catalog result — eligible BARD account required to download**

This would still be extremely valuable, especially if the BARD website’s own search experience is less efficient for keyboard and screen-reader users.

### 5. Open Library

Open Library provides public APIs for book search, author lookup, subjects, covers and other bibliographic information. It explicitly prioritizes open-source, educational, library and mission-aligned applications, although it expects caching and reasonable request volumes. ([Open Library][5])

QUILL could use it for:

* Broad bibliographic discovery
* ISBN lookup
* Edition comparison
* Subject browsing
* Finding public-domain editions
* Locating LibriVox versions
* Connecting related authors and works
* Enriching incomplete metadata from other providers

Open Library distinguishes between books that are freely readable, borrowable through an account and preview-only materials. ([Open Library][6])

Therefore, every result needs an explicit access state:

* **Free to read or download**
* **Account required to borrow**
* **Preview only**
* **Metadata only**

I would initially avoid implementing Open Library borrowing inside QUILL. We can link users to its official borrowing interface while handling public-domain material directly.

## Release 3: curated Internet Archive access

Internet Archive provides public tools and APIs for search, metadata and downloading. ([Internet Archive][7])

However, it contains an enormous mixture of:

* Public-domain books
* Community uploads
* LibriVox recordings
* Old-time radio
* Music
* Software
* Scanned documents
* Borrow-controlled books
* Items with incomplete or inconsistent rights information

For that reason, it should come after the simpler providers.

The first Internet Archive integration should search only curated, rights-safe collections such as:

* LibriVox
* Community Audio with explicit licenses
* Public-domain texts
* Government publications
* Accessible historical recordings
* Old-time radio collections
* Public-domain podcasts or lectures

QUILL should never assume that every downloadable-looking Internet Archive file can be redistributed or imported. Each result needs a rights and availability evaluation.

## Build OPDS support into the foundation

Before implementing every individual provider, QUILL should gain a reusable **OPDS catalog client**.

OPDS is an open, decentralized standard for discovering and acquiring digital publications. It supports searching, browsing, pagination, metadata and acquisition links. ([opds.io][8])

That gives us two benefits:

1. Standard Ebooks and other OPDS catalogs become easier to add.
2. Users can add their own compatible catalogs later.

A user-defined catalog could include:

* A personal Calibre library
* A school or university repository
* A nonprofit accessible-book collection
* A local network library
* A future QuillVille community catalog

## Proposed first milestone

I would define the initial **QUILL Open Library Hub** milestone as:

### Included providers

* LibriVox
* Project Gutenberg
* Standard Ebooks
* NLS BARD public catalog
* Open Library metadata and public-domain availability

### Included capabilities

* Unified search across all providers
* Provider-specific search
* Title, author, narrator, subject and language filters
* Audio versus ebook filtering
* Public-domain-only filter
* Direct streaming and downloading where permitted
* Open in QUILL
* Add to library
* Favorite or create a reading list
* QuilleBeacon bookmarks
* QuilleSync reading position
* Duplicate-title grouping
* Accessible result details
* Clear source, format, rights and availability announcements

## The guiding rule

Every result should be placed into one of four unmistakable categories:

1. **Open now** — QUILL can stream, read or download it directly.
2. **Public catalog record** — QUILL can search it but must hand off access.
3. **Account required** — the user must authenticate with the provider.
4. **Partner integration required** — QUILL needs an organizational agreement.

That lets us deliver substantial value immediately while Bookshare, Learning Ally and other partnership discussions proceed separately. The closed providers then become additions to an already functioning library platform rather than blockers for the entire project.
