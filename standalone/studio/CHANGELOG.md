# Changelog

All notable changes to QUILL Studio are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.0] - built, not yet released

QUILL Studio 2.0.0 is the next Studio release after Audio Studio 1.0.0. The previously unpublished 2.2.0 build is renumbered to 2.0.0 for the QUILL Studio rename. Shared-runtime compatibility does not require matching the other apps' version numbers.

This version is built but not yet published: Audio Studio is not offered in the QuillVille menu, and there is no 2.0.0 download page. Everything below is in the build.

Testing build: **2.0.0 (build 2)**. Builds since the first have not been published.

### Choose Your AI, Ask and Describe a Picture (2026-11-01)

- **One AI choice, the family's.** The AI menu has Choose Your AI (Ctrl+4), Which AI Am I Using (Ctrl+8; twice opens Choose Your AI), Ask (Ctrl+6), AI Usage, Use My Own AI Key and Privacy Agreement, the same rows as the editors. Studio's old question about which AI should read a picture is gone: every picture goes to the AI chosen there. Studio still signs in as QUILL Studio, and an existing sign-in stays in use.
- **Ask about your setup.** Ask sends the last pre-flight check, what it measured, the last recording check, the recording running now and the name of the open book. Never a picture or sound.
- **Describe a Picture** (Ctrl+F5) describes one picture, or one frame of a video at the time you give, fitted to the AI in use. The same picture asked about again sends nothing.
- **Pictures are asked about once per connection.** The first picture on a connection says where pictures go and asks Yes or No, No the default, and asks again when the company changes. Screenshots are still confirmed every time. A connection that cannot see sends nothing and offers the switch.
- **Use My ChatGPT Subscription** moved from the Capture menu to the AI menu and now has a key, Alt+F5.
- **An AI cell** ends the status bar: press Enter on it to open Choose Your AI.

### Live broadcast: a slow link, short gaps and proof of air (2026-10-31)

These lessons come from Tony Gebhard's TG Drop Deck, an MIT-licensed broadcast cart program. Studio's code is its own; the lessons are his.

- **A slow connection no longer stalls the saved copy.** The stream and the saved copy each have their own queue and their own writer, so a slow upload can hold up only the stream. The mix and the saved copy keep going. Up to about 30 seconds of stream is held while listeners fall behind, and Studio says once when they are 5 seconds behind. After that the oldest stream sound is dropped, counted, and said once. Only the stream ever loses sound this way. (BCAST-026)
- **No more tiny gaps from bursty sources.** Each source in the stream fills to 100 ms before it is played, and again after it runs dry, so sound that arrives in small bursts is no longer cut into gaps you hear as a change in pitch. A source that runs ahead is trimmed back to that 100 ms, instead of drifting to 2 seconds late. The status shows short gaps and trims when there are any. (MX-186)
- **The stream keeps time with the microphone.** The mix still runs on a timer, because loopback sound stops arriving when nothing is playing. The timer is now corrected against the sound the microphone actually delivers, so the two clocks no longer drift apart over a long show.
- **"On air" means sound is reaching the server.** Studio says "On air" and "The stream is back on air" only after the server has taken 2 seconds of encoded sound, not as soon as the connection opens. If the server stops taking sound, Studio says so once, and the status shows that you are off air. (BCAST-027)
- **A refused password stops the retries.** If the server refuses the user name or password on any attempt, not only the first, Studio stops trying and gives the reason.

### Display scaling, named controls, licensing and packaging (2026-10-27 to 2026-10-31)

- **Shared-runtime licensing.** Installed editions use the QuillVille Runtime,
  which currently carries PyMuPDF 1.28.2 under AGPL-3.0 through the shared
  GLOW dependency; Studio does not itself expose GLOW. Release-specific source
  and legal review are required before the next public release. Portable
  contents must be checked separately. See Licences and Notices and the
  PyMuPDF distribution review.
- **Chapter sound provenance.** The default page-turn-like cue is now generated
  from scratch by QUILL rather than using a recording with unconfirmed origin.
  Custom chapter sounds remain available.
- **Speech packaging.** Studio portable builds now copy only supported speech
  engine folders, rather than all speech data. Distribution of a legacy voice
  engine has stopped pending licensing review. A separately installed copy
  still works; complete removal and previous package review remain open.
- **Shared Windows runtime.** Windows OCR and Media projections move to
  PyWinRT 4.0.3 and the Windows SDK 10.0.28000.2705 line. The Windows Media
  engine releases device references and event handlers on shutdown.
- **Production planning.** The consolidated Studio plan proposes a shared
  Converter round trip and reviewable local or explicitly consented cloud
  transcription. These proposals are not delivered features.
- **Controls that had no label now have a spoken name** (2026-10-30).
  JAWS, NVDA and Narrator used to announce them as a bare role, such as
  "edit" or "list". Now they say what they are: the choices and number boxes in Convert
  Audio, the summary of your choices at the end of the wizard, and the
  translation voice and languages to export in the translated speech export.
- **Sharp text at any display scaling** (2026-10-31). QUILL Studio now handles
  each monitor's scaling itself instead of letting Windows stretch it, so
  text stays sharp at 125, 150 and 200 percent and on monitors with
  different scaling, and windows and list columns keep their proportions.
  Setting the environment variable `QUILL_DPI_UNAWARE` to `1` turns this off,
  for diagnosing a display problem (#1702). User guide: "Text looks blurry, or a window is the wrong size".
- **Pygments in the notices** (2026-10-31). The shared runtime now bundles
  Pygments, which QUILL and QUILL Lite use to read code and web pages for
  spell check, so QUILL Studio's third-party notices list it.

### The new name: QUILL Studio

- Rename the application to **QUILL Studio**. Window, tray, wizard, runtime chooser, installer display name and shortcuts use the new name. Existing audiobook workflows and shortcuts are preserved.

### Screenshots, global hotkeys and AI inspection (2026-10-26)

- **Choose exactly what to capture.** Select a named visible window (listed by title), an individual display, the full desktop across all displays, the active window after a delay, or a rectangle entered as Left, Top, Width and Height in physical pixels. The window list stays short by default by showing top-level task windows (similar to Alt+Tab); enable the advanced "show all windows" option when you need tool windows or helper dialogs, and use the window properties view for process IDs and identifiers. Negative coordinates support displays left of or above the primary display. Refresh the target list without silently substituting a desktop capture for a missing target. Restore minimized windows before selecting them.
- **Delayed, immediate and repeat capture.** Set a 2-to-60-second delay and an absolute output folder, start, and cancel while capture is pending. Immediate commands capture the active window or full desktop. Repeat the last selected target with its chosen folder and delay. Completion is announced without moving focus away from the application being captured.
- **Guided capture without pixel calculations.** Recommend the whole named window; guided regions derive Whole source, Top/Bottom/Left/Right half or Middle quarter from a named source. Read a selectable, announced capture plan explaining exclusions, overlap and review steps. Keep exact coordinates optional under advanced settings, initialize them from the selected portion, reject moved/resized/replaced source windows and keep actions available beside scrolling content. Richer user-guide examples, troubleshooting and a PRD coverage audit distinguish this from still-pending UIA selection, annotations and full screenshot acceptance.
- **Configurable global screenshot hotkeys.** Capture > Capture global hotkeys offers active-window, full-desktop, repeat-last-target and cancellation actions while Studio is in the tray or another application is active. Assign or clear keys in the shared native manager. No global capture key is registered by default. Windows registration conflicts are reported, only successful registrations dispatch, unrelated apps' saved bindings are preserved, keys are released on exit, and Safe Mode leaves global registration inactive.
- **Keyboard discovery.** Every capture action is in the Capture menu and command palette, with app-scoped in-app shortcuts. Capture keeps the established library focus, audiobook journeys, F6 status, preferences and existing menus. New native controls have accessible names and F1 help.
- **Capture the selected window rather than an unrelated desktop.** Named windows use direct window-handle capture. Recheck process identity, display availability/layout and rectangle bounds. A closed, hidden or minimized window, changed identity, disconnected display, invalid rectangle, capture failure or dimension mismatch reports a failure instead of broadening the source. Shared legacy screen capture also rejects invalid target names and handles negative-monitor window rectangles.
- **PNG files and objective evidence.** Save each screenshot with a unique PNG name. Reopen and fully decode the saved bytes; record dimensions, image format, byte count, SHA-256, timestamp, requested target and OS-reported source/bounds/backend metadata. Report uniform pixels as a possible capture problem. Save JSON and readable Markdown verification reports; keep privacy, completeness and visual correctness explicitly unverified. Successful file decoding does not prove that protected or GPU content was captured correctly.
- **Persistent native Screenshot Inspector.** Review the source, hash, objective checks and selectable conversation in one keyboard-operable window. Open the latest screenshot or reopen a saved PNG; recover prior saved observations only when the sidecar's image hash matches. Copy the image to the clipboard, save an updated evidence report or export a text description and conversation.
- **Offline OCR.** Read screenshot text through QUILL's existing local OCR service. Show recognition confidence only when the backend supplies it, and state when it is unavailable. OCR errors are visible and announced; uncertain recognition does not become a verified claim. This slice does not derive keyboard semantics or UIA element positions from pixels.
- **Seven rich screenshot prompt presets.** Orientation and overview; controls and navigation; exact text/errors/tables; framing and capture problems; possible sensitive information; alt text and extended description; and chart/diagram explanation. Also use the existing shared image styles and your saved custom prompts. Edit or extend prompt instructions, ask your own separate question, and add/edit/delete reusable prompts through Manage prompts.
- **Chat about the intended screenshot.** Ask follow-up questions in the same conversation. Each request uses the reviewed image's exact bytes and prior observations, not a fresh capture of whichever application is now active. Hash-check a private temporary snapshot before sending and remove it afterward. Changed files are rejected. Replies arrive asynchronously without closing the chat, questions remain editable while waiting, duplicate sends are guarded, and failures preserve the screenshot and conversation.
- **Configured AI providers.** Screenshot AI uses QUILL's shared AI connection settings, model selection, provider-specific credentials and vision transport: OpenAI, Google Gemini, Anthropic Claude, OpenRouter, Ollama (local or cloud), and compatible custom endpoints. Select the provider and an image-capable model through the shared AI setup. Studio does not require Ollama or maintain a separate provider configuration. Provider/model image support still applies; a text-only model cannot inspect screenshots. Changing the connection pauses previously approved automatic uploads.
- **Explicit AI sharing and Safe Mode.** Manual AI requests identify the effective provider, model and endpoint and ask before transmitting the complete image. There is no automatic redaction. A sensitive-information prompt reviews an image already sent to that provider and cannot certify safe sharing. AI Off and Safe Mode block AI requests while local capture, OCR and file checks remain available. Closing chat cancels unsent work; already sent requests may finish.
- **Optional automatic AI.** Off by default. A separate approval covers future user-triggered Studio screenshots, including full-desktop capture and globally triggered screenshots. Save the chosen automatic prompt and any edited instructions. Bind approval to the effective provider/model/endpoint; pause on connection changes. Recheck permission, cancellation and AI availability before queued uploads. Disable future/unsent automatic work without claiming to recall images already sent. Background results remain associated with their screenshot and are available in its inspector and evidence report.
- **Shared architecture and documented acceptance.** Reuse QUILL's existing OCR, provider transport, credential storage, prompt library, announcements, task manager, hotkey manager and atomic storage. Add target/privacy/grounding tests and an opt-in real Windows test that captures only its own named fixture window and checks expected pixels. This is an implementation milestone, not a published release or a claim of live-model or screen-reader certification.
- **Still pending.** JAWS/NVDA/Narrator/braille acceptance; live-provider, mixed-DPI, installer/portable and resource testing; UIA-element and scrolling/sequence capture; annotation/redaction editing and screenshot comparison; and the later video demonstration with optional sound. None is represented as already delivered by this milestone.

### Lessons from TG Drop Deck, with thanks to Tony Gebhard (2026-10-31)

Tony Gebhard's [TG Drop Deck](https://github.com/tonygeb23/tg-drop-deck), an accessible, open-source (MIT) live audio playout app, writes down the interface bugs it found the hard way. Studio checked itself against those notes and fixed these, with thanks to Tony. No TG Drop Deck code was copied; these are its lessons, written again for Studio.

- **Start and stop are heard whole.** A sentence raised from a menu or the tray icon's menu now waits until the menu has closed and the screen reader has said where focus went, so it is no longer cut off. The status bar shows it at once. Sentences put the state first, such as "Recording started" and "Recording stopped", and none reads out a file path: when a broadcast ends you hear "Broadcast ended. A copy was saved.", and the saved copy's path is in the status bar (UX-013).
- **Moving through a list changes nothing.** The Studio Mixer, the broadcast window's sound list and Record a demonstration's sound sources show the selected row's volume, sound card, level and mute in their controls. Those controls are now written under a guard, so showing a row can never run the handler for a change you make, and arrowing through a list can never mute, move or re-level what it passes. Showing a row in the broadcast window no longer makes a passed check stale either (UX-014).
- **A failing timer is no longer silent.** Every timer in Studio (the status windows' once-a-second refresh, the camera check, the end-of-chapter sleep timer, the voice preview cue and the spoken note) now logs a failure, and the main window shows it in the status bar, instead of stopping without a word. A timer that fails every time it runs is reported once.
- **Every preference has a test that watches it work.** Each of Studio's preferences is now changed by a test that observes the behaviour it controls, and a new preference without one fails the build. All seven were found to be read (UX-015).
- **A camera that is starting is not a fault.** A webcam takes about half a second to send its first picture, and its first pictures are often dark. "Your face left the camera view", and "No face in view" in Check camera framing, now wait until the camera has been sending pictures for a second and a half, counted from the frames actually read, so the start of every recording no longer gives a false alarm (VIDEO-003).

### Lessons from Quick Describe, with thanks to Kelly Ford (2026-10-30)

Kelly Ford's [Quick Describe](https://github.com/TheIdeaPlace/QuickDescribe), a free, open-source app that describes the screen with Windows' own AI, shares what it learned the hard way. Studio adopted these lessons, with thanks to Kelly for the ideas and for giving so much to the community.

- **The Recording status window and magnifiers.** Keeping a window out of a recording can also hide it from a magnifier and from screen sharing. Record a demonstration has a new check box, Let magnifiers and screen sharing see the Recording status window, off by default; the check says when it is on, because the window is then recorded too if it is inside what you record.
- **Ask AI about a video reads more clearly, and guesses less.** Fewer frames are now drawn bigger (4 frames at 960 pixels wide each, 16 at 512), so no sheet is wider than about 2048 pixels and a provider has little reason to shrink it. Frame times are drawn in a larger font, so answers can cite them. The AI is told to quote text only where it can read it clearly, to say when text is too small, and not to describe what happened between frames. Quick Describe found that a picture shrunk until a model accepts it comes back with invented text.
- **A face detector that stops answering is replaced.** Check camera framing starts a fresh detector after a failure, and after three failures in a row says once that framing advice has stopped, instead of going quiet. Quick Describe found that Windows' AI can report itself ready while it has stopped answering.
- **"Automatic screenshot AI is paused" is said once,** not with every screenshot, until automatic AI can run again. A limitation repeated with each result is noise.
- **Your user name leaves diagnostic bundles.** Paths were already cut at the user folder; now the name on its own is replaced too, as a whole word only, so a user called Al does not turn Alt into a placeholder.
- **No garbled text.** A new test fails if any of the app's text, or any app's user guide, has text garbled by a wrong encoding, such as a dash turned into three characters a screen reader reads out one by one.

### Ask AI about pictures on your ChatGPT plan (2026-10-31)

- **Studio can read pictures on your ChatGPT plan, with no API key.** The Screenshot Inspector's Ask AI, automatic screenshot analysis and Ask AI questions about a video all use the plan once Studio is signed in.
- **Signing in is one step from where you are.** With no AI set up, asking about a picture offers Sign in with your ChatGPT plan instead of stopping with a refusal. Saying yes opens Use My ChatGPT Subscription, the same window QUILL uses. Studio signs in on its own, as QUILL Studio, and never uses the sign-in QUILL or QUILL Lite made; if one of them is signed in, the offer says so, because the browser is then usually one Allow away. The window is also on the Capture menu, for choosing the model or signing out.
- **With a plan and an AI provider, Studio asks which to use** each time, starting on the one you chose last. With only one, it doesn't ask.
- **The approval question names your plan and account,** says the picture goes straight to OpenAI on your account, and says it counts toward your plan's usage with no separate charge.
- **Pictures the plan can't take are converted first.** A picture over 20 MB, wider or taller than 4096 pixels, or not PNG, JPEG, WebP or GIF is scaled and converted before it is sent. Ordinary screenshots and video frame sheets go as they are. A video is still one sheet of 4 to 16 frames, never a stream.
- **When the plan says no, Studio says so and stops.** A used-up plan offers to open ChatGPT's Usage settings; Studio never moves to your API key by itself, so to use another AI you ask again and choose it. A request the plan doesn't take for other apps is explained and not retried. A sign-in OpenAI no longer accepts tells you where to sign in again.
- Making a picture with AI still needs an OpenAI or Gemini API key; ChatGPT plans don't make pictures for other apps. Safe Mode and AI Off block all of this, as before.

### Record a demonstration (2026-10-29)

- **Screen, sound and camera as one checked video.** Capture > Record a demonstration (Ctrl+Alt+Shift+V) records a named window, one display or the full desktop to an MP4 (H.264 and AAC) through the bundled FFmpeg, using desktop duplication where it can reach the display and the GDI grabber otherwise. Frame rate 15 to 60, an optional 1080p or 720p ceiling, the mouse pointer on or off, a spoken countdown, and Studio's own windows kept out of the picture.
- **You choose every sound, and your screen reader stays private.** Sound sources are a list with a state column: the target program's own sound (Windows process loopback), system sound with the screen reader left out by default, the microphone of your choice, screen reader speech (with confirmation), and any other program playing sound. Each has its own level. The microphone and screen reader always start left out, the microphone's on state is never saved, and Studio's own process is never recorded.
- **Screen, camera and sound in any combination.** Two check boxes, Include the screen picture and Include the camera picture, with the Sound sources list: screen only, screen with a camera corner, camera filling the picture, or sound only (M4A, MP3, WAV, FLAC or Opus). A video with no sound source gets a silent soundtrack unless you turn that off. The after-check expects exactly the streams you chose.
- **Keep awake and Do Not Disturb.** On by default while recording; put back exactly as they were when you stop, and after a crash on the next launch.
- **A picture and sound as a YouTube video.** Capture > Make a YouTube video from a picture and sound (Ctrl+Alt+Shift+Y), also offered after a sound-only recording: shape (YouTube, square, vertical or the picture's own size), an optional slow zoom and sound wave, chapters from the recording's markers, and a title and description saved beside the video ready for YouTube's upload page. The sound is used exactly as it is.
- **ASIO sound cards.** Use ASIO sound cards, in Studio > Preferences (after restarting Studio), lists an interface's ASIO inputs as microphones, first and marked "(ASIO)". Off by default.
- **Record a whole sound card.** Add a program's sound also offers "Everything playing on" each sound card, recorded by Windows loopback; the check warns when the screen reader may be on it.
- **Ready for a long recording.** The check also records three seconds at your settings and warns if the computer drops frames, warns on battery (with the charge and time left) and when Windows Update is waiting to restart. The quick test can last from 5 seconds to 10 minutes, as a rehearsal.
- **Captions and a transcript for a recording.** The result window's Make captions and a transcript saves SRT, VTT and a plain transcript beside the file, transcribed on this computer.
- **Ask AI about a video.** Capture > Ask AI questions about a video (Ctrl+Alt+Shift+K): the whole video or a stretch, as labelled frames with the transcript of that stretch, in the Screenshot Inspector's conversation, with its approval and Safe Mode rules.
- **Make a picture with AI.** Capture > New picture with AI (Ctrl+Alt+Shift+J), with OpenAI or Google Gemini: describe it, ask for changes in words, keep every version, and hear an independent description of each from your vision model. Every request is approved first; AI off and Safe Mode refuse it.
- **Broadcast live to Icecast or SHOUTcast.** Capture > Broadcast live (Ctrl+Alt+Shift+G): server and show details, plain-word quality presets with Custom (format, bit rate, stereo or mono, sample rate), loudness, a stream-only list of sounds with their own levels (the screen reader asks first), an optional saved copy, a spoken check and a private connection test. While live: now-playing title, Mute everything public (Ctrl+Alt+Shift+Z), Stop (Ctrl+Alt+Shift+E), automatic reconnect. Passwords stay in Windows Credential Manager.
- **Studio Mixer.** One window (Ctrl+Alt+Shift+M) with a Programs tab (each program's volume, mute and sound card, so a program can move to another card as in Windows Settings) and a Devices tab (default and communications devices, recording level and mute).
- **Camera and face framing.** Add your camera in any corner, or record the camera alone. Check camera framing (Ctrl+Alt+Shift+C) says whether your face is in view and which way to move, and during a recording Studio can say when your face leaves the view and returns. Face detection is Windows' own, on this computer; no frame is saved by the check.
- **One spoken check before you start.** Check takes a trial picture, opens each source, looks for digital silence (a blocked microphone), the microphone lock, the camera, FFmpeg's real capabilities, the folder and its free space, and system-wide keys. Stops block the start; Warns are named. Any change afterwards asks for a new check. A 5-second test records and checks the exact setup.
- **Control from anywhere.** Pause and resume as separate segments, markers, microphone mute, a status line, emergency stop and discard, from the Capture menu, the tray (without restoring Studio) and a focus-safe Recording status window. All join the opt-in system-wide hotkey list; none is assigned by default.
- **Independent check and recovery.** After Stop the finished file is reopened and checked (streams, length, frame count, decoding at start, middle and end, black stretches, each source's level, SHA-256) and reported as Verified, Needs review or Failed in one sentence and in JSON and Markdown reports beside it. Failures during a recording are spoken once and marked. Recordings are written as crash-safe segments in a hidden folder, and Capture > Recover unfinished recordings finishes any that a crash left behind.
- **Still pending.** Window targets record the window's screen area (Windows.Graphics.Capture is not yet used, so a covering window is recorded and movement is not followed); JAWS, NVDA, Narrator and braille acceptance; long-recording audio and video alignment on reference hardware; and a live check of face detection with a person in front of the camera.

### Sound, volume and the sliders

- **Slider Keys: choose which way the arrow keys move a slider** (2026-10-26). **Studio > Preferences...** (Ctrl+,) has a **Slider Keys...** button with two choices. **Up is more**, the default: Up, Page Up and Home raise the volume, Home being the top (100 percent), and Down, Page Down and End lower it, End being 0. Until now Home went to the bottom of the slider, so a full volume read as the bottom of the scale. Or **As Windows sliders**: the trackbar's own keys, where Down, Page Down and End raise it. Right is always more and Left less. It is one choice for every Quill app with a volume slider (QUILL Studio, Quill Radio, QUILL Cast and Quill Media Player), so changing it in one changes it in the others at the next key press. Each key press also tells the screen reader the new value, so it is never read from before the key. Ctrl+Up and Ctrl+Down, the volume keys that work from anywhere in the apps that have them, are not changed.
- **Where Audio Studio's own sounds play, and Alt+Shift+M to turn them off.** **Studio > Preferences > App Sounds Play On...** offers System default, None (no sounds), or any sound card or headset by name. After a change one sound plays on the new card, so you hear where it went. If that card is unplugged the sounds play on the system default until it is back, and Audio Studio says so once. **Alt+Shift+M** turns Audio Studio's sounds off and back on where they were, and **Studio > App Sounds** shows a check mark while they are on. Each QUILL app keeps its own choice; "Share these choices with my other Quill apps" keeps them in step. Your screen reader is never moved. Asked for on QUILLVille by Rick Lewis.

### Also added in 2.0.0

- **QUILL Audio Studio has its own icon.** It used to ship a byte-identical copy of Quill Radio's broadcast-wave icon, carried over when the standalone shell was scaffolded, so two products wore one face in the taskbar, in Alt+Tab and in the tray. Audio Studio's icon is now a three-bar waveform on a slate tile -- the same rounded shape and amber accent as the rest of the QuillVille family, with its own silhouette and its own colour. The waveform was re-cut once before shipping: at 16x16 five bars merged into a solid slab, so there are three, with real gaps between them, which is what makes a waveform read as bars rather than as a block.

- **The QuillVille Runtime -- install Python once, and every Quill app starts instantly.** Every QuillVille app (QUILL, Quill Radio, Quill Weather, and QUILL Audio Studio) now shares one Python runtime, the QuillVille Runtime, installed once per user and reused by all of them. Install it a single time and every app you add afterward launches immediately. The runtime is reference-counted: it is removed only when the last app that needs it is uninstalled. Alongside the existing full portable and full installer builds, two new lightweight editions arrive that ride the shared runtime:
  - **Companion edition** (`QUILL-Audio-Studio-Companion-<version>.zip`, about 2 to 3 MB) -- just the app and its docs. The first time you launch it, if the QuillVille Runtime is not already installed, it offers to download and install it (about 230 MB, once) with a fully accessible progress bar; after that, this app and every other QuillVille app start instantly.
  - **Thin installer** (the `-Lite` setup) -- a tiny installer that downloads the shared runtime only if it is not already present, then installs the app.
  - The **full portable** edition is now named `QUILL-Audio-Studio-Portable-Lean-<version>.zip` (about 675 MB): fully self-contained, runs from a USB stick with no installation and no internet, bundling a genuine unmodified copy of Python plus the offline speech and text-to-speech engines (whisper.cpp, DECtalk, eSpeak-NG, Piper, and neural Kokoro). The **full installer** (`QUILL-Audio-Studio-Setup-Shared-<version>.exe`) installs the shared runtime, if it is not already present, plus the app.
- **Accessible runtime downloads.** Whenever the QuillVille Runtime is downloaded -- by an installer or by an app's own first launch -- it shows a fully accessible progress bar that works with NVDA, JAWS, and Narrator, announcing progress as a percentage.
- **Update in one click -- Audio Studio installs it and restarts itself.** When an update is available, choose Download, then **Install and restart now**: Audio Studio applies the update (extracting the new portable files over your folder, or running the installer silently) and relaunches automatically, keeping all your settings and data. No more closing the app, unzipping, and swapping folders by hand. Shared across every Quill app.
- **A status bar you can read, and a running job you can follow from the tray.** The status bar is now arrow-navigable: press **F6** to move focus into it, Left and Right to move between cells, Enter to act on one, Escape or a second F6 to leave. Its cells are Activity, Progress, Sleep timer, Your books, and Time, so "what is going on right now" is always one key away instead of something you have to guess at. The Progress cell carries a live narration or build run -- percentage, files, and the current step -- and the same text is written to the system-tray tooltip, so a long run stays reviewable with the window minimized. **View > Show Status Bar** turns it on or off, and the choice is remembered.
- **Convert Audio, right in the Studio.** **Voices > Convert Audio...** builds a queue of files and folders and converts them between formats -- MP3, M4A/M4B, Opus, Ogg, FLAC, WAV, AAC and more -- pulling the audio track out of video files (MP4, MKV, MOV, WebM and the rest) along the way. It uses the ffmpeg the Studio already bundles, so nothing new to install, nothing leaves your machine, and it works in Safe Mode. Ten presets cover the usual jobs (Just convert, MP3 at three bitrates, Podcast, Audiobook M4B, Voice memo, Web voice Opus, Archival FLAC, and Hearing-aid mono); the queue only ever offers formats your ffmpeg can actually encode, so a batch cannot die half way for a missing encoder; conversion runs off the UI thread with several workers, a real Cancel, and a spoken summary that **names the files that failed** instead of quietly claiming success.
- **Advanced processing for a conversion.** The converter's Advanced panel adds loudness normalization (Audiobook/ACX at -20 LUFS or Podcast/streaming at -16 LUFS), gain, a high-pass filter, silence trimming, pitch-preserving tempo, a compressor, a night-mode leveler, fade in and fade out, and a safety limiter. Everything is off or neutral by default, so a plain conversion stays a plain conversion.
- **Convert from a link.** **Voices > Convert from URL...** takes a YouTube link (and the many other sites yt-dlp supports), downloads the audio, and drops it straight into the converter. The downloader is never bundled: it installs on demand after a one-time consent and rights notice. Unavailable in Safe Mode.
- **Announcements now reach your braille display.** Reported by a braille user: messages the Studio speaks never appeared in braille. The diagnosis was blunter than the report -- nothing had ever been sent to a braille display at all. Braille is now routed at the same point as speech, so every message is covered at once. Three rules govern it: braille never costs speech (an unplugged display, a reader that rejects the call, a bridge without the capability all degrade to "spoke but did not braille", never to silence); nothing is truncated, because clipping would drop the end of the very thing you asked for; and an identical message inside two seconds does not steal the display twice, since a flash message replaces whatever is under your fingers. A burst of different messages no longer flickers past faster than cell one can be read -- the first message of a quiet period writes instantly, and anything landing within the next 150 milliseconds settles to the newest rather than each shoving the last aside, with errors exempt and always written through at once.
- **Every announcement channel in one place.** Speech, braille, sound, and the status line are now delivered by one shared announcement service, the same one QUILL uses, so a message the Studio makes reaches every channel you rely on instead of only the ones that happened to be wired. Announcements are also recorded, so a message that passed while you were reading something else is not simply gone. New shared accessibility settings control the braille style (the full spoken string, or the compact position-first form), how long an identical braille message is held back, whether an error sticks on the display instead of flashing past, whether the companion apps play sound cues, whether a cue stands in for speech while Quiet Mode is on, and which severities interrupt speech. They live in the store the Studio shares with QUILL, so setting them in QUILL's Preferences applies here too.

### Also changed in 2.0.0

- **Fewer antivirus false positives.** The app's launcher is now a genuine, tiny native program, and the bundled Python is the official unmodified build. Earlier versions used a renamed and modified copy of Python's `pythonw.exe` as the launcher, which some antivirus tools flagged as a false positive. That pattern is completely gone, so the Quill apps are far less likely to be flagged.
- **Audio Studio is now built straight from QUILL's own source.** The app used to be assembled from a copy of QUILL's audio code kept in a separate repository and re-synced by hand. It is now built directly from the QUILL package, so the Studio and QUILL's built-in Audio Studio can never drift apart and a fix upstream is in the next Studio build with nothing to copy across. Nothing changes for you except that the two stay in step.
- **Updates come from one place, per app.** **Help > Check for Updates...** now looks at the shared QUILL project releases and picks out Audio Studio's own download for the flavor you run, so each Quill app updates on its own schedule without needing a repository of its own. An update to Quill Radio is never mistaken for an update to the Studio.
- **Piper voices download from the project's own mirror.** All 39 Piper voices are now served from the project's signed component mirror rather than a third-party model host, so voice downloads no longer depend on an outside service being up or reachable from your network.
- **Shared components are counted, not guessed.** Audio Studio declares the components it needs (ffmpeg) when it starts, and the shared store keeps a count per component, so uninstalling one Quill app can never take away something another app still needs.
- **A smaller download.** The build now leaves out the large libraries the Studio never loads, so the installer and the portable zip are meaningfully lighter without giving anything up.
- **A choice at install time.** The installer offers Full, Compact (program only, no bundled documentation), and Custom setups; the shared runtime and the app itself are always installed, and only the packaged documentation is optional.

### Fixed in 2.0.0

- **Up is more on every slider.** The player's Position and Volume sliders
  answered Up with less, because a Windows slider on its own treats Up as
  "towards the start", the left end. A Quill Radio listener reported the
  volume slider as backwards, and the fix is family-wide: Up and Page Up now
  raise every slider in every QuillVille app and Down and Page Down lower it;
  Left, Right, Home and End are unchanged (`quill/ui/slider_keys.py`, 2026-09-28,
  with a gate that fails the build for a new slider without it). Since 2026-10-26 Home and End follow Up and Down as well, and the direction is the family's Slider Keys choice (see Sound, volume and the sliders above).
- **Kokoro narration no longer stops mid-run on a portable copy.** A long, dense passage could overrun the neural model's input window; the Studio then fell back to a heavyweight code path that a portable copy does not carry, and reported "Kokoro voices need one more component" for a component you had already installed -- 29 chapters into a run. The Studio now re-splits that one passage at safe boundaries and carries on, so a portable narration completes; the per-passage size limit is capped below the model's window everywhere it is used, including translated editions; and when a passage genuinely cannot be synthesized the message names the real cause and where to find the report instead of pointing at a download you do not need.
- **A conversion's progress reaches the tray.** Converter progress is reported through the same channel as a narration run, so it appears in the status bar's Progress cell and the tray tooltip rather than only inside the dialog.
