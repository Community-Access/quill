# Changelog

All notable changes to QUILL Cast are documented here. See `docs/release-notes-1.2.md` for the fuller narrative version of the unreleased work, and `docs/release-notes-1.1.md` for 1.1.

## Unreleased

- **The columns are yours (Subscriptions > Choose Columns..., Ctrl+Alt+Shift+C).** An episode list is read out one column at a time, so whoever chose the columns chose the sentence every row speaks -- and until now that choice was made once, in code, for everybody. Somebody working through one show heard its name on two hundred rows; somebody queueing by length had the duration read fourth. The episode list, Downloads and Add Podcast's results can now be reordered and pruned, and the episode list offers three columns it does not show by default: **Podcast** (worth having in a list that spans several shows and noise in a list of one), **Time Left** on an episode you have started, and **Downloaded**. Add Podcast can show the **Feed Address**, which is what tells two shows with the same name apart. Two lists rather than checkboxes, for the reason Quick Actions reorders by position: a checkbox inside a list is a state a screen reader has to be asked for, while a list position is a place you land on. **Hidden means absent, not last** -- a screen reader speaks every column a report list is given, so the only way to stop hearing something is for the column not to exist -- and a hidden column keeps its place in the order, so showing it again does not send it to the end. Under the two lists one line reads out exactly what a row will say, comma-separated, because that is how a screen reader runs a report row's cells together; you can hear a change before pressing OK. One column per list is pinned (the episode's title, the podcast's name), because a row with nothing to identify it is a row nobody can choose between, and the refusal says why rather than being a disabled button that says only no. Changing the layout while the Manager is open takes effect there and then. The whole machinery is shared with Quill Radio (`core/media/list_columns.py`), so the two apps cannot drift into answering the same question differently again.

- **Your place follows you to another app, not only to another QUILL machine.** Cast has carried listening positions between two copies of itself for a while, encrypted, through a folder you already sync -- and that will only ever work QUILL-to-QUILL. **Listening Places** is the other half: a small, published, plain-text format any podcast app can read and write in the same folder. No account, no server, no signup. Every device writes exactly one file and reads everyone else's, which is what stops a cloud drive ever producing a `positions (Jeff's conflicted copy).json`; the most recent position wins rather than the furthest, because jumping back twenty minutes on purpose and then opening the episode elsewhere must not be undone; and reading happens **only at launch and when you press Sync Now**, because a position arriving mid-session would move the playhead under somebody with no visual cue that it had happened. Every id in the folder is hashed, so what leaks is counts and timings, not titles -- and names are a separate switch again. The format is written down in `docs/engineering/listening-places-spec.md` with JSON conformance fixtures both implementations test against, so two apps cannot quietly drift into disagreeing about somebody's data.
- **Share This Moment.** Cast could copy an episode's audio address and save its audio to a file; neither is what somebody means by *listen to this bit*. Sharing now copies two things together -- a `quill-cast://` link that reopens the episode at the second you shared it from, and a plain sentence saying the same thing ("Blind Abilities, Episode 214, at 41 minutes 12 seconds"). The sentence is not an afterthought: a link nobody can open is worse than a sentence anybody can paste, and the person receiving it very often does not have Cast at all. Opening a link is treated as somebody else's input -- it resolves to a feed address and a GUID, both looked up in the library you **already** subscribe to, and a link for a podcast you do not follow says so and does nothing. Cast never fetches a web address, and never adds a subscription, because a link asked it to.
- **A second podcast directory, for the metadata Apple's does not carry.** Add Podcast now has a **Directory** picker: iTunes, Podcast Index, or both. Podcast Index is the index the Podcasting 2.0 tags were defined for -- chapter documents, transcripts, marked moments, credits -- which is a great deal of what Cast is built on. Searching both merges by feed address and says where the results came from; a directory that fails does not fail the search, it contributes a sentence about itself and you keep the results that arrived. iTunes stays the default and stays keyless: Podcast Index needs a free key, so the option is simply absent until you add one in **Subscriptions > Podcast Index Credentials...**, where the key and secret go to Windows' credential store rather than a settings file and are scrubbed from crash reports.
- **Look at a podcast before subscribing to it.** A search result is a title, and subscribing to a title is how you end up unsubscribing from a title. **Preview** -- and Enter on a result, which now previews rather than subscribing -- opens the show read-only first: what it is, who makes it, how many episodes, its own description as text you can arrow through, and its ten most recent episode titles with dates. Between them those answer *is this the show I meant, is it still going, and is it in my language*.
- **A folder is somewhere you listen from now.** Cast has had a folder tree for a long time and never had a single action *on* a folder, so forty shows filed into "News" made the list tidier and did nothing for the listening. A folder's menu now offers **Play All Unplayed** (the newest unplayed episode of *each* show -- one per show, because a folder of forty holds hundreds and a queue of hundreds is something you have to undo), **Add All to Queue**, **Move Up** / **Move Down** with the new position announced, **Folder Settings...** (queue expiry, Inbox routing and speed applied to every podcast in it at once, each control starting at "change nothing"), and **Export This Folder as OPML...**. A folder always means its whole subtree, everywhere. The **Play Queue can be grouped by folder** as well as by podcast; grouping never changes the play order, only how it reads, and a group header announces itself as one.
- **Move several podcasts into a folder at once.** Filing was one show at a time, so tidying forty into six folders was forty trips through a picker. **Move Several Podcasts to Folder...** uses a multiple-selection list -- arrows move, Shift and arrow extend, Ctrl and Space toggles -- with Select All and a running count, then the folder picker once for the lot. The subscription tree itself is deliberately not multi-select: that would change how every existing selection in it behaves, and multi-select trees are markedly harder to drive with a screen reader.
- **Smart playlists can say what you actually mean.** The rules ANDed everything, which is right for narrowing and useless for the other half of what people want -- *anything from these three shows, or anything I have bookmarked* cannot be said with AND at all. There is now **match all or any**, plus filters on a **library folder** (subtree aware), **downloaded or not**, **has a note of mine**, **title or show notes contain**, **where the playhead is** (genuinely different from the played mark), and **at most N episodes**, applied *after* sorting so "the ten newest" is the ten newest. Beside them is the thing that makes a rule builder usable at all: **"Matches 23 episodes right now"**, recomputed as you type -- without it, checking a filter meant saving, closing, reopening and reading. And because a blank rule builder is where most people stop, **Add Starter Playlists** creates five worth having (Continue Listening, New This Week, Quick Listens, Downloaded and Unplayed, Long Reads) as ordinary editable playlists rather than built-ins.
- **Chapters for the episodes whose publishers never wrote any.** Most podcasts publish no chapter list, and a good many do something almost as useful that Cast was throwing away: they describe their running order in prose. Cast now takes each described topic and finds where in the episode its distinctive words actually *arrive* -- so the chapters carry titles **a person wrote** and times that were worked out. Measured against hand-built reference lists the marks landed within 9 and 15 seconds. The phrases are matched in order, because show notes are written in the order the programme runs; and a topic anchors where it **starts** rather than where it is densest, because a thirty-five-minute interview mentions its guest most often in the middle, which put one episode's main segment at 30:00 when it began at 1:09.
- **Thorough stopped offering the pause scan, and Deep started keeping its promise.** Measured against the same reference lists, listening for pauses scored **0.06** where cutting the episode into equal slices with no knowledge of it at all scored **0.15**. An answer worse than dividing by *n* is not an answer, and offering it by default spent tens of seconds making the list worse. Thorough now fetches a transcript and works the sections out of the words, and says so plainly when there is no transcript to be had. Deep keeps the scan -- somebody who chose Deep has said they would rather have a weak answer than none -- and so does a recording off the radio, where there is nothing else. Deep can also now **transcribe an episode on your machine**, which it has advertised since it shipped and never actually done: the engine is in the box, 40 MB and CPU-only, so chapters answer the first time you ask with no download and no network. It beat models thirty-five times its size on measurement (0.372 against 0.316, and 4.7 times faster) and not on transcription quality: its cues break at natural pauses, so its edges are already plausible section starts.
- **Every chapters setting has a control now.** All six were live and all six were invisible, which is worse than absent -- a listener whose chapters were slow, missing, or being worked out when they did not want them to be had no way to find the switch that said so. Podcast Settings has a **Chapters** group, led by the only question most people will ever want to answer (how hard should I look?) with the consequence of that choice spelled out beneath it.
- **How long your listening history is kept is yours to choose.** Don't keep one, 30 days, 90 days (the default, and what was hardcoded with no way to change it), a year, or forever. "Don't keep one" stops the write rather than deleting afterwards, which is what somebody choosing it asked for.
- **Downloads can wait for a connection you are not paying for.** Cast has mentioned metered connections in its own source comments for two releases and never checked. It checks now, and holds only *automatic* downloads -- a download you pressed the button for always happens. An unknown connection counts as unmetered, because refusing to download on a guess is worse than downloading.
- **Audio Output Device...** joins the Episode menu. Cast plays through Windows' default device and cannot switch devices itself, so rather than opening a picker that would do nothing it says so in a sentence and offers to open Windows' own per-app sound settings, where the choice sticks.
- **Listening streaks, and a Year in Review.** Streaks are **off by default**: a streak is a nudge, and a nudge nobody asked for is pressure. Year in Review is a few sentences you can read, copy or save rather than a dashboard -- a table read aloud is a list of numbers with their meanings three columns away -- and anything the log cannot support is omitted rather than printed as a confident zero.
- **What Quill Radio was asked to do now happens.** From Radio's browse tree you could play a subscribed show's episode and nothing else, so the same episode offered different things depending on which app you met it in. **Play Next in QUILL Cast**, **Add to QUILL Cast Queue** and **Send to the QUILL Cast Inbox** are on those rows now, handed over through a file of their own that an older Cast simply never opens -- so an instruction waits rather than being consumed and silently discarded.
- **The Inbox got the bulk actions it was missing.** Selecting forty episodes and choosing an action worked everywhere except the one place triage actually happens. **File N Episodes to Inbox Folder...** now asks once which folder and files the lot -- being asked the same question forty times is how a bulk action stops being one -- and a show that gains a remembered folder says so once rather than once per episode. **Add N Episodes to Playlist...** and **Remove N Downloaded Copies** came with it; removing downloads never removes the episodes, because freeing space and unsubscribing are very different things to want.
- **Open a subscription list by double-clicking it.** An OPML file is how one podcast app hands its whole list to another, and QUILL Cast could only receive one through a file picker inside a dialog inside a menu. The installer now offers to open `.opml` files with Cast -- **unchecked**, because taking over a file type without being asked is how an installer earns a reputation -- and Cast opens on the import rather than on an empty library with a menu to find. Removing Cast gives the file type back.
- **Hold Shift+Right to scan forward.** Skipping in fixed jumps answers "get me past this"; it does not answer "where does this bit end?", which needs to hear the audio going past. Hold the key and playback runs at four times speed; let go and it drops back to *exactly* the speed you were at -- 1.5 if that is where you listen, not 1.0. Both edges are announced, because a player stuck at four times speed with no announcement is indistinguishable from a broken one. Losing the window, or the app closing, ends a scan too.
- **Everything you started, in one list.** **Continue Listening...** (the Episode menu) shows the podcast episodes you are partway through *and* anything else QUILL remembers a place in, newest first, with the kind named on every row. Resume picks up where you left off; Forget drops the place while leaving the episode unplayed, because "I am not going back to this" and "I finished it" are different things to say.
- **Everything else the podcast published, which Cast was throwing away.** A podcast feed can carry a good deal more than a title and an audio file. QUILL Cast read two of it -- chapters and transcripts -- and discarded the rest while it sat there in bytes it had already downloaded and parsed. **About This Episode...** (the Episode menu, and any episode's context menu in the Manager) is where the rest of it now lives: **People** (who is on this episode, and who makes the podcast, each row a sentence and each with its link where the publisher gave one), **Highlights** (the moments the podcast marked as worth hearing), **Live** (some podcasts carry a live stream inside their feed -- if one is on the air, Enter plays it through the ordinary transport, so pause and volume are the same keys as everything else), **Other Audio** (a smaller version of the same episode for a slow or metered connection), **Recommended** (the podcasts this show recommends -- subscribing here is a real subscribe, so the show arrives with its proper name, artwork and episodes), **Support** (opened in your browser, and QUILL Cast has nothing whatever to do with what happens there -- nothing here costs money), and **Place**.
  A tab exists only when it has something in it, so there is no empty People tab on a podcast that publishes no credits. The command speaks a one-line summary before the window opens -- "2 people, 1 marked moment, 1 recommended podcast" -- so if all you wanted was to know whether there was anything, you never have to open it. And where a podcast published none of it, the window still opens and says so: "this podcast publishes no extra details" and "QUILL Cast cannot read them" are very different things to know. The button names what it is about to do and changes as you move -- *Open in Browser*, *Play*, *Subscribe to This Podcast* -- and reads *Nothing to Open*, disabled, on a row with nothing to do.
- **The moments a podcast marks are now chapters.** A marked highlight is a chapter mark in all but name: a person chose the moment and wrote its title. So an episode that published no chapter list at all can still have real, named places to jump to. They sit last among the sources a person wrote, and that is deliberate -- two highlights in an hour answers *what is the good bit* completely and *how is this laid out* barely at all -- so they are used only when nothing better was published, each keeps its own real end rather than running on to the next mark, and the list says what they are: **Moments this podcast marked**. One marked moment is enough to offer; it is still a place worth jumping to.
- **A first run that answers the three questions people actually arrive with.** QUILL Cast used to drop a new listener into an empty library tree. That is an accurate picture of having no podcasts and it answers none of *what is this*, *how do I add a show*, and *what happens then*. There are now three screens -- welcome, add your first podcast, you're set -- and three is the number on purpose: Cast has no account, no tracker and no cloud, so it does not need the privacy screens a phone app needs, and a first-run flow that pages you through consent you never gave anything is how people learn to dismiss dialogs without reading them.
  The screens are a text area you can arrow through and copy rather than a wall of labels, so a sentence you missed can be gone over at your own pace. **Skip** is a real button, not a small link -- somebody who already knows what a podcast player is should be able to leave in one keystroke -- and skipping counts as done, because you chose it. Anybody who already has podcasts, from an import or a restored backup, never sees it at all.
- **One-sentence tips, once each.** The first time you reach somewhere that one non-obvious fact changes what you can do -- the difference between the Play Queue and the Inbox, that most settings can differ per podcast, that a worked-out chapter list can tell you how it was found -- Cast says it, once, and never again. They are never modal, never take the keyboard, and go to speech and braille like everything else. One switch turns the lot off permanently, and **Show Tips Again** puts them back if you want the refresher.
- **The pause between queued episodes can be removed.** When one episode ends and the next begins, there is a wait: the stream has to be opened and a buffer filled, which on a poor connection is several seconds of silence in the middle of listening. **Start loading the next episode before this one ends** (Podcast Settings) fetches its first moments while you are still on the current one, so moving on costs an open and a seek rather than a download.
  It is **off by default**, deliberately: those are speculative bytes, and on a metered connection somebody pays for them by the megabyte. It never runs for an episode already downloaded, never runs while there is still most of an episode to go, and what it fetches is a cache rather than a download you asked for -- capped, and a clean-up may take it at any time. It also never says anything about itself: a player narrating its own buffering at somebody trying to listen to a programme is exactly the wrong kind of feedback.
- **Chapters for episodes that never published any, and now they say what they are about.** QUILL Cast could already work sections out of an episode -- from the transcript, or by listening for pauses -- and the results were nearly useless, because nothing *named* them. A section titled with its own first few words, or "Section 4", tells you nothing about what is in it, which is the entire point of a chapter list. Sections are now titled by what they are **about**, from the words spoken in them, in a single pass rather than one request per chapter.
- **The best answer wins, not the first.** The old order tried each method in turn and kept whatever the first one returned -- so a weak guess from the transcript permanently hid a better answer from listening to the audio. Every method the effort setting allows now runs, each answer is scored, and the best is kept. A chapter list published by the podcast still wins outright over anything worked out, always: a person wrote those titles.
- **A published transcript is fetched rather than skipped.** If an episode published a perfectly good transcript and you had simply never opened it, Cast used to ignore it and go straight to the slow audio scan. The best free answer available was being routinely passed over.
- **Show notes are read properly now.** A publisher who wrote chapter timestamps has already done the work, and the words beside each timestamp are a **title a person wrote** -- the only cheap source whose titles are authored. Cast used to recognise one shape; it now reads `00:00`, `1:02:03`, `12.34`, `1h05m`, bracketed and bulleted and numbered forms, timestamps at the **end** of the line ("Introduction — 00:00", at least as common as the other way round), and **HTML**, which is how show notes usually actually arrive.
- **One setting, not a page of knobs: how long are you willing to wait?** **Quick** uses only what is already here. **Thorough** (the default) fetches a published transcript, or listens to the audio for pauses. **Deep** transcribes the episode on your own machine and works the sections out from that. Everything else -- how quiet counts as a pause, how much of a section is read to name it -- follows from that one choice, because nobody can reason about "silence threshold -35 dB" and everybody can reason about how long they are prepared to wait. Each individual method can also be switched off, and off means **off**, at any effort level.
- **You can ask how a chapter list was found.** An inferred chapter list is a claim, and a claim you cannot inspect is one you have to take on faith. Every chapter now carries where it came from, how confident that was, how long it runs, and *why* it is where it is -- "a 2.4 second silence", "the topic changed", "from the show notes" -- and the summary says so in sentences: "12 sections, worked out by listening for pauses in the audio. Examined: 48 minutes of audio. Confidence 41%. These were worked out rather than published, so the titles describe the words used rather than the subject."
- **Nothing is ever computed twice, and nothing interrupts.** A published list, the file's own chapter marks, the show notes and a previous run's cached result are all checked first, in that order, and an episode under ten minutes never runs anything at all. While a scan is running the menu item says so in its own text -- **Chapters (working them out...)** -- rather than being greyed out, because a disabled item teaches nothing and a screen reader reads a label. Opening it mid-scan says "Chapters are being worked out. I will say when they are ready" rather than putting a spinner in front of you.
- **The Inbox can work the other way round now.** Until now it was opt-in only: a show appeared in the Inbox because you marked it. **Podcast Settings > Which shows go to the Inbox** adds the opposite -- *every* show except the ones you exclude -- which is a completely different object over a large library, and the one people with a hundred subscriptions actually want. The same per-show mark is reused rather than adding a second one that could disagree with it, so under the new mode the menu item reads **Keep This Show Out of the Inbox** and the spoken confirmation changes with it. Nothing moves unless you change the setting: the default is exactly what Cast has always done. The Inbox caps added in 1.1.0 are what make the new mode survivable -- an Inbox holding every episode of every show would be unusable without them.
- **Transcripts keep their timings, and there is now a window that reads them back.** QUILL Cast could already fetch a feed-provided transcript, read it, cache it for offline search, and open it as a QUILL document -- and the reader discarded the timings, which was right for "open this as a document" and useless for anything that follows along. Transcripts are now parsed into timed lines (WebVTT, SubRip, Podcasting 2.0 JSON, and YouTube's caption format, which arrives free with every YouTube resolve in Quill Radio and was being thrown away). That is what makes *follow the audio as it plays*, *jump playback to this line*, and "found at 12 minutes 8 seconds" possible at all. **Read Transcript...** on any episode's context menu opens it: an ordinary read-only text box, so arrow keys, selection and your screen reader's review cursor behave exactly as they do everywhere else -- plus **Follow the audio** (off by default, because while you are reading, playback must not move your cursor), **Enter on a line to play from there**, **Find with the position spoken** ("Found at 12 minutes 8 seconds"), Copy, **Save As** in plain text or WebVTT or SubRip, and Open in QUILL. It is the *same window* Quill Radio opens on a video's captions, deliberately -- two transcript readers would drift apart the day after the second one was written. An automatic caption track says so in its heading, because a machine transcript presented as a human one is a confident wrong answer. **Open Transcript in Editor** is unchanged and still there; it is a different thing to want.
- **An episode's own row can download it now.** The main page's library tree could expand a show to its episodes, and an episode row's context menu then offered nothing but "Open Manager..." -- no way to fetch the one episode under the cursor. The menu now leads with **Play Episode** (or Stop, when it is the one playing) and **Download Episode**, on the same authenticated path every other download takes, so a private feed's sign-in is never forgotten. The file lands under your Download location as `show-title\episode-title.mp3` -- names that mean something in Explorer, not a feed's serial number.
- **The pinned views are yours to name.** Favorites, New Episodes, Continue Listening and the Inbox ship with the app, which is exactly why you may call them what you like: press **F2** on one (or choose **Rename...** from its menu), and the name follows you into the Podcast Manager too. A renamed view's menu gains **Reset Name**, and entering a blank -- or the shipped name itself -- is also a reset, so only genuine customizations are ever stored. Folders rename with the same F2 (the menu item always said so from today; the key is new). A show or an episode politely refuses: those names belong to the podcast's own feed, and a personal alias would quietly stop matching what every other player calls it.
- **Podcasts sort your way, including by hand.** **Subscriptions > Sort Podcasts** offers Ascending (A to Z), Descending (Z to A), and **Custom Order** -- and custom order is built by moving shows: **Alt+Up / Alt+Down** on a show in the library tree (or the context menu's Move Up/Down in Custom Order) nudges it among its folder's neighbours. The first move switches you to custom automatically, after freezing the order already on screen as the starting point, so nothing visibly jumps. The Manager's own "Sort shows" dropdown gained the same two modes -- Title Z-A and Your custom order -- and now opens on whatever the library is actually sorted by, so the two windows never disagree.
- **The tree's numbers say what they count.** Folders now wear a badge with how many podcasts live under them (the whole subtree, matching what expanding reveals), and a show's badge now reads "(3 unheard)" rather than a bare "(3)" -- two different counts that read identically would have forced you to remember which kind of row you were on.
- **An emptied search box empties its results.** In Search Everywhere and Add Podcast alike, deleting your query used to leave the old results sitting there looking current -- stale matches for text that no longer exists, indistinguishable from live ones to a screen reader arrowing the list. Clearing the field now clears the list at once, exactly as running an empty search would, and says so.
- **Show notes read as paragraphs, not a wall.** The plain-text form of an episode's notes ran every paragraph together with a bare line break, which a screen reader's next-paragraph navigation sails straight past. Paragraphs are now separated by one blank line -- never more, however many empty tags the publisher stacked -- so "next paragraph" is a real place to land, everywhere notes appear: the Show Notes window, About This Episode, and text sent to the editor.
- **Every app in the family has its own face now.** QUILL Cast's icon was always its own -- a microphone capsule under waves, which is what separates it from Quill Radio at a glance -- but three of its siblings were shipping byte-identical copies of Radio's icon and two more had no icon at all. All eight now come from one generator (`scripts/build_app_icons.py`) that owns the shared tile shape and the amber accent Cast and Radio established. Cast's own glyph was redrawn only slightly: its arcs now carry the same stroke weight as Radio's, because the two apps are the closest pair in the family and a thinner line read as a different idea rather than a sibling one.

## 1.1.0

### Getting episodes without asking

- **QUILL Cast can now fetch episodes for you.** Until now it knew what to throw away and nothing about what to fetch: an episode landed on your disk because you asked for it, or -- with Always Sync -- because *everything* did. There was no "keep the newest three ready". Podcast Settings now has **Automatically download**, with None, the newest 1, 3, 5, 10, or every episode, and any podcast can set its own from **Settings for This Podcast...**. New episodes arrive downloaded, on subscribe and on every refresh. Two more switches: anything you add to the Play Queue downloads too (on -- something you queued is something you meant to play), and anything routed to the Inbox does not (off -- the Inbox is where episodes wait to be sorted, not a commitment).
- **Auto-Queue a podcast.** Turn on **Auto-Queue New Episodes** for a show and its new episodes go straight into the Play Queue on refresh, skipping the Inbox entirely. For the two or three shows you always listen to, that is the whole workflow.
- **Have one podcast announce itself.** **Announce New Episodes**, per show, names the new episodes out loud and in braille when the background check finds them, and shows a tray notification. Deliberately per podcast, and off until asked: being told about every feed is being told about nothing.

### Your queue looks after itself

- **Queue Expiration.** A queued episode you never got to is worse than clutter -- the queue decides what plays next, so a stale item does not merely sit there, it takes a turn. Any podcast can now set **Expire from the queue** (1 day up to a month; never, by default). Daily news show? Two days. Weekly long-form? Two weeks. Or leave it off entirely. There is deliberately no global setting: the right number differs per show, and one number for everything is a number nobody wants.
- **Recently Expired**, a new pinned view in the Podcast Manager beside New Episodes and the Inbox, holds what expired for seven days. **Restore** puts an episode back at the end of the queue with a fresh clock; **Restore All** takes the lot. Nothing is deleted when an episode expires -- it keeps its downloaded file, its position, and its place in its show. Only the seven-day sweep removes a downloaded copy, and only for something you chose not to restore. Every expiry is announced; a queue that quietly shortened itself is exactly the kind of silent change QUILL Cast does not do.
- **Upgrading is safe.** A queue saved before this release has no timestamps to age against. QUILL Cast reads an unstamped episode as "added just now", not "added long ago", so the first launch after updating cannot empty your queue.

### Knowing what you listened to

- **Listening Statistics** (Episode menu). Time listened this week, month, year, or all time; how much extra content faster playback bought you; how many episodes you finished; and a breakdown by podcast, most-listened first. It is a read-only text field you arrow through line by line and can copy, the same shape as Player Information -- not a chart with a caption. Durations are read as language ("3 hours, 47 minutes"), never as a clock face, because a screen reader reads `3:47:00` as a time of day. **Export CSV...** saves every session; **Clear Statistics...** deletes the log and nothing else. Ninety days are kept by default.
- **One number is missing on purpose.** Time saved by Smart Speed is not reported, because the silence-trimming path cannot say how much silence it actually dropped. An invented figure would flatter the feature and mislead you, so the line is simply absent rather than showing a confident zero.

### The menus are yours now

- **Quick Actions...** (Subscriptions menu) puts the actions you actually use where you expect them. Three lists -- episode, podcast, and Play Queue -- each reorderable with Move Up, Move Down, and Make Default. **The first action in each list is what Enter does.** The first nine also answer to **Ctrl+1** through **Ctrl+9** in the episode list, so the ones you use constantly need no menu at all. And the whole list is the order of the right-click menu, so muscle memory holds. Nothing changes until you change it: the shipped order puts Play first for an episode and Play Next Episode first for a show, exactly as before.

### Getting an episode back out

- **Save Episode Audio As...** keeps your own copy of the audio wherever you choose. This is the useful half of "sharing" on a desktop: what you actually want is a file you can put somewhere. It **copies** rather than moves -- QUILL Cast keeps managing its own downloaded copy, so retention, the storage cap, resume and Remove Downloaded Copy all still apply to it, and your saved copy sits outside all of that. An episode you have not downloaded offers to fetch it first rather than freezing behind a progress bar you cannot escape. The suggested filename is "Show - Episode", with anything Windows rejects replaced and the length bounded, so the Save dialog never opens pre-filled with a name the system will refuse.
- **Copy Podcast Link**, beside the existing Copy Episode Link. The feed address rather than the homepage, because a feed address is the thing another podcast app can actually be given. A local podcast says it has no link instead of silently copying nothing.
- **Show in File Explorer** opens the folder holding a downloaded episode with the file selected. (It genuinely selects it now -- see Fixed below.)
- All three are **Quick Actions** entries, not hard-coded menu items, so they can be reordered, made the Enter default, or reached on Ctrl+1 through Ctrl+9 like everything else.

### Deciding what happens next

- **Stop After This Episode** (Episode menu): a one-off that stops instead of auto-advancing, clears itself when it fires, and never survives a restart. QUILL Cast says "Will stop after this episode" when you turn it on.
- **Two switches for what follows an episode.** Podcast Settings now has "Play the next episode in the Play Queue" (on -- what QUILL Cast has always done) and "When the queue is empty, keep going with the same podcast" (off, new). With both off, playback stops at the end of the episode you started, which is the entire point of having the pair.
- **Finishing a mid-queue episode no longer throws you back to the top.** Play the ninth thing in your queue, and when it ends the tenth follows -- not the first. It always jumped to the queue head before.
- **Playback speed is a real range.** 0.5x to 5.0x in tenths, replacing six fixed choices that stopped at 2.0x. **Speed Up** (Ctrl+Shift+Up), **Speed Down** (Ctrl+Shift+Down), and **Reset Speed to Normal** (Ctrl+Shift+0) change it from the keyboard while you listen, and say which speed and whose -- the playing podcast's own, or the shared default when nothing is playing.
- **Mark All as Played...**, per podcast, always confirmed by name and count. The episodes stay in your library and downloaded files are not deleted; they simply leave the Inbox, because the Inbox is unplayed episodes and these are no longer that.
- **Sleep timer: "End of this episode"** is now a choice in the timer, and it follows the episode rather than a clock -- seek forward and it moves with you instead of cutting you off early. **Extend 5 Minutes** appears on the timer while it counts down and on the Episode menu, and it also undoes any fade already in progress, because the point of extending is that you are still listening.

### The Inbox and your disk

- **Inbox caps, per podcast.** Keep at most N episodes, and drop episodes older than 6 hours up to 2 weeks. **Trimming never deletes anything**: a trimmed episode leaves the Inbox and stays unplayed in its show's own list. And three kinds of episode are never trimmed at all -- anything you have started, anything in the Play Queue, and anything you filed into an Inbox folder by hand. That distinction is the difference between a helpful cap and losing your place.
- **Downloads...** (Downloads menu) finally answers "how much disk are my podcasts using". Total size, a per-podcast breakdown largest first, an Unheard/All filter that says how many rows it hid, and **Remove This Podcast's Downloads...** for one show at a time.
- **Two automatic storage rules**, both off by default: delete downloads older than N days, and a total storage cap in MB. When the cap is exceeded, already-played downloads go oldest first. **A queued or part-played episode is never removed** -- disk pressure is not a reason to throw away the thing you are halfway through. **Free Up Space** applies both on demand and reports the bytes reclaimed.
- **Run Housekeeping Now** does the whole pass -- expire, sweep, trim, enforce -- and tells you everything it did in one sentence. It also runs automatically after each refresh.

### Importing a real subscription list

- **Import OPML rebuilt for lists in the thousands.** Tested against a 1,307-feed export. Reading, parsing, and adding now happen off the UI thread instead of inside a button handler, so the window never freezes. Duplicate detection matches on a normalized address, so the `http://` and `https://` forms of one feed are correctly one feed -- and a file listing the same show twice imports it once. Two shows that merely share a *title* are both imported and flagged for review, because two shows genuinely can be called "The Daily".
- **QUILL Cast can now tell you which of your feeds are dead.** Tick "Check that each feed is still reachable" and it checks them concurrently after importing, with live progress you can hear (announced every ten per cent) and a **Stop Checking** button that keeps everything already imported. A feed asking for a sign-in counts as alive, so a private feed is never reported dead.
- **And then prune the file.** The import report has **Save Pruned OPML...**, which writes your original file back without the feeds that no longer answer -- folders, attributes, and all. Knowing that three hundred feeds are dead is only useful if you can do something about it.

### Winamp keys, the same ones as Quill Radio

- **The classic transport letters work in QUILL Cast.** `X` play, `C` pause, `V` stop, `B` next, `Z` previous; Left/Right seek 5 seconds and Shift+Left/Right seek 30; `T` switches between elapsed and remaining; `J` jumps to an episode by name and `Ctrl+J` to a time; `L` opens what is selected. Exactly the keys Quill Radio's recordings player uses, from the same shared map -- the whole value of muscle memory is that it does not have to be relearned per app. On by default, with one Preferences checkbox to turn the letters off if you would rather use them for list typeahead.

### Chapters you can skip

- **Mark chapters to skip.** In the Chapters dialog for the episode you are playing, **Skip This Chapter** marks the ad break, the sponsor read, or the outro; playback jumps past it and says "Skipping chapter:" and its name. Marks last for the listening session only -- a chapter you skipped in yesterday's episode says nothing about today's. Consecutive marked chapters are stepped over together, and marking everything to the end simply finishes the episode normally, so auto-advance and delete-after-play still fire.

### Speed, size, and not falling over

- **A big library no longer stalls the app.** With a thousand-plus shows fully refreshed, saving the library takes about seven seconds and writes a 164 MB file -- and that save used to run on every pause, every stop, and every episode change. Above a size threshold, saves and the library-tree rebuild now settle onto a short timer instead of running in the middle of your keystroke; below it nothing changes and saves stay immediate. Closing the app always writes everything out first.
- **Expanding a podcast is no longer the whole library.** A show's episodes are built when you expand it, not for every show up front. That was around 196,000 tree items on a large library, rebuilt on every save.
- **Long lists say what they are not showing.** A cross-show view (New Episodes, the Inbox) fills the newest thousand rows and the status line says so and what to do about it, instead of trying to list two hundred thousand episodes.

### Also

- **Settings for This Podcast...** collects everything that only makes sense one show at a time -- auto-download, auto-queue, announcements, queue expiry, speed, Inbox caps, download age limit -- with **Follow the Shared Defaults** to drop every override at once. Leaving a field on the shared default stores no override, so changing the global later still reaches that show.
- **Read the podcast name first**, an accessibility preference for cross-show lists. In a list of two hundred rows from forty shows, whichever name comes first is what you can skim by first letter -- and which one that should be depends entirely on how you look for things.
- **Start on this view**: choose which part of the library QUILL Cast opens on -- New Episodes, Continue Listening, the Inbox, Favorites, Recently Expired, or the top of the tree.
- **Group the Play Queue by podcast**, with move-group-to-top/up/down/bottom. Forty items from four shows is a list nobody can hold in their head; four groups is.
- **Export My Data...** writes your subscriptions, folders, queue, playlists, episode notes, listening statistics, and recently-played list to one readable JSON file. OPML covers subscriptions and nothing else.
- **Delete All Podcast Data...** starts you over, confirmed twice, with downloaded files as a separate question -- "start over" and "reclaim the disk" are not the same wish.

### Fixes and additions that landed alongside

- **A re-published episode comes back to your Inbox.** Publishers do re-issue episodes -- a corrected file, a re-cut, one pulled and put back -- and QUILL Cast used to refresh the details in place and leave it where it was. If the Inbox had already trimmed it, the corrected version sat in the show's own list where you were never going to look. It now returns, announced in words that do not call it new: "Episode 42 was re-published by The Daily, so it is back in your Inbox." Three kinds of episode are left alone, and they are the same three the Inbox caps already exempt -- one you **played**, one you **started**, and one you **queued** -- plus anything you filed into an Inbox folder yourself. A refresh should not argue with decisions you have already made.

- **Your place is kept even if QUILL Cast never gets to shut down properly.** The resume position was only written when *you* did something -- pause, stop, change episode, or quit cleanly. Every other ending took it with you: a crash, a power cut, Task Manager, a forced restart. You came back to your last pause, which after an uninterrupted hour is an hour ago. It now saves every fifteen seconds while an episode plays, so the worst an unclean exit can cost is a sentence.

- **Your episode notes are reachable from the player.** A note is something you make *while listening*, so needing to leave the player, find the episode in the library tree and open its context menu to read your notes back was the wrong shape. **My Notes in This Episode...** now acts on whatever is playing, and selecting a note jumps to it.
- **Copy Note** shares one bookmark as text somebody else can act on: the episode, the podcast, the timestamp, your note, and the audio link together. The note's own words pasted alone are a fragment with no way back to the moment they mark. A note whose podcast you have since unsubscribed from still copies -- the parts that are gone are simply left out.
- **Fixed: Player Information said "0 notes" for every episode.** The count was gathered by a call with the wrong number of arguments, and the error it raised every single time was swallowed -- so an episode with fifty notes read as having none. A confident wrong number is worse than an absent one.
- **Fixed: Show in File Explorer opened the wrong folder.** Windows Explorer wants `/select,` and the path as one argument; passed as two it quietly ignores the switch and opens Documents. A window appeared, so it looked like it had worked -- with nothing to tell a screen-reader user otherwise. There is one tested implementation now, shared with QUILL and Quill Radio.
- **A podcast host having a bad minute no longer looks like a dead feed.** Refreshing a feed, searching the directory, and the OPML reachability sweep retry twice on a transient failure -- a 5xx, a dropped connection, a timeout -- a second and then two seconds later. A 404, an address that does not resolve, and a sign-in failure still fail immediately, because asking again cannot change those answers. It matters most in the reachability sweep, whose verdict is what the import report offers to prune from your OPML file: one busy moment must never be the reason a live subscription gets deleted.

- **Fixed: QUILL Cast would not start at all.** On some builds the app closed before its window ever appeared, so there was nothing to report and nothing to work around. The library tree asks Windows to expand its top level; because the tree deliberately hides its invisible root node (so the first thing you arrow to is a real folder or show, not a meaningless "root"), Windows refused the request and took the app down with it. The request was never needed -- a hidden root's children already *are* the visible top level -- so it is now skipped. A regression test keeps the guard in place.
- **Announcements now reach a braille display.** Everything QUILL Cast says through your screen reader is also written to your braille display, which the standalone apps never did before -- previously braille users only saw whatever the display happened to be tracking. A burst of different messages no longer flickers past faster than cell one can be read: the first message of a quiet moment is written instantly, and anything arriving in the next fraction of a second settles to the newest instead of each shoving the last aside. Errors are exempt and always write through at once, and can be held on the display instead of flashing by. Braille can send either the same wording as speech or a compact position-first form, and the "identical message repeated" window is adjustable. These are shared accessibility settings, so they are set once in QUILL and apply here.
- **Every destructive confirmation now defaults to No.** **Delete Folder**, **Delete Playlist**, **Remove All Episodes**, and **Delete Downloaded Files** all used to open with Yes as the default button, so pressing Enter reflexively destroyed the thing. Enter is now always the safe answer, and Yes is a deliberate choice. An automated build check fails if a destructive Yes-default is ever added again.
- **Quillins in QUILL Cast.** A **Quillins** menu runs QUILL's small, sandboxed, permission-gated add-ons inside QUILL Cast. A Quillin declares which apps it targets, so only add-ons written for QUILL Cast appear. The bundled `cast-premium-auth` sample supplies a sign-in header for a private subscriber-only feed. Off in Safe Mode; third-party Quillins stay disabled in this release.
- **Keyboard Shortcuts... and Global Hotkeys... in the Help menu.** The same Keyboard Manager and Global Hotkeys manager QUILL uses, scoped to QUILL Cast's own commands. A new **Show/Hide QUILL Cast to the Tray** command can be given a system-wide key (Ctrl+Alt+Shift+Q by default) so the window tucks away or comes back even when another program has focus.
- **Spotify podcasts (experimental, off by default).** Groundwork for playing Spotify-hosted podcasts, shipped hidden behind a feature flag. Turning it on needs a signed unlock code, a Spotify Premium account, and your own Spotify Client ID. Spotify audio is copy-protected, so an episode plays but cannot be downloaded. See the User Guide.
