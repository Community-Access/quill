For GitHub issues and pull requests, use the shared GitHub inside QUILL and QUILL Lite tutorial. It covers the expandable PR outline, Tab and arrow navigation, Ctrl+R replies, and every context menu. This is a separate guide from the 31 in-app lessons.

Welcome. There are 31 short lessons here, about 158 minutes in all, and you can take them in any order. Each one is a few small steps, and each step tells you what to press and what you should hear.

This page is the lessons written out, so you can read them anywhere. If you would rather be walked through, open Help > Tutorials… (Ctrl+Alt+F1) in QUILL Lite. It does a step for you when you ask, and moves on by itself once it hears you have done one.

The keys here are the ones QUILL Lite comes with. If you have changed a key, the lessons inside the app use your key; this page cannot know about the change.

Your first documents

Start here. Open a file and save it back unchanged, find out where the facts about it live and what kind of document you are in, and move between the documents you have open.

Open a file, and give it back unchanged

Start here. You open a file you already have, hear the three things QUILL Lite remembers about it, and save it back exactly as it was.

5 steps, about 5 minutes.

  1. Open something you already have. Pick any text file you already have. An older one is a good test. QUILL Lite opens plain text, Markdown, HTML and rich text, so whatever you choose will be fine.

    • Keys: Ctrl+O
    • You should hear: The file’s name, and the first line of it.

  2. Look at what it remembered. Now go to the status bar. It is a row of cells, and you move along it with the arrow keys. Listen for three of them: Encoding is how the letters are stored, Line Endings is how each line finishes, and Format is the kind of document. QUILL Lite keeps all three just as it found them.

    • Keys: F6
    • You should hear: Each cell’s name and its value as you arrow along.
    • Worth knowing: Press Escape to go back to your document. Looking around is safe: nothing changes unless you press Enter on a cell and answer the question it asks.

  3. Save it without changing anything. Save the file straight back without typing anything. If you like, compare it with a copy of the original afterwards. You will find they are the same, byte for byte.

    • Keys: Ctrl+S
    • You should hear: “Saved” and the file’s name.

  4. Find it again later. QUILL Lite remembers what you open. Open the Recent Documents window and your file is at the top of the list. Next time, press Enter on it instead of hunting for it with Open. Alt Shift 1 reopens the newest one without opening the window at all.

    • Keys: Alt+Shift+0
    • You should hear: The Recent Documents window, on your file’s name and its folder.
    • Worth knowing: Press Escape to close the window. Pin, in the same window, keeps a file you use often at the top for good.

  5. Type a character the file cannot hold. This one is optional. If your file uses an older encoding, type an em dash or an emoji and save again. QUILL Lite stops and asks you first: save as UTF-8 and keep the character, save as it was and lose it, or cancel. You decide.

    • You should hear: A question counting the characters, naming the encoding, and offering Yes, No and Cancel.
    • Worth knowing: Not sure which encoding your file uses? The Encoding cell in the status bar tells you.

That is the heart of QUILL Lite. Your file comes back the way you left it, and everything else is built on top of that.

Next: Four kinds of document, and how to say which.

Four kinds of document, and how to say which

Plain text, Markdown, HTML and rich text: what each one means for you, and the one key that moves between them.

4 steps, about 4 minutes.

  1. Find out what you are in. Go to the status bar and arrow to the Format cell. It tells you which kind of document this is. QUILL Lite guesses from the file’s name, and you can always change its mind.

    • Keys: F6
    • You should hear: The Format cell, reading “Markdown”, “HTML”, “Plain text” or “Rich text”.

  2. Ring through the four. One key steps through all four kinds, and each one says its name as you land on it. Keep pressing until you hear the one you want. Moving between plain text, Markdown and HTML does not touch your words. It only changes what the formatting keys type from now on.

    • Keys: Alt+Shift+F
    • You should hear: Each kind naming itself as you land on it.

  3. Go into rich text, and come back. Rich text is the one stop that really converts. Going in turns Markdown into real bold, headings and lists. Coming back out turns them into Markdown again, and QUILL Lite asks you first, naming anything it cannot carry across.

    • You should hear: A question before it converts, then “Rich text mode” or “Plain text mode”.
    • Worth knowing: Your file keeps its name. A rich document cannot be saved over a .txt file, so the next Ctrl+S offers you the right ending already filled in.

  4. Say otherwise, for this window only. Sometimes you want to write HTML in a scratch .txt file, and that is fine. Document Language lets you pick the kind yourself, and tells you what each choice will do before you choose. Your choice lasts as long as this window is open.

    • Keys: Ctrl+Alt+F6
    • You should hear: Each option described, and the one the file name would have chosen marked.

Now you know what kind of document you are in, and how to change it when QUILL Lite guessed wrong.

Next: Your documents are numbered.

Your documents are numbered

Instead of tabs, every open document gets a number. Here are the ways to get to the one you want.

3 steps, about 3 minutes.

  1. Open a second file. It opens inside the same window, as document 2. A number is easy to remember and easy to say: “document 3” is much clearer than “the other Untitled”.

    • Keys: Ctrl+O
    • You should hear: The new document’s number and name, in its title.

  2. Walk between them. Ctrl+Tab is what most people press, and Ctrl+F6 is the key Windows uses for this. Both work. The Window menu lists them too.

    • Keys: Ctrl+Tab
    • You should hear: The document you arrive at, announcing its number and name.

  3. Go straight to one. Hold Alt and press a document’s number to go straight to it. Once you have more than two open, this is the quickest way around, and it is why they have numbers.

    • Keys: Alt+1, Alt+2, Alt+3
    • You should hear: The document you asked for.
    • Worth knowing: Your documents all live inside one QUILL Lite window, so they do not appear in Alt+Tab. Use the keys in this lesson to move between them instead.

Open as many as you like. Each one has a number, and Alt with that number takes you straight there.

What to press when you are lost

Three keys that tell you where you are, what something does, and what QUILL Lite can do.

3 steps, about 3 minutes.

  1. Ask what you are standing on. F1 works everywhere: in your document, on a button, in any window. It tells you what the window is for, and then what the thing you are on does.

    • Keys: F1
    • You should hear: The window’s purpose, then the control’s.

  2. Ask what the facts are. The status bar holds everything QUILL Lite knows about your document, plus the last thing it said. Missed a message? It is waiting in the last cell, Status Message. Press End to jump there.

    • Keys: F6
    • You should hear: “Status bar” and the cell you land on, then each fact as you arrow.

  3. Ask what exists. The Keyboard Shortcuts window lists every key QUILL Lite has. It shows your keys, including any you have changed, and you can type part of a name to find one.

    • Keys: Ctrl+F1
    • You should hear: A searchable list of every command and its key.

Whenever you are unsure, one of these three keys will explain where you are.

Working in a document

Selecting more than a few words

Three different ways to select a stretch of text without seeing it, and when each one is the easiest.

6 steps, about 6 minutes.

  1. Take a whole thing in one key. If what you want is a whole word, line, sentence, paragraph or block, there is a key for it. You do not need to find where it starts. Try it now on the paragraph you are in.

    • Keys: Ctrl+Shift+H
    • You should hear: “Selected paragraph”, and how many words that was.

  2. Grow and shrink. Starting from whatever you have, you can grow the selection one step at a time: word, line, sentence, paragraph, block, then everything. You can shrink it back the same way. Each step tells you what it took.

    • Keys: Ctrl+Shift+X
    • You should hear: The new scope, and its word count.

  3. Mark a spot and walk to the end of it. For anything that is not a neat word, line or paragraph. Drop a marker where the selection should start. Then move any way you like, with the arrows, Find, Go To Line or a bookmark. You do not have to hold any key down while you go.

    • Keys: F8
    • You should hear: The line and column where the marker went down.

  4. Finish it, and hear how far it reached. When you reach the end, finish the selection. Everything between the marker and where you are now is selected. You can even use Find on the way, and it will not spoil it.

    • Keys: Shift+F8
    • You should hear: How many words, and the lines it ran between.
    • Worth knowing: Hearing the line numbers is a quick way to check you caught the stretch you meant.

  5. Or hold the Shift down without holding it. Here is a third way. Turn on Extend Selection Mode, and every arrow key selects as it moves, just as if you were holding Shift. Your screen reader does not say “selected” on every press, either. Turn it off the same way when you are done.

    • Keys: Alt+Shift+F9
    • You should hear: “Extend selection mode on”, and where it started.

  6. Check what you have before you replace it. Before you type over a selection, it is worth checking it is the one you meant, because the next key you type replaces it. Say Selection reads it back to you. A long one is summed up instead of read in full.

    • Keys: Ctrl+Shift+Y
    • You should hear: The selection, or a summary of it with its size.

Lost a selection by accident? Reselect Last Selection puts it back, however you made it.

Next: Finding your way back.

Finding your way back

Bookmarks, marks and Go Back. They sound alike, but each one helps you in a different moment.

4 steps, about 5 minutes.

  1. Keep a place you mean to come back to. You have nine numbered bookmarks in every file, and they are still there tomorrow. A bookmark stays with its words, so if you add three paragraphs above it, it is still on the right line.

    • Keys: Ctrl+Shift+1
    • You should hear: The bookmark’s number, and the line it went on.

  2. Drop a pin you will forget. A mark is quicker and lighter. It just remembers where you were before you went to look something up. There is no number and no list. Pop Mark takes you back and then forgets it.

    • Keys: Ctrl+Shift+M
    • You should hear: The line, and how many marks you now have.

  3. Go and look something up, then come back. Move a long way off. Ctrl+End, the end of the document, will do. Now pop the mark, and you are back where you were.

    • Keys: Ctrl+M
    • You should hear: The line you came back to, and how many marks are left.

  4. Undo the jump. Go Back works like the Back button in a web browser. Every jump in QUILL Lite can be undone with it: bookmarks, marks, headings, Go To and search results. So you can always get back to where you were.

    • Keys: Alt+Left
    • You should hear: Where you were before the jump.
    • Worth knowing: This is handy after following a heading. One key brings you back to the paragraph you were writing.

Bookmarks are for places you will come back to tomorrow. A mark is for right now. Go Back is for any jump you did not mean.

Skimming something long

Get a feel for a long document the way a sighted reader does by scrolling, using its headings instead.

5 steps, about 5 minutes.

  1. Ask for the shape. The headings list shows every heading in the document, in order. Each one tells you its level and its words. Press Enter on one to go there.

    • Keys: Ctrl+Alt+L
    • You should hear: Each heading, with its level.

  2. Walk it instead. Next Heading and Previous Heading move from heading to heading instead of line by line. Each time you arrive, you hear the level and the words.

    • Keys: Ctrl+Alt+H
    • You should hear: “Heading 2”, and the heading’s words.

  3. Skim by section. Moving by section tells you the heading, whether it is folded, and how many lines are under it. That last part is your glance. It tells you a section is huge without reading any of it.

    • Keys: Ctrl+Alt+Shift+Down
    • You should hear: The heading, its state, and its size in lines.

  4. Mark one as dealt with. Folding a section is a note to yourself that you are done with it. Nothing is hidden: your cursor still goes in and Find still finds things there. You just hear that it is folded as you pass.

    • Keys: Ctrl+Shift+F9
    • You should hear: How many lines went with it.

  5. Rearrange it, if the shape is wrong. The Heading Organizer shows every heading as one list. Tab makes a heading one level lower, Shift+Tab one level higher, and Move Up and Move Down carry the heading along with everything under it.

    • Keys: Alt+Shift+O
    • You should hear: Each heading as you arrow, with a preview of its section.
    • Worth knowing: Nothing changes until you press Apply, and one Ctrl+Z puts it all back.

With headings, a long document becomes something you can move around in quickly, a section at a time.

Spelling, without a red squiggle

How QUILL Lite lets you know a word looks wrong without breaking into your sentence, and the one key that fixes it.

4 steps, about 5 minutes.

  1. Type something wrong, and keep going. Type a word wrong on purpose and carry on. A moment after you finish the word, the status bar notes that it may be misspelled. Nothing is spoken over your typing, so you can finish your thought first.

    • You should hear: Nothing, unless you asked for a sound or a sentence in Preferences.

  2. Fix the word you are standing in. The Applications key is your red squiggle. Put the cursor in the word and press it. The first Down arrow lands on a suggestion. Press Enter to use it. Your cursor stays put and no dialog opens.

    • Keys: Applications, Shift+F10
    • You should hear: The suggestions, in order, as you arrow.
    • Worth knowing: Everything else you can do with the word, like ignore it, add it, or go to the next or previous one, is in the same menu just below the suggestions.

  3. Teach it a word. You can add a word to your own dictionary, and it is known for good. Or add it to the document’s dictionary, which travels with that file, so anyone who opens it gets the word too. That suits a product name better than your surname.

    • You should hear: Which of the two it was added to, by name.

  4. Check the whole thing. F7 goes through the document one word at a time. It starts where your cursor is, and when it reaches the end it offers to carry on from the beginning.

    • Keys: F7
    • You should hear: Each word, its suggestions, and a summary of what changed at the end.

One more thing: spelling stays quiet in program code and settings files, whatever your settings say, so you are not told about every made-up name in them.

Asking a question about a document

AI help is the one feature that sends anything off your computer. Here is how to turn it on, what is sent when you use it, and what it will not do.

5 steps, about 6 minutes.

  1. Turn it on, and agree to it separately. AI help stays off until two things are true: the feature is switched on, and you have said yes to the privacy agreement. These are two separate steps, so nothing is ever sent just because a profile, a settings file or someone else switched the feature on. Only your own yes counts.

    • Keys: Ctrl+Alt+Shift+K
    • You should hear: The agreement, read out in full before you are asked.
    • Worth knowing: You can reach the agreement three ways: this command, a check box in Preferences, or switching AI help on in Customize Features. You can always open it to read it, whether or not you have agreed.

  2. Connect this computer, once. There is no account, no password and no email address. You are given an eight-character code. Open the web page on anything with a browser, this computer or your phone, and type the code in. Asking for the code is the first moment anything is sent.

    • Keys: Ctrl+Alt+Shift+F10
    • You should hear: The code, character by character, and the window confirming in place rather than opening another one.
    • Worth knowing: Each computer connects on its own. Signing one out leaves the others connected.

  3. Ask about what is in front of you. Type a question about the open document, like ‘what does this say about the deadline’. The answer comes back along with the part of the document it came from, so you can go and read that part yourself.

    • Keys: Ctrl+Alt+Z
    • You should hear: The passages it chose, before anything is sent, and then the answer.
    • Worth knowing: Long documents are fine. It does not send the whole file. It picks the three passages most likely to answer you and sends only those.

  4. Or hand it a job. The AI pad has five rows. Four of them work on what you have selected, or on the paragraph or section you pick with Send this much: summarize it, rewrite it clearer and shorter, proofread it, or explain a tricky passage. The fifth is the question you just asked. Nothing changes in your document by itself. The answer comes with Replace My Selection, Insert Below and Copy underneath, and you choose.

    • Keys: Ctrl+Alt+G
    • You should hear: What is about to be sent, before it goes.

  5. Know what you have left. The service is free, so it has limits. One question can carry about two thousand two hundred and fifty words of your document, and you get a hundred requests a month. If what you asked about is too big, you are told in plain words before anything is sent, so you can select less and try again.

    • Keys: Ctrl+Alt+Shift+F9
    • You should hear: What you have used and what is left.
    • Worth knowing: The limits can change from time to time. Usage always shows the numbers that apply to you right now.

What is kept is how many requests you made and how big they were. What you wrote, and what came back, is not kept.

Write by talking

Dictate a few sentences into a document, take one back, turn it off, and find the settings. Everything stays on your computer.

6 steps, about 6 minutes.

  1. Start dictation. Put the cursor where the words should go, and turn dictation on. The first time, it takes a second or two to get ready.

    • Keys: Ctrl+F11
    • You should hear: Two rising tones, and “Dictation on”.

  2. Say a sentence, and pause. Talk the way you would to a friend, then stop for a moment. You do not need to say the punctuation: full stops, commas and capitals are put in for you.

    • You should hear: A soft tone, then the words that were written, read back with their punctuation said.

  3. Take a phrase back. Say scratch that, on its own, after a pause. Only the last phrase you said goes; anything you typed is left alone.

    • You should hear: “Scratched:” and the words that went.

  4. Turn it off with the same key. Press the dictation key again to turn it off. One press starts dictation and the next stops it, and stopping never cuts off a sentence you are still finishing.

    • Keys: Ctrl+F11
    • You should hear: Two falling tones, and “Dictation off”.

  5. See the phrases you said. Recent Phrases lists what you dictated this session, newest first. Enter writes one at the cursor again, which rescues a scratch that that went one too far.

    • Keys: Shift+F11
    • You should hear: Recent Phrases, on the newest phrase.

  6. Find the settings. Dictation Settings has the speech engine, the microphone and what you hear after each phrase. Moonshine, the engine it starts with, needs nothing downloaded. Better Accuracy: Speech Models offers larger models and recommends one for this computer. More Dictation Settings, inside it, lets you hold the key to talk if you prefer, and has the words heard while you speak and talking to the AI.

    • Keys: Alt+Shift+F6
    • You should hear: Dictation Settings, on Speech engine.
    • Worth knowing: Nothing you say leaves the computer unless you choose OpenAI with your own key, or a speech provider you set up with your own account in Speech Providers, and agree to it.

You can now write by talking, take back a phrase, and turn dictation on and off with one key. Say what can I say while dictating to hear everything it understands; the user guide’s dictation chapter has the rest.

Punctuation and symbols by voice

Say punctuation, start a bulleted list and a heading, and spell a web address, and hear every mark read back so you know it went in.

4 steps, about 5 minutes.

  1. Start dictation. Open a new document, so nothing you care about is in the way, and turn dictation on.

    • Keys: Ctrl+F11
    • You should hear: Two rising tones, and “Dictation on”.

  2. Say a sentence with its punctuation. Say: dear Sam comma thank you for the letter period. Then pause. Saying a mark always wins over the one the engine would add.

    • You should hear: Dear Sam comma thank you for the letter period.
    • Worth knowing: The marks are read back by name whatever your screen reader’s punctuation level is. Say punctuation marks in the read-back, in More Dictation Settings turns that off.

  3. Start a heading and a list. Say heading two, then the heading’s words, and pause. Then say bullet and an item. These marks count only at the start of what you say, so ordinary sentences are never turned into lists.

    • You should hear: Hash sign hash sign, then your heading; hyphen, then your item.

  4. Spell a web address. Say spell, then the letters with dot and at sign between them: spell sierra alpha mike at sign echo dot charlie oscar. Spelling writes punctuation with no spaces.

    • You should hear: The address, read back with its marks.

Say what can I say at any time for every mark and symbol, including the Markdown ones: backtick, vertical bar and block quote.

Fix a word by voice

Find words you said earlier, select them or put the cursor beside them, and correct them without touching the keyboard.

4 steps, about 5 minutes.

  1. Dictate a couple of sentences. Turn dictation on and say two short sentences, pausing after each, so there are words to find.

    • Keys: Ctrl+F11
    • You should hear: Each sentence read back.

  2. Select a word you said. Say select, then a word from the first sentence. The nearest one before the cursor is found first, because that is usually the one you are fixing.

    • You should hear: “Selected:” and the words.

  3. Say the right word. Just say the word you meant. What you say next replaces the selection, in one step that Undo or scratch that takes back.

    • You should hear: The new word read back.

  4. Correct and spell a name. Say correct and a name the engine got wrong, then spell it, or say spell that straight after dictating it: the letters you say next replace it.

    • You should hear: “Correcting” and the words, then the spelled word.
    • Worth knowing: If the words are not in the document, what you said is written as text and you hear Not found, written as text. Scratch that removes it.

Go to and go after put the cursor beside words instead of selecting them, and select again moves on to the next place the words appear.

Snippets and clips by voice

Copy the whole document, paste a Copy Tray slot and put in a snippet, all by saying so.

3 steps, about 4 minutes.

  1. Copy the whole document. With dictation on, say copy all. Nothing is selected, so nothing can be typed over by accident.

    • Keys: Ctrl+F11
    • You should hear: “Copied the whole document” and how many characters.

  2. Paste a slot from the Copy Tray. Say paste clip and a slot number, like paste clip one. It goes in as one phrase, so scratch that takes it out again.

    • You should hear: “Pasted slot 1”, or that the slot is empty.

  3. Put in a snippet by name. Say insert snippet and its name. If more than one snippet matches you hear how many, and the list opens so you can choose.

    • You should hear: “Snippet” and its name.

Say show clips or show snippets to open either list by voice.

Switch to Spanish and back

Move between English and Spanish dictation without opening a window.

2 steps, about 3 minutes.

  1. Switch the language. Use Switch Dictation Language. The choice is remembered, so the next time you dictate it starts in the language you used last.

    • Keys: Ctrl+Shift+F11
    • You should hear: “Español”.

  2. Come back by voice. While dictating in Spanish, say cambiar a inglés. In English, say switch to Spanish to go the other way.

    • You should hear: “English”.
    • Worth knowing: The first switch can take a moment while the Spanish model loads; after that it stays ready for the session.

Dictation Status tells you which language and engine are in use.

Make a live transcript

Write down a talk or a meeting as it happens, in its own document, while you keep working.

3 steps, about 4 minutes.

  1. Start a live transcript. A new document opens and everything the microphone hears is written into it, quietly. Please record other people only when they have agreed.

    • Keys: Ctrl+Alt+Shift+PageDown
    • You should hear: “Live transcript on, in a new document”.

  2. Ask how it is going. Use Dictation Status at any time; the status bar and a braille display show the same thing.

    • Keys: Alt+F9
    • You should hear: How many minutes and how many words.

  3. Stop and save. Use the same command again to stop. The document stays open, unsaved, for you to name.

    • Keys: Ctrl+Alt+Shift+PageDown
    • You should hear: “Live transcript stopped” and the number of words.

Time stamps in live transcripts, in More Dictation Settings, puts the time at the start of each paragraph.

Transcribe a recording

Turn an audio recording into text in the background, then open its saved transcript when you are ready.

5 steps, about 5 minutes.

  1. Open the recording transcriber. Transcribe a Recording opens a separate window for choosing the audio file and how to transcribe it.

    • Keys: Shift+F5
    • You should hear: Transcribe a Recording, with focus in Recording.

  2. Choose the recording. Type a file path, browse for one or more supported audio files, or drop them on the window. The window reports the recording’s length and estimates how long the chosen model should take.

    • You should hear: The file path, followed by its length and estimated time.

  3. Choose the language and speech model. Choose English or Spanish and a model that knows that language. The most accurate available local model starts selected. Local models keep the recording on this computer; an OpenAI model uses your own key and asks before sending the recording.

    • You should hear: The selected language and model, and the estimate for this recording.

  4. Start it and carry on. Press Enter to start. Transcription runs in the background, so the document you were editing stays untouched while you work.

    • Keys: Enter
    • You should hear: That the recording is being transcribed in the background.

  5. Open the result when it is ready. A completion notice appears in Notifications with a privately saved transcript. Activate the notice to open the transcript in a document; it is never inserted into the document you had open. Save the document normally if you want a separate file.

    • You should hear: The completed transcript in its own document.

The recording and your current document stay separate, and the result is waiting in Notifications when you are ready for it.

WordPress

If you look after a WordPress site: connect it, write and publish a post, fix a page you found by its address, pictures with alternative text, the check before you publish, earlier versions, and comments.

Connect your WordPress site

Connect QUILL Lite to a WordPress site with an application password, hear which role you have there, and learn the WordPress keys.

7 steps, about 5 minutes.

  1. Know what you need first. You need three things: the site’s address, your WordPress username, and an application password. An application password is a separate password WordPress makes for one app. It is not the password you sign in with, and you can take it away again at any time.

    • Worth knowing: These lessons use the QUILL WordPress Test Site, at https://lp.csedesigns.com/wordpress/, as the example. On your own site, use your own pages wherever a lesson names one.

  2. Open Connect a Site. In the File menu, open WordPress and choose Connect a Site. It is a short form, and nothing is saved until the site has said yes.

    • Keys: Ctrl+Alt+Shift+Grave, A
    • You should hear: The Connect a WordPress Site dialog, on Kind of site.

  3. Type the site’s address. Leave Kind of site on My own WordPress site. Tab to Site address and type it, for example https://lp.csedesigns.com/wordpress/. QUILL Lite only connects over HTTPS, so your password never travels in the clear.

    • You should hear: Site address, edit, and the letters as you type them.

  4. Get the password with your browser. Press Get Password with My Browser. Your browser opens the site’s own approval page. Sign in there if it asks, then choose Approve. On a newer site the password comes back to QUILL Lite by itself.

    • You should hear: “Connected to QUILL WordPress Test Site as” and your role, such as Editor.
    • Worth knowing: On an older site, WordPress shows you the password instead. Copy it, come back, and paste it into the box that is waiting for it.

  5. Or paste one from your profile. If you would rather do it by hand, make an application password in your WordPress profile, under Application Passwords, and copy it. Type your username, paste the password into Application password, and press Connect.

    • You should hear: “Connected to QUILL WordPress Test Site as” and your role.
    • Worth knowing: Your password is kept in Windows’ own Credential Manager, never in a settings file. Never paste it into an email or a chat.

  6. Choose which site comes first. With more than one site, Switch Site, in File, WordPress, chooses your default. New and Open start there, and a document always stays with the site it came from.

    • Keys: Ctrl+Alt+Shift+Grave, S
    • You should hear: “Default site:” and its name, or that it is your only site.

  7. Learn the WordPress keys. The WordPress key layer gives the commands one letter each. Press the layer key, let go, then press a letter. The six you will use most are O for Open Page or Post, P for Publish or Update, M for Media Library, S for Switch Site, W for Open by Web Address, or D for Save Draft to Site. Escape leaves the layer without doing anything.

    • Keys: Ctrl+Alt+Shift+Grave, then a letter
    • You should hear: Whatever the letter runs. After Escape, nothing at all.
    • Worth knowing: The whole layer: G New Page, N New Post, O Open Page or Post, W Open by Web Address, L Open Local Draft, D Save Draft to Site, P Publish or Update, E Schedule Publish, I Open on Site, Y Copy Address, R Properties, V Previous Versions, C Compare with Site, T Move to Trash, S Switch Site, Shift+S Sites, A Connect a Site, M Media Library, B WordPress Blocks, K Check Before Publishing, U Upload Files, X Alt Text Review. Every WordPress command is also in the Command Palette: type WordPress, or part of the command’s name.

You are connected, and the site has told you what your account may do. Next, write something and send it.

Write a post and publish it

Start a new post, write it in the editor you already know, keep it on your computer, send it as a draft, and then publish it.

6 steps, about 6 minutes.

  1. Start a new post. In the File menu, open WordPress and choose New Post. A post is a dated article, the kind that goes in a blog or a news list. A page is the lasting kind, like About or Contact.

    • Keys: Ctrl+Alt+Shift+Grave, N
    • You should hear: The New Post dialog, on Site, with your default site chosen.

  2. Give it a title and a format. Tab to Title and type one. The slug, which is the end of the web address, fills itself in as you type. Choose Markdown or HTML under Write in, check a category or two, and press Create.

    • You should hear: “New post for” the site, and that nothing is sent until you choose Save Draft to Site or Publish.
    • Worth knowing: Markdown is the easier one to write by ear. The format cannot change later.

  3. Write, and save on this computer. Write a few sentences the way you write anything else. Find, spelling and dictation all work here. Save as you always do: it keeps the post on this computer and sends nothing.

    • Keys: Ctrl+S
    • You should hear: The usual saved message. The site has not changed.

  4. Send it as a draft. Save Draft to Site, in File, WordPress, puts your post on the site where only you and your editors can see it. It is the safe way to see how it looks before anybody else does.

    • Keys: Ctrl+Alt+Shift+Grave, D
    • You should hear: “Draft saved to QUILL WordPress Test Site. It is not public.”

  5. Publish it. Choose Publish or Update. Before anything goes, a question names the post and the site, and says what Check Before Publishing found. Press Publish if you are happy, or Escape to stop.

    • Keys: Ctrl+Alt+Shift+Grave, P
    • You should hear: “Publish on” the site, the title, and “Ready to publish: no problems found”, or how many things there are to look at.
    • Worth knowing: If your role cannot publish, the same command sends the post for review instead, and says so.

  6. Hear where it went. Once it is published, the post’s web address is put on the clipboard, ready to paste into an email. Open on Site, in File, WordPress, opens it in your browser if you want to hear it the way a visitor will.

    • Keys: Ctrl+Alt+Shift+Grave, I
    • You should hear: “Published on QUILL WordPress Test Site. The address is on the clipboard.”

Saving keeps it here, Save Draft to Site sends it quietly, and Publish asks first. Closing a document never publishes anything.

Open a page by its address and fix a sentence

Open a post you found in your browser straight from its web address, change one sentence, and send the change back.

5 steps, about 5 minutes.

  1. Copy the address. In your browser, copy the address of the post you want to change. On the test site, use the welcome post, at https://lp.csedesigns.com/wordpress/welcome/. Copy it from the address bar.

    • You should hear: Your browser’s own word that the address was copied, if it says one.

  2. Open it by its address. Choose Open by Web Address, in File, WordPress. When there is an address on the clipboard it is used straight away; when there is not, a box asks you for one.

    • Keys: Ctrl+Alt+Shift+Grave, W
    • You should hear: Open Welcome to the test site, and the Open as list.

  3. Open it as Markdown. Choose Markdown. It reads more easily than HTML, and anything Markdown cannot show is kept exactly on a short line of its own, so nothing on the page is lost.

    • You should hear: “Opened Welcome to the test site from QUILL WordPress Test Site.”

  4. Fix one sentence. Find the sentence that says Open me by web address, and rewrite it in your own words. Arrow over it first if you like; this is an ordinary document now.

    • You should hear: Your new sentence, read back as you arrow over it.

  5. Send the change. Choose Publish or Update. A post that is already public is updated rather than published again, and the question says Update. Press Update.

    • Keys: Ctrl+Alt+Shift+Grave, P
    • You should hear: “Update on QUILL WordPress Test Site”, then “Published on QUILL WordPress Test Site.”
    • Worth knowing: If somebody changed the post on the site after you opened it, nothing is sent. You are told what changed, and offered Compare the two, Open the site’s copy, or Send mine anyway.

Any address on one of your sites opens this way. Next time, try Open Page or Post for a page you know by name rather than by address.

Pictures with alternative text

Put a picture from the site’s Media Library into a post with good alternative text, and fix a picture in the library that has none.

7 steps, about 6 minutes.

  1. Open a post to put a picture in. Choose Open Page or Post and pick Posts. Type part of a title in Find by title or status and press Enter, then Enter again on the one you want. The post you wrote earlier is a good one.

    • Keys: Ctrl+Alt+Shift+Grave, O
    • You should hear: Each row’s title, its status, and when it last changed.

  3. Listen to the alternative text. A picture dialog opens on Alternative text. That is what a screen reader says in place of the picture, so it should say what the picture shows and why it is there. This one already has some, from the library.

    • You should hear: Alternative text, “Volunteers sorting donations at the spring fair”.
    • Worth knowing: Suggest Alternative Text asks your chosen AI for a first try. Check the Decorative box for a picture that adds nothing a visitor needs, like a divider.

  4. Insert it. Change the text if you can say it better for this post, then press Insert. The text belongs to this placement, so the same picture can say something different in another post.

    • You should hear: “Picture inserted:” and its alternative text.

    • You should hear: “Alternative text saved on QUILL WordPress Test Site.”

  7. Review every picture in the post. Back in your post, Alt Text Review, in Tools, WordPress, lists every picture with its text, so the empty ones and the weak ones are easy to find and fix.

    • Keys: Ctrl+Alt+Shift+Grave, X
    • You should hear: How many pictures there are, and how many to look at.

Every picture now says something to somebody who cannot see it. Check Before Publishing finds any you missed.

Check Before Publishing

Have a post checked for the problems that trip up visitors, go to each one, and fix it before anybody else meets it.

5 steps, about 5 minutes.

  1. Open the post with problems. Choose Open Page or Post and pick Posts. Type draft in Find by title or status and press Enter. On the test site, open Things to check before publishing. It was made with one problem of each kind.

    • Keys: Ctrl+Alt+Shift+Grave, O
    • You should hear: Things to check before publishing, Draft, and when it last changed.

  2. Run the check. In the Tools menu, open WordPress and choose Check Before Publishing. It reads the whole post the way a careful visitor would, and nothing on the site changes.

    • Keys: Ctrl+Alt+Shift+Grave, K
    • You should hear: How many things there are to look at, with the problems and the things to check counted separately.

  3. Listen to the list. Arrow down Things to look at. Each one says what to look at and why: a heading 1 in the body, a skipped heading level, link text that does not say where it goes, a picture with no alternative text, a table with no header row, and a few more.

    • You should hear: One finding a line, each with its reason.

  4. Go to one. Press Go to It on the finding you want to fix. The list closes and the cursor lands on that place in the post, so you can fix it there and then.

    • You should hear: The line of the post the finding is about.

  5. Fix it, and check again. Make the fix, then run Check Before Publishing again. Work down the list until it is empty, or until what is left is something you chose on purpose.

    • Keys: Ctrl+Alt+Shift+Grave, K
    • You should hear: One fewer each time, and at the end, “Ready to publish: no problems found”.
    • Worth knowing: None of the findings stops you publishing. Publish runs the same check and reads you the summary in its question.

The check is the second pair of eyes a sighted editor has by default. Run it before every publish; it costs a few seconds.

Go back to a previous version

Hear the earlier versions of a post, the ones kept on this computer and the site’s own history, read one, and put it back.

5 steps, about 5 minutes.

  1. Open a post with a history. Open the welcome post again with Open by Web Address. The test site changed it three times when it was set up, so it has a history to look through.

    • Keys: Ctrl+Alt+Shift+Grave, W
    • You should hear: Opened Welcome to the test site, or your working copy of it.

  2. Open Previous Versions. In the File menu, open WordPress and choose Previous Versions. It lists the versions QUILL Lite kept, newest first, and then the site’s own history.

    • Keys: Ctrl+Alt+Shift+Grave, V
    • You should hear: Each row’s date, title, and why it was kept, such as On the site.

  3. Read one before choosing. Select a version and press View. The whole text opens in a window of its own, where you can read it or copy a paragraph out of it. Escape brings you back to the list.

    • You should hear: The Version window, with the title and then the text.

  4. Put it back. Press Restore on the version you want. It goes into the editor in place of your text, and nothing is sent to the site until you choose to.

    • You should hear: “Version put in the editor. Nothing was sent; your text before is in Previous Versions.”

  5. Hear what is different. Compare with Site, in File, WordPress, lists the differences between the site’s copy and yours, a line at a time. It is the check worth making before you send a restored version.

    • Keys: Ctrl+Alt+Shift+Grave, C
    • You should hear: Lines starting Site: for the site’s copy, and Yours: for yours.
    • Worth knowing: Changed your mind? Your text from before the restore is the newest row in Previous Versions, marked Before restore.

Nothing you send is ever lost: the site’s copy is kept before every update. Restore is the way back, and it never publishes.

Answer comments

Hear the comments waiting for you, reply to one, approve it, and deal with the spam.

5 steps, about 5 minutes.

  1. Open Comments. In the Tools menu, open WordPress and choose Comments. It starts with the ones waiting for you, because those are the ones nobody else can see yet.

    • You should hear: Comments: Waiting, and the site’s name, then the list. On the test site, Alex asks when the next session starts.

  2. Read the whole comment. Each row says who wrote it, on which post, when, and its first words. Tab to Details to read the whole comment before you decide what to do.

    • You should hear: The comment’s full text.

  3. Reply to it. Tab back to the list and press Reply. Write your answer and press OK. It is published under your name, under the comment it answers.

    • You should hear: “Reply to Alex published on QUILL WordPress Test Site.”

  4. Approve it. Press Approve on the comment. It goes on the site for everybody to read, and leaves this list of waiting ones.

    • You should hear: “Comment from Alex approved.”
    • Worth knowing: Spam and Trash are beside Approve, for the comments that should never be seen.

  5. Look in the spam. Press Show and choose Spam. WordPress catches most junk by itself, but now and then a real comment lands here, and Not Spam sends it back to Waiting.

    • You should hear: Comments: Spam, and the comments in it.

Waiting Count on First Use, in the same window, has the number of waiting comments said to you the first time you use the site in a session, so they never pile up unnoticed.

Forms

Start a form from a template, add questions and a rule, check it, fill it in yourself, save it in large print or braille, and publish it to your site and read the responses.

Start a form from a template

Start a contact form from a template, save it, and read it through, first as text and then as an outline of its questions.

6 steps, about 5 minutes.

  1. Know what a form is here. A form in QUILL Lite is a short plain text document: a title, some questions, their choices and a few rules, written in BITS Accessible Forms’ form language. You never have to learn the language, because the Forms commands write it for you.

    • You should hear: Nothing yet. This step is the idea the rest build on.
    • Worth knowing: Forms is on in every feature profile except Essential. If there is no New Form in the File menu, switch Forms on in Profiles and Features.

  2. Open New Form. In the File menu, choose New Form. It sits with the other New commands. Nothing is written anywhere until you have chosen where to save it.

    • You should hear: The New Form dialog, on Title.
    • Worth knowing: No Forms command has a shortcut key, because you will not write forms every day. The Command Palette finds every one of them: type form.

  3. Give it a title and a template. Type Ask us anything in Title. That is the name your visitors will see. Tab to Template and arrow down to Contact form. There are seven templates, and each one is a few questions you can change.

    • You should hear: Template, and Contact form: Name, email address and a message.

  4. Save the new form. Press Next. The ordinary Save As window opens with a file name made from your title, Ask us anything.bfl. Choose a folder you will find again and press Save. The new form opens straight away.

    • You should hear: “Saved Ask us anything.bfl, a contact form with 3 questions.”
    • Worth knowing: A form file ends in .bfl. It is ordinary text, so you can open it in any text editor too.

  5. Read it through as text. Arrow down through the form from the top. Each question starts on a line of its own: its kind, its id after a number sign, and its label in quotes. The indented lines under it are its settings, such as required.

    • You should hear: “text #name”, then “Your name” in quotes, then “@required”.
    • Worth knowing: Because it is text, Find, spelling, copy and paste all work here, and you can type a question yourself if you would rather.

  6. Hear it as an outline. In the View menu, choose Form Outline. It lists every page and question in order, each one read like a sentence, so you can hear the shape of the form without the form language.

    • You should hear: “Page 1, 3 questions”, then “Your name, text field, required, with an autofill hint, page 1”.
    • Worth knowing: Enter takes you to the selected question in the document. Escape closes the outline.

You have a real form, saved on this computer, and you have heard it two ways. Next, give it a question of your own.

Add questions

Add a choose-one question and a phone number question to your form, each from a short window that asks only what that kind needs.

6 steps, about 5 minutes.

  1. Put the cursor where it goes. Move to the line that says Your message. A new question goes in straight after the one your cursor is on, so this one will come last in the form.

    • You should hear: “textarea #message”, then “Your message” in quotes.

  2. Open Form Field. In the Insert menu, choose Form Field. A list of every kind of question opens, each row saying what a visitor meets. Section and Page break are at the top.

    • You should hear: The Insert Form Field dialog, and the Kind of question list.

  3. Find the kind you want. Tab to Search, type choose, and press Enter to narrow the list. Arrow to Choose one and press Enter. A visitor meets it as a group of buttons, and picks only one.

    • You should hear: Choose one: Choose one from a group of buttons.

  4. Write the question and its choices. In the next window, type Best way to reply in Label. Tab to Choices, one per line, and type Email, press Enter, then type Phone. Press Insert.

    • You should hear: “Inserted Best way to reply, choose one.”
    • Worth knowing: Help text is a sentence a screen reader reads with the question. Leave Id empty and the id is made from the label.

  5. Add a phone number question. With the cursor still on Best way to reply, choose Form Field again. This time pick Phone number, type Phone number in Label, and press Insert. Leave Required unchecked: only some people will want a call.

    • You should hear: “Inserted Phone number, phone number.”

  6. Save your work. Save as you always do. A form saves like any other document, on this computer, and nothing is sent anywhere. Each insert is also one step that Undo takes back.

    • Keys: Ctrl+S
    • You should hear: The usual saved message.

The form now asks five questions. The phone number is asked of everybody, which is not quite right. A rule fixes that.

Next: Add a rule and hear it as a sentence.

Add a rule and hear it as a sentence

Make the phone number appear only for somebody who asked to be phoned, built from three choices and read back to you as a sentence.

5 steps, about 5 minutes.

  1. Open Form Rules. In the Format menu, choose Form Rules. It lists every rule in the form as a sentence. This form has none yet, so the list is empty.

    • You should hear: The Form Rules window, and the Rules list.

  2. Say which question it listens to. Press Add Rule. In When this question, choose Best way to reply. Leave Is on is. In This answer, type Phone, the choice’s own words; capitals do not matter.

    • You should hear: When this question, and Best way to reply.
    • Worth knowing: A choice is stored as its words in small letters, with a hyphen for each space: Large print is large-print. QUILL turns what you type into that, so the rule matches however you write it.

  3. Say what it does. Tab to Then and leave it on Show. In To this question or page, choose Phone number. Read that back to yourself: when Best way to reply is Phone, show Phone number.

    • You should hear: To this question or page, and Phone number.
    • Worth knowing: Then can also hide, require, make optional, enable, disable, or skip to a page.

  4. Add it, and hear the sentence. Press Add Rule. The rule is written into the form for you, and QUILL Lite reads it back as the sentence it is, so you can hear whether it says what you meant.

    • You should hear: “Show Phone number when Best way to reply is Phone.”
    • Worth knowing: If you know the form language, Or write the condition yourself takes a whole condition instead. It is checked before anything is written, and you are told what is wrong if it does not read.

  5. Find it in the form. The new rule is in the Rules list. Press Go to It to close the window and land on Phone number. The line under it, starting @when, is your rule in the form language.

    • You should hear: “phone #phone”, then “Phone number” in quotes.
    • Worth knowing: Edit changes a rule’s condition, and Remove takes one out after asking. Undo in the document takes back either.

Rules are the part of a form that is hardest to see on a web page. Here every one is a sentence you can read. Next, let the form be checked.

Next: Check This Form.

Check This Form

Find what would make the form hard to fill in, go straight to it, fix it, and check again.

5 steps, about 4 minutes.

  1. Run the check. In the Tools menu, open Forms and choose Check This Form. It looks for anything that would make the form hard to fill in, such as a question with no label, and lists the most serious first.

    • You should hear: “Phone number has no autofill hint, so the browser cannot fill it in. The hint is tel.”
    • Worth knowing: An autofill hint lets a visitor’s browser fill in their own phone number, which saves typing and mistakes.

  2. Know the On the site today lines. Arrow down the Findings list. A line that starts On the site today is not a mistake in your form. It says where the forms plugin on a website reads your form differently today, so you know before you publish.

    • You should hear: Lines starting “On the site today”, if there are any.

  3. Go to the finding. Arrow back to the autofill finding and press Go to It. The window closes and your cursor is on the Phone number question, ready to fix.

    • You should hear: “phone #phone”, then “Phone number” in quotes.

  4. Fix it. Go to the end of the last indented line under Phone number and press Enter. Type two spaces, then @autocomplete “tel”, with the quotes. That is the hint the finding asked for.

    • You should hear: Your new line read back: “@autocomplete”, then “tel” in quotes.
    • Worth knowing: Suggest Autofill Hints, in Tools, Forms, asks your chosen AI to suggest them all at once. It says what it sends first.

  5. Check again. Choose Check This Form once more, in Tools, Forms. The autofill finding has gone. When there is nothing to fix at all, there is no list, just one sentence.

    • You should hear: Only On the site today lines, or, with none of those, “Check This Form found nothing to fix.”

Check This Form is worth running every time you change a form, and always before you publish one. Next, fill it in yourself.

Fill It In Yourself

Open your form as a real window and fill it in with your screen reader, the way a visitor will, before anybody else sees it.

6 steps, about 5 minutes.

  1. Open the form as a visitor meets it. In the Tools menu, open Forms and choose Fill It In Yourself. QUILL Lite builds a real window from the same text, with ordinary edit boxes, buttons and lists, so you meet what a visitor meets.

    • You should hear: Fill It In Yourself: Ask us anything, and the first question.

  2. Tab through the questions. Press Tab to move from question to question. Listen for each label, and for the word required on the ones that must be answered. Type a name and an email address as you go.

    • You should hear: Your name (required), edit. Then Email address (required), edit.
    • Worth knowing: If a question is hard to understand by ear here, it will be hard on the website too. That is the point of this window.

  3. Watch the rule work. Tab to the Best way to reply group and arrow to Phone. Your rule runs as you answer, and you are told about the question it brings in, because nothing else would say so.

    • You should hear: “Phone number appears.”

  4. Change your mind. Arrow back to Email. The phone number question goes away again, exactly as it will for a visitor who chooses Email on the site.

    • You should hear: “Phone number is hidden.”

  5. Submit, which sends nothing. Press Submit. Nothing is sent anywhere. Instead, a window shows what would have been sent, one question and its answer to a line, and anything that still needs an answer.

    • You should hear: What Would Be Sent: “Nothing was sent. This is what the form would send:”, then each question and your answer.
    • Worth knowing: On a form with more than one page, Next first checks this page and names any required question still empty, then puts you on it.

  6. Close it. Press Escape to close What Would Be Sent, and Escape again to close the form. Nothing you typed is kept, so you can try it as many times as you like.

    • You should hear: Your form document again, where you left it.

You have filled in your own form the way your visitors will. Next, make a copy for people who would rather have it on paper or in braille.

Save it as large print or braille-ready text

Make a large-print copy and a braille-ready copy of your form, from the same text, without a website.

4 steps, about 4 minutes.

  1. Know why there are other copies. Not everybody fills in a form on a website. Some people want it on paper in large print, and some want it in braille. Every copy comes from the same form, so it always asks the same questions.

    • You should hear: Nothing yet. This step is the reason for the next two.
    • Worth knowing: These work without a site and even in Safe Mode. If the form has a problem it cannot be read past, you are told to run Check This Form first, and nothing is saved.

  2. Save a large-print copy. In the Tools menu, open Forms and choose Save As Large Print. The ordinary Save As window opens with a name ending in large print. Choose a folder and press Save.

    • You should hear: “Saved Ask us anything large print.docx, a large-print Word document, 18 point and up, with 5 questions, lines to write on and boxes to check.”

  3. Save a braille-ready copy. Choose Save As Braille-Ready Text, in Tools, Forms. It writes one question to a block, with the choices lettered a, b, c, 40 cells to a line, ready to emboss or read on a display.

    • You should hear: “Saved Ask us anything.txt, braille-ready text with 5 questions, one a block.”
    • Worth knowing: With the braille pack installed, you are first asked whether to save it as it is or as a braille file in UEB contracted braille.

  4. Read the braille copy back. Open the .txt file you just saved, as you open any document. Arrow through it to hear one question to a block, so you know what the person reading it will find.

    • You should hear: The form’s title, then each question, numbered, with its choices lettered.
    • Worth knowing: Save As Web Page and Save As Word Document, beside these in Tools, Forms, make the other two copies the same way.

One form, and a copy for whoever needs one. The last lesson puts the form on your website.

Publish it and read the responses

Publish your form to a WordPress site running BITS Accessible Forms, put it on a page, try it there, and read what people send.

6 steps, about 7 minutes.

  1. Know what the site needs. Publishing needs a WordPress site you have connected, with the BITS Accessible Forms plugin installed and switched on. The WordPress lessons show how to connect a site.

    • You should hear: Nothing yet. This step is what the rest need.
    • Worth knowing: Without the plugin you hear that the command needs BITS Accessible Forms on the site, and to install and activate it there. Publishing and Responses are off in Safe Mode.

  2. Publish the form. With Ask us anything in front, open Forms in the Tools menu and choose Publish Form. With more than one site, you choose which one first.

    • You should hear: Publish Form, and Publish as, on Live.

  3. Choose live or draft, then say yes. Live means people can fill it in wherever it is placed. Draft puts it on the site where nobody can use it yet. Press Enter on Live, and then on Publish when the question asks.

    • You should hear: “Published Ask us anything on” your site, its form number, “live. Insert Form Into Page puts it on a page.”
    • Worth knowing: Publishing again later updates the same form. If somebody changed it on the site since, you are asked first, and the site’s copy is kept on this computer.

  4. Put it on a page. Open a page with Open Page or Post, in File, WordPress, and put the cursor where the form goes. Choose Insert Form Into Page in Tools, Forms, pick your form, then Publish or Update the page.

    • You should hear: “Inserted the Ask us anything form”, and that it shows on the page once the page is sent.

  5. Try it on the site. Back in your form, choose Test on Site, in Tools, Forms. It opens the page that shows your form in your web browser, so you can fill it in for real and send yourself a response.

    • You should hear: “Opened” the page’s name “on” your site, “where the form is.”

  6. Read what people sent. Choose Responses, in Tools, Forms. With your published form in front it goes straight to that form’s responses, newest first. Press Enter on one to read it, a question and its answer a line.

    • You should hear: Responses to Ask us anything, and each response: its number, when it was sent, and who sent it.
    • Worth knowing: Responses are people’s personal details. They are read only while this window is open and saved only where you choose, with Export to CSV or Export to Word.

Your form is live, and you can hear every answer it brings in. The first time you use a site in a session, you are also told how many new responses are waiting.

Coding, in the Developer profile

Work on a folder of code with an AI: ask for a change, review every edit, allow the commands it runs, hear the test results, and undo a whole turn.

Your first project task

Open a small project, ask for one change, review it, let the agent run the tests, hear the result, and put everything back with one command.

8 steps, about 12 minutes.

  1. Make a practice folder. Make an empty folder and put one small file of code in it, such as a Python file with a function that has a mistake in it. A project is just a folder; nothing in it is changed until you say.

    • Worth knowing: Use a copy, not your real work, the first time. Undo Last Turn puts files back, but practising on a copy costs nothing.

  2. Open the folder as a project. Open Project Folder is in the File menu. Choose Browse for a Folder and pick your practice folder. The status bar’s Project cell now names it.

    • You should hear: Project, and the folder’s name, is open.

  3. Ask for one small change. Press the task command. With a project open it starts a project task rather than a document task. Type one plain request, such as fix the add function and run the tests, and press Enter.

    • Keys: Ctrl+3
    • You should hear: Nothing at first; then “The plan is ready”, with the number of steps.
    • Worth knowing: The first time, QUILL may ask whether to use the project’s notes for AI agents, if it has any. Read Them First shows them.

  4. Read the plan. Press Alt+P in the task window to put the cursor on the plan, and read it with the arrow keys. Nothing has changed yet.

    • Keys: Alt+P

  5. Review the change. When the agent has an edit, Review Changes opens on a list of files. Press Enter on a file, read the change with its line numbers, and Accept or Reject it. Apply Accepted Changes writes what you accepted; Reject All writes nothing.

    • You should hear: The window’s own title and the first file’s row.

  6. Allow the test command. Run This Command? shows the exact command. Arrow through it, then Allow once. A warning line appears only when QUILL sees a risk, such as reaching the internet.

    • You should hear: The result in one sentence, such as “Tests: 3 passed.”

  7. Undo the whole turn. Undo Last Agent Turn, in Edit under Agent Work, puts every file the turn changed back as it was and removes files it made.

    • You should hear: “Undid turn 1”, and which files are back.
    • Worth knowing: If you edited one of those files yourself since, undo refuses and offers to show you the file as it was, so nothing of yours is lost.

  8. Try coach mode. Check Coach mode (Alt+A) in the task window and ask how to fix the mistake yourself. The agent explains and points to a file and line; you make the change in the editor.

    • Keys: Alt+A
    • Worth knowing: Stop Agent stops a task from any window: Edit, Agent Work, Stop Agent.

That is the whole loop. Every change is reviewed before it is written, every command asks first, and one command undoes a turn.
