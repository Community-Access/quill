Scrobbling and AudD song recognition

Branch feat/br-scrob. Two ideas from BlindRadio by serrebidev (MIT, https://github.com/serrebidev/blindradio), both chosen in docs/design/blindradio-review-2026-11-07.md (items 4 and 5). Both are off by default and send nothing until the listener turns them on and signs in or pastes their own token. No BlindRadio code was copied; the request shapes, the last.fm signature and the one-minute rule follow its scrobble.rs and recognize.rs, checked against the official API documentation.

What was built

Scrobbling

  • Songs heard for a minute or more are sent to ListenBrainz, last.fm and Libre.fm, each switched on separately in Preferences, Scrobbling group.
  • The rule is one minute, and that is deliberate. last.fm’s own rule is “longer than 30 seconds, and played for half its length or 4 minutes, whichever comes first”; ListenBrainz asks for the same half-or-4-minutes. Both need the song’s length, and radio almost never sends one. So Quill Radio uses BlindRadio’s rule: a minute heard. It is longer than 30 seconds and shorter than 4 minutes, so it never sends a song last.fm would call too short, and it never waits for a length nobody knows.
  • Heard, not broadcast. Titles are kept as a broadcast timeline; the clock that counts is the playhead (now minus how far behind live playback is, read from the mpv engine). A pause adds nothing, rewinding adds nothing, jumping ahead adds no more than real time. A listen is stamped with when hearing began. Up to six hours of timeline is kept, past the longest time-shift buffer.
  • Noise titles (song_history.is_noise_title: the station’s own name, Live, advert markers) and titles without an artist are never sent; a noise title still ends the song before it.
  • Hooked at song_history_commands.record_song, the one choke point every title change already goes through (ICY, the engine, the status page), so scrobbling and Song History never disagree. It runs even when Song History is off. A 5-second wx timer runs only while a song is followed and stops when nothing plays.
  • ListenBrainz: POST /1/submit-listens with Authorization: Token ...; single for one listen, import for several, playing_now for the song just started (never retried).
  • last.fm and Libre.fm: the desktop sign-in flow. auth.getToken on a worker, the browser opens the service’s own “allow Quill Radio?” page, a message box waits until the listener comes back and chooses OK, then auth.getSession on a worker. The password is never typed into Quill Radio. track.scrobble in batches of up to 50 with chosenByUser=0 (what last.fm asks a radio player to send), track.updateNowPlaying when a song starts (never retried). Libre.fm uses https://libre.fm/2.0/ and https://libre.fm/api/auth/.
  • Pressing Sign In again while signed in offers to sign out (No is the default).
  • Failed submissions wait in a queue on disk (radio_scrobble_queue.json in the data folder, atomic writes): 500 songs per service at most (newest kept), dropped after 14 days (last.fm ignores older scrobbles), retried after 1, 2, 4 … minutes up to an hour. Error 9 and HTTP 401 hold the songs until the listener signs in again and say so once per session; 11, 16, 29, 429 and 5xx retry; anything else drops the batch, because it will never be accepted as written. All sending runs on the task manager; the queue file is written on the worker, never on the UI thread.
  • Nothing runs in Safe Mode.

The last.fm application key

last.fm needs an API key and shared secret for the application. None is invented or committed. QUILL already ships build-time credentials through gitignored generated modules (tools/generate_podcast_index_key.py, tools/generate_youtube_oauth_client.py), so this follows that:

  • tools/generate_lastfm_api_key.py writes the gitignored quill/_lastfm_api_key.py from QUILL_LASTFM_API_KEY / QUILL_LASTFM_SHARED_SECRET (or the _FILE variants). Lenient: with nothing set it writes an empty pair, or keeps a pair already written.
  • Called leniently from scripts/build_windows_distribution.py and standalone/runtime/build_runtime.ps1.
  • The listener can always paste their own pair into Preferences (last.fm API key and last.fm shared secret boxes), and their own pair wins, the way the Podcast Index credential works. With neither, Sign In says what is missing, and a Get a last.fm API Account button opens https://www.last.fm/api/account/create.
  • Libre.fm uses the same pair. GNU FM has historically accepted any client key, so a build could drop that requirement for Libre.fm alone; I did not verify that against libre.fm live, so it is not relied on.

Someone has to register the application at https://www.last.fm/api/account/create and put the pair into the release build environment. Until then, last.fm and Libre.fm need the listener’s own pair.

AudD recognition

  • Preferences, Song recognition group: a Song recognition service choice (AcoustID, the default, or AudD) and an AudD API token box. The AcoustID key box moved into the same group.
  • Identify This Song is unchanged for AcoustID. With AudD chosen it needs only the token (no fpcalc), takes a 20-second clip from the buffer already playing (the same dump_recent_audio sample AcoustID uses, shorter), and posts it as multipart to https://api.audd.io/ with the token. The clip is capped at AudD’s 10 MB limit and deleted afterwards.
  • AudD’s answer maps into the same acoustid.Match AcoustID returns (title, artist, a new optional album field, score 1.0 because AudD gives none). The sentence names AudD and never says a percentage: “AudD says: Constant Craving by k.d. lang, from Ingenue.”
  • AudD errors 900 (token not accepted) and 901 (free limit, no token) are their own sentences; 300 (too short) is “no match”. No automatic polling: AudD is only ever asked when the listener presses Identify This Song.

Secrets

Every token and session key is kept in the Windows credential store (DPAPI-sealed to the user) through the new quill/core/radio/radio_credentials.py, the same store the AcoustID key uses; nothing is in a settings file, so a synced or exported data folder carries none of them. Session keys carry the account name in the credential’s user-name field. tests/conftest.py has a new autouse fixture, radio_credential_store, so no test reaches the real store.

User guide text (to add)

Under Identify This Song:

Choosing AudD instead of AcoustID

Identify This Song asks AcoustID by default. AcoustID is free, and all it is sent is a fingerprint of the audio, which cannot be played back. If you have an AudD account, you can ask AudD instead: it copes better with live radio, where a presenter talks over the start of a song or one song runs into the next. To use it, open Preferences, find the Song recognition group, set Song recognition service to AudD, and paste your AudD API token (from dashboard.audd.io) into the AudD API token box.

Be clear about the difference. AudD is sent about twenty seconds of the audio itself, together with your token. Quill Radio only does that when you choose Identify This Song; it never listens on its own. To go back, set Song recognition service to AcoustID.

A new section, Scrobbling:

Scrobbling: keeping a list of what you heard

Quill Radio can add the songs you hear to your listening history on ListenBrainz, last.fm or Libre.fm. This is called scrobbling. It is off until you turn it on.

Scrobbling sends the artist, title and album of each song you hear for a minute or more, and the time you heard it, to the services you turn on, and only when you turn one on and sign in or paste your token. Nothing about the station or about you is sent.

ListenBrainz. Open Preferences, find the Scrobbling group, and paste your user token from listenbrainz.org/settings into the ListenBrainz user token box. Check Send the songs I hear to ListenBrainz, then choose OK.

last.fm and Libre.fm. In the same group, choose Sign In to last.fm (or Sign In to Libre.fm). Your web browser opens that service’s own page, asking whether Quill Radio may scrobble for you. Sign in there if it asks and choose Yes, allow access. Then come back to Quill Radio and choose OK in the box that is waiting. You type your password on the service’s page, never into Quill Radio. Then check Send the songs I hear to last.fm (or Libre.fm) and choose OK. To sign out, choose the Sign In button again; it offers to sign you out.

If Sign In says it needs an API key, this copy of Quill Radio did not come with one. Choose Get a last.fm API Account, make a free account there, and paste its API key and shared secret into the two boxes above the buttons. Libre.fm uses the same pair.

What counts as heard. A song counts once you have heard a minute of it. last.fm’s own rule is half the song or four minutes, but that needs the song’s length, and radio stations almost never send one. If you pause or rewind with the time-shift buffer, the song counts when you actually hear it, and the time you were paused does not count. The station’s own name, “Live”, adverts, and titles with no artist are never sent.

If the internet drops or a service is busy, the songs wait and are sent later, for up to two weeks. If a service stops accepting your sign-in, Quill Radio tells you once, and the songs wait until you sign in again. Nothing is sent in Safe Mode.

Not done or not verified

  • No live request was made to ListenBrainz, last.fm, Libre.fm or AudD; all behaviour is checked against hand-written fixtures from the official docs. The first real sign-in and scrobble should be tried by hand with a test account, ideally under JAWS and NVDA, including the “come back and choose OK” box.
  • The application has not been registered with last.fm; until it is, the listener must paste their own API key and secret.
  • AudD’s exact error JSON ({"status":"error","error":{"error_code":...}}) is from memory of the API and the docs’ error list; worth one live check with a wrong token.
  • The AudD clip is the raw stream data mpv’s dump-cache writes (MP3, AAC or Ogg, depending on the station), sent as application/octet-stream. AudD accepts common formats, but an HLS station’s dump has not been tried.
  • Time-shift is read from the mpv engine. On the classic engine there is no time-shift, so the playhead is live, which is right. The engine-title fallback (mpv media-title) may already describe the playhead rather than live when shifted; then a shifted song would count late, never wrongly.
  • Retries happen only while a station is playing (the timer stops when nothing plays); songs queued at exit are sent the next time a station plays.
  • The internet radio inside QUILL (the editor) runs the same hook, since it shares song_history_commands.record_song, but QUILL has no Preferences rows for scrobbling. It scrobbles only if its RadioHistory has a service turned on; I did not check whether that is the same file Quill Radio writes.
