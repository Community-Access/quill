Dictation: how the design was built

What QUILL Lite 1.1 (and QUILL’s Live Dictation) did with each part of QUILL Lite Basic Dictation (the PRD in this folder), and the places it deliberately went another way. Written 2026-09-25, alongside the code.

PRD sections

PRD Status Notes
1-7 Summary, interaction, continuous dictation Done Ctrl+F11 toggles; phrases commit at pauses; focus stays in the editor.
8-11 Command layer and parsing Done Data-driven table, longest phrase first, literal escape, action objects rather than string replacement.
9 Command vocabulary Done Every listed phrase, plus braces, symbols, and single quotes. “new page” is not built: neither editor’s plain text has a page, and QUILL Lite has no page break command to reach.
12-13 Transactions and undo Done Each phrase one undo step; scratch removes exactly its own range, after checking the text is unchanged.
14 Selection Done The first phrase replaces a selection.
15 Spacing Done Plus: a full stop an engine added at a pause is taken back when the next phrase continues the sentence.
16-18 Architecture, dependency strategy Changed See “Engines” below.
20 Packaging Done Models and the sherpa-onnx package ship beside the launcher; nothing is downloaded.
21 Package identity Not needed SAPI and sherpa-onnx need no package identity.
22 State machine Done Plus STANDBY, for the wake phrase.
23-27 Earcons Done Generated byte-for-byte from the PRD’s generator; four Sound Scheme rows.
28-29 Sound settings, announcements Done Start/stop/error tones and on/off words switchable; phrase feedback is the shared sound/speech/both/neither choice, where speech reads the words back.
30 Microphone Done Chosen by name; an unplugged choice is refused, not replaced.
31-32 Privacy, network Done Offline; nothing recorded, logged or sent.
33 Wake word Done, with one change User-defined wake phrase. Uses the dictation engine and voice detection rather than a separate keyword model, which is what makes any phrase possible without training. Foreground only; see below.
34 Windows Voice Typing Done An engine choice that hands over to Windows+H.
35 Voice Access Coexists QUILL never drives Voice Access; both can run. Untested together by ear.
36 Settings Done Engine, language (Windows speech), microphone, phrase feedback, dash, tones, words, wake phrase. The keyboard shortcut is changed in the Keyboard Manager like every other key.
37 Errors Done Every failure is spoken with what to do.
38 Performance Done Moonshine runs at about a twenty-fifth of real time on one core; first start loads for a second or two.
39-40 Accessibility, visual status Done Menu check mark plus a Dictation cell in QUILL Lite’s status bar.
45 Phase two Done Wake phrase, user vocabulary, user phrases, more punctuation, capitalization commands, selection commands, spelling mode, cursor commands. The macOS adapter is out of scope: QUILL Lite is Windows only.

Engines

The PRD proposed the WinRT speech API. It was replaced for two reasons found while building: WinRT’s recogniser cannot use any microphone but the Windows default, and choosing the microphone was a requirement; and Windows’ desktop recogniser (SAPI), the other built-in option, proved inaccurate on an untrained voice and does not punctuate. Eight candidates were measured (engine-comparison.md); Moonshine and Whisper, run by sherpa-onnx with no PyTorch, ship in the box, and SAPI stays as an option.

The wake phrase listens in the foreground only

The PRD allowed an opt-in background mode. It was left out: to write anything, waking would have to bring the window forward and take the focus from whatever the person was doing, which is exactly the kind of surprise a screen reader user cannot see coming. The microphone closes when another program comes to the front and reopens when QUILL comes back.
