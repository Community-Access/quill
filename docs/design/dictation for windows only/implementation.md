# Dictation: how the design was built

What QUILL Lite 1.1 (and QUILL's Live Dictation) did with each part of
*QUILL Lite Basic Dictation* (the PRD in this folder), and the places it
deliberately went another way. Written 2026-09-25, alongside the code.

| PRD | Status | Notes |
|---|---|---|

| 14 Selection | Done | The first phrase replaces a selection. |

| 20 Packaging | Done | Models and the sherpa-onnx package ship beside the launcher; nothing is downloaded. |
| 21 Package identity | Not needed | SAPI and sherpa-onnx need no package identity. |
| 22 State machine | Done | Plus STANDBY, for the wake phrase. |
| 23-27 Earcons | Done | Generated byte-for-byte from the PRD's generator; four Sound Scheme rows. |
| 28-29 Sound settings, announcements | Done | Start/stop/error tones and on/off words switchable; phrase feedback is the shared sound/speech/both/neither choice, where speech reads the words back. |
| 30 Microphone | Done | Chosen by name; an unplugged choice is refused, not replaced. |
| 31-32 Privacy, network | Done | Offline; nothing recorded, logged or sent. |

| 35 Voice Access | Coexists | QUILL never drives Voice Access; both can run. Untested together by ear. |

| 38 Performance | Done | Moonshine runs at about a twenty-fifth of real time on one core; first start loads for a second or two. |

## Engines

The PRD proposed the WinRT speech API. It was replaced for two reasons found
while building: WinRT's recogniser cannot use any microphone but the Windows
default, and choosing the microphone was a requirement; and Windows' desktop
recogniser (SAPI), the other built-in option, proved inaccurate on an untrained
voice and does not punctuate. Eight candidates were measured
(`engine-comparison.md`); Moonshine and Whisper, run by sherpa-onnx with no
PyTorch, ship in the box, and SAPI stays as an option.

## The wake phrase listens in the foreground only

The PRD allowed an opt-in background mode. It was left out: to write anything,
waking would have to bring the window forward and take the focus from whatever
the person was doing, which is exactly the kind of surprise a screen reader user
cannot see coming. The microphone closes when another program comes to the
front and reopens when QUILL comes back.
