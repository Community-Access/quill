FUX-07 adoption: dictated and expanded text goes only to the intended place

Date: 2026-11-23. Scope: every path in the QUILL family that types into another program’s window. Earshot and macOS are out of scope.

The rule, from the family UX pilots, section 4: text is inserted only into the target that was current when the input began. If the target’s identity changes, or cannot be confirmed, the text is kept and offered as Insert or Copy. It is never typed somewhere else, and never read aloud unasked. A secure or password field is refused only where the platform can tell, and nothing claims to detect one where it cannot.

How a target is identified

Two identities exist, and both are now built from the same three facts: the foreground window handle, its process id, and the focused control.

  • Dictation (focus_identity in quill/ui/windows_dictation_external.py): (window, process, control), where the control is UI Automation’s runtime id, else UI Automation’s native window handle, else the focused window handle Windows reports for the foreground thread (focused_window_handle in quill/platform/windows/text_target.py). No window in front gives None, which never equals a locked field.
  • Inkwell’s text runtime (TargetSnapshot.same_identity in quill/core/external_text.py, built by probe_focused_target in quill/platform/windows/external_target.py): target id, window, process and control id. The control id now falls back to the focused window handle before the class name.

Before this change both fell back to the focused window’s class name when UI Automation had nothing, and two edit boxes in one dialog share a class.

A restarted program gets a new process id (and normally a new window handle), so it is never the same target. A password field is refused when UI Automation’s IsPassword says so, and by the deny-list of password managers and sign-in windows (quill/core/expansion/targets.py). Neither is described to the user as a general password detector.

What “offer Insert or Copy” looks like

  • Dictation keeps its existing pause: Resume, Resume in This Field and Discard Held Words, in the tray menu and the Dictation menu, with held words also kept sealed on disk for Recent Phrases (Insert Again, Copy).
  • Inkwell’s one-shot insertions (rows 7 and 8) show Text Not Typed (quill/ui/held_text_dialog.py): one sentence from quill/core/expansion/destination.py, which names the reason and the choices and never contains the text; Insert (Alt+I, offered only where trying again can work: the focus moved or Windows could not answer), Copy (Alt+C), and Cancel (Escape). The window’s sentence is read with its title when it opens, and nothing else announces it (GATE-13). Insert goes back to the same target and checks it again; it never types into a new one.
  • Inkwell’s typed-as-you-go expansions and undo (rows 6 and 9) have nothing to keep: nothing was erased, the abbreviation is still on screen. They say one sentence with the reason.

What only a live check can show

Unit tests fake the target identity; they cannot show what real programs report. These need a person at a Windows machine with NVDA and JAWS, on a source run and on the frozen build:

  • Inkwell expansions type again in Notepad, Word, Outlook, Chrome, Edge, Firefox and an Electron app (for example Teams or VS Code), after this fix.
  • Quick Insert and a fields snippet type into the same field after the picker or form closes, in each of those, including Outlook’s To and Subject boxes and a browser form with several text fields.
  • That Windows’ focus-stealing prevention does not stop Inkwell bringing the window back from the tray-launched picker; when it does, Text Not Typed appears and Insert succeeds once the person returns.
  • That UI Automation runtime ids stay stable while a field keeps the focus in Chrome, Edge, Firefox, Word and Outlook; if one changes on its own, dictation would pause there with no move.
  • A browser password field and a Windows sign-in prompt are refused, and Text Not Typed offers Copy only.
  • NVDA and JAWS read Text Not Typed’s sentence once, with its title, and do not read the text.
  • Cast’s and Radio’s Dictate Here with QUILL Transcribe both running and starting from closed, moving the focus in between.
