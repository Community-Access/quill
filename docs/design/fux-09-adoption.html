FUX-09: the first useful task, app by app

Date: 2026-11-24 Feature: FUX-09, “Give the first useful task a clear beginning”, from the family UX plan (read it with git show b7c6a1a04^:complete2.md). It is held to family-interaction-contracts.md. It is not one of the promoted pilots (2026-11-19-family-ux-pilots.md, section 5), so the work is limited to gaps in what the family already has: no new tour, welcome, sample library or training product. Out of scope: Earshot and the macOS apps.

The moment: “I installed this. What can I do successfully right now?” The first thing a new person meets is usually an empty list: no podcasts, no favorites, nothing queued, nothing open. That place should name the one or two actions that fill it, by the label the menu uses and the key that runs it, so a first useful result comes before the product’s vocabulary.

1. The shared pieces

  • quill/core/first_task.py (wx-free, strict-typed) builds the sentence: first_task_line("No podcasts yet.", [NextAction("Add Podcast", command_id, "finds one by name")], key_for) gives “No podcasts yet. Add Podcast (Ctrl+N) finds one by name.” The key is read from the app’s live bindings when the line is built, so a rebound key is the key that is said. An unbound command is named by its label alone, never with a key that does nothing. Two actions read as a choice (“A, or B.”). A third is a menu, not a beginning, and is left out.
  • quill/ui/empty_state_line.py is the wx side for a list that had nothing to say when empty. EmptyStateLine is one read-only, single-line text box, named “Getting started”, placed just before the list in the Tab order and shown only while the list is empty. It is on screen for magnification, in the Tab order for the keyboard, and read by the screen reader when it gets focus, so the app never has to speak it (GATE-13). It is single-line because a screen reader reads the whole value of a single-line edit on focus, but only the wrapped line under the caret of a multi-line one. Its name is set with set_spoken_name, the name Windows screen readers read. It keeps a normal border, so it looks like a field and shows a focus ring, and the whole sentence is its tooltip, for a magnifier view that cuts it short. When the list fills, the line hides, and if it had focus, focus goes to the list; if it was the window’s last focus when a dialog opened (Add Custom Station), focus goes to the list when the window is active again. Launch focus goes to the line while the list is empty, and to the list otherwise.
  • Where an app already has a place for the sentence, that place is used instead of a new control: Cast’s spoken arrival in an empty place, Radio’s Local Media window, and Weather Center’s status line. Cast’s arrival sentence is said, not shown; a line before its Podcasts tree is left for now (section 3).

Rules every change keeps:

  • The line is a genuine action: the menu’s label and the key that runs it.
  • It is said once, or shown on one focusable control. It is never a modal, a tour, a welcome message or a reminder, and it never blocks the normal window.
  • A first task that needs the internet, an account or a download says so in the same sentence (“over the internet”).
  • Sample content stays marked as sample and separate from personal work.

3. Left, with the reason

  • Cast: a line before an empty place, not only speech. Cast’s empty places say their sentence on arrival and keep it on the status bar; there is no line before the tree, so once the status bar moves on the sentence is not on screen. Putting an EmptyStateLine in Cast’s content pane, which swaps between a tree and a report list for thirteen places, is a change to that pane rather than to the first task.
  • QUILL Lite: the empty window’s state as text. The empty MDI window has no control and no status bar, so its sentence is speech and braille only; a status bar or title change on the shell is a change to the shell’s layout, left for its own work.
  • QUILL: a tray launch with Start With No Document Open. The window is not shown, so the Start page’s sentence is not said, and restoring the window from the tray does not say it either; the Start tab itself is there.
  • Cast: Add Your First Podcast, then closed without adding. The Add Podcast window is a peer window with no “closed without adding” signal; closing it leaves the empty tree without its sentence until the next launch or the next arrival at Podcasts.

4. Existing pieces reused, not duplicated

  • Tutorials (Help > Tutorials, Ctrl+Alt+F1) in QUILL, QUILL Lite, Radio, Cast, Transcribe and Weather, each with a first lesson (“Write and save your first document”, “Open a file, and give it back unchanged”, “Play your first station”, “The first hour”, “Your first dictation, in the Practice window”, “Add your first place”). The empty-state lines name the action itself rather than a lesson, because the action is the first useful result; the welcomes already point to Tutorials. “Your First Week” is the WordPress track and has no empty state of its own here.
  • The welcomes in Cast and Radio are kept as they are. They run once; the line is what is there every time after.
  • Practice Dictation in Transcribe is the scratch document the plan’s example asks for.

5. Acceptance

  • First-task wording is a genuine action with a keyboard path and visible label: every line names the menu’s label and its live key, and is on screen.
  • Sample content is clearly marked, removable and never mixed into personal work: no sample is added. Social’s existing demo is the one sample in the family; its marking is planned above.
  • Declining the sample leaves the normal app ready to use: the line never blocks anything; the list, menus and keys work as before.
  • First tasks name a network, account or download dependency before asking: Cast’s and Radio’s lines say “over the internet”; Player, Converter, Studio and Transcribe’s first tasks are local.
  • Observe time to first result and where new users stop: this needs people, not code. It belongs with the pilot observation in 2026-11-19-family-ux-pilots.md; no telemetry is added.
