QUILL Audio Studio migration audit

Date: 2026-07-17. Research only; no code changed. Sources: full reads of quillas/apps/studio.py and quillas/ui/app_shell.py, targeted reads across quillas/ and S:, both pyproject files, both installers, the PyInstaller spec and both build pipelines, git history in both repos, and a claim-by-claim trace of the changelog and user guide. Five parallel research passes: feature parity, dependencies/packaging, vendor drift, UX/accessibility, and misrepresentation.

Each finding is tagged with where the defect lives:

  • [BOTH-HIDDEN] code is byte-identical in QUILL and QUILL-AS, but only the standalone surfaces it, so only Audio Studio users can hit it. Fix upstream in quill/, then re-vendor.
  • [BOTH-LIVE] broken and reachable in both apps. Fix upstream.
  • [AS-ONLY] lives in standalone-only code (studio.py, app_shell.py, build scripts, installer, docs).
  • [DOCS] documentation or UI-string misrepresentation only.

Executive summary

The extraction itself is high quality: 256 of 282 vendored files are byte-identical to QUILL HEAD, the audio core (workbench, player, speech, publish) came across intact, and most changelog claims trace to working code. The serious problems cluster in four places:

  1. The Phase 2 listening layer is substantially broken at the seams. The home library never populates, its pinned views are never filled, the tree context menu would crash, the play queue skips a book on auto-advance, and the sleep timer’s end-of-chapter mode is ignored. Most of this is shared code that embedded QUILL never exercises, so it shipped without a second user.
  2. Screen reader output is silently broken in the shell. The standalone’s _set_status never speaks, so a dozen “announcements” (including the sleep timer firing and voice-preview guidance) are visual-only. For a screen-reader-first product this is the single most corrosive defect.
  3. The two build pipelines disagree, and each has a hole. The PyInstaller freeze cannot install on-demand engines (no pip); the portable build omits declared extras (SFTP, feedback dialog) and stages ffmpeg from a hardcoded path with only a warning if absent.
  4. Re-vendoring is currently a foot-gun. Nine local edits to vendored files, six of them uncommitted, are unprotected by the vendor script’s PRESERVE list; a re-vendor today reintroduces top-level ImportErrors. Root cause: the import-rewrite regex misses quill.build_info, quill.branding, quill.__main__, and quill._feedback_token.

Where we go from here (2026-07-20 recommendation)

The strategic questions – merge Audio Studio into QUILL as an app? standalone vs integrated? a shared runtime component future apps rely on? – were already decided in sections 20 and 22-25 and remain the right calls. Current state makes the next move concrete:

  1. Merge Audio Studio into QUILL as quill/apps/studio.py (the Option D reverse-vendor, section 25). The feature code already lives in quill/ as the source of truth; quillas/ is only a vendored snapshot, so this is a move + wrapper conversion, not a rewrite. It puts Audio Studio beside radio.py / podcasts.py, deletes the 283-file vendored closure and its drift tooling, and – most valuable – brings Audio Studio under the same GATE suite that just kept Radio 2.1.1 clean. Highest-leverage structural step, and the literal answer to “merge it in as an app.”

  2. Build-time sharing, NOT a runtime shared library (section 22). Each app ships its own frozen copy of quill/ off a pinned tag; a per-app hotfix is a pin bump, and one app can never break another. The heavy assets (ffmpeg, libmpv, engine packs, neural voices) already runtime-share in %APPDATA%\Quill, which is where the real disk win is; runtime-sharing the Python code would add a compatibility-matrix support burden for little gain. Radio 2.1.1’s pinned-SHA build already proves this model end to end.

  3. The “component future apps rely on” is the data contract + core seams, not a shared install. What makes the apps a family is the shared %APPDATA%\Quill store and the wx-free quill/core seams (player, recorder, speech, publish, versioned-store), consumed at build time. The concrete enabling work is Tier 1 data-store hardening (preserve unknown fields on rewrite, rewrite-only-on-legacy, last-writer stamp) plus a FAMILY-DATA.md ownership map – do this before more apps pin/vendor, so a newer app can’t silently downgrade an older app’s settings.

Recommended order: (a) finish Tier 0 hygiene (the pr files); (b) land Tier 1 data-store hardening on a branch with the GATE suite; (c) reverse-vendor Audio Studio into quill/apps/studio.py per section 25 and pin its wrapper to a QUILL tag; (d) then unify the four packaging stacks into one parameterized toolkit (section 24). Audio Studio being “in good shape for now” is exactly the moment to reverse-vendor it – before it drifts further from quill/ HEAD.

1. Critical bugs (P1)

1.1 Library never shows any books [BOTH-HIDDEN]

No code path ever appends to LibraryState.books. load_library only reads persisted state (quillas/core/audio_studio/library.py:54-79); there is no add function and studio.py only synthesizes a temporary BookEntry (studio.py:381). The tree renders state.books (quillas/ui/audio_studio/library_tree.py:86-88), so “Your books” is four permanently empty headers. Everything downstream - Enter to open, Delete, Favorites, Move to Folder, the whole context menu - is unreachable. Meanwhile the status bar reports “N books in your library” from the recent-files MRU (studio.py:1945-1948), contradicting the empty tree. This is the 1.1.0 headline feature and it does not function.

1.2 Pinned views are empty decorations [BOTH-HIDDEN]

view_query (library.py:133-159), which would populate Favorites, In Progress, Recently Played, and Inbox (including the promised Inbox-from-recent-files behavior, see comment at studio.py:348-349), is never called anywhere. Documented as working in docs/userguide.md:48-53 and release-notes-1.1.md.

1.3 Shell announcements are silent for screen readers [AS-ONLY]

studio.py’s _set_status (1927-1932) and _set_status_quiet (1934-1940) both resolve to the status-bar-only AppShellFrame._set_status (app_shell.py:76-79); only _announce (app_shell.py:71-74) speaks. QUILL’s MainFrame _set_status speaks; the standalone’s does not. Silent as a result: “Sleep timer: playback stopped” (studio.py:488), “Download this voice to hear a preview.” (1894), “Choose a voice to preview” (991), “Voice configured: X” (1404), “Audio Studio cancelled” (1018), “Piper voice already downloaded” (1450). A blind user pressing Preview on a not-installed voice hears nothing.

1.4 Tree context menu crashes when invoked [AS-ONLY]

studio.py:656-658 calls PopupMenu(menu, item) passing a TreeItemId where wx expects a point - TypeError. Latent only because 1.1 makes book items unreachable. The keyboard path (Applications key, _on_tree_key at studio.py:577-579) hits the same call, and the tree’s accessible name (studio.py:314-319) advertises that key.

1.5 Two vendored call sites crash on _show_message_box [BOTH-LIVE]

AppShellFrame._show_message_box(message, caption, style) has no default style (app_shell.py:81) - and neither does QUILL’s MainFrame version (quill/ui/main_frame.py:5661). Two shared call sites pass only two args:

  • publish_dialog.py:609-612 - the Safe Mode refusal raises TypeError instead of showing “Publishing is disabled in Safe Mode.”
  • chapter_workbench.py:781-784 - the unreadable-book error dialog itself crashes, masking the real failure.

These are genuine upstream QUILL bugs vendored faithfully; both apps crash.

1.6 Play queue skips a book on auto-advance [AS-ONLY]

next_entry mutates current_index (play_queue.py:71-76). _on_book_finished advances once to announce “Up next” (studio.py:439) and _on_book_closed advances again to open (studio.py:461) - the announced book is skipped. Also the “Up next” announcement fires at end of playback, but nothing opens until the Workbench closes, which misleads about what happens next.

1.7 “Reveal in Workbench” is a no-op [BOTH-HIDDEN]

library_tree.py:217-224 only announces “Revealing {title} in the Chapter Workbench” - no reveal, no open. userguide.md:55 documents it as “Reveal in Folder”. Speech-only success is especially confusing for SR users.

1.8 Sleep timer “stop at end of chapter” does nothing [BOTH-HIDDEN]

The dialog exposes and persists the flag (sleep_timer_dialog.py:60-62; core/audio_studio/sleep_timer.py:37,68) but should_fire checks only elapsed minutes (sleep_timer.py:42-46) and _on_sleep_fired never reads it (studio.py:485-488). Documented as working in userguide.md:280, release-notes-1.1.md, and CHANGELOG.md.

1.9 Favorite/Move announcements lie for unknown books [BOTH-HIDDEN]

LibraryTreeActions.toggle_favorite always announces success (library_tree.py:117-121) but core toggle_favorite returns False and changes nothing for paths not in the library (library.py:113-115). Same for move_to_folder (library.py:125-127 vs library_tree.py:174-175). The announcement is the only feedback an SR user gets.

1.10 On-demand engine installs cannot work in the PyInstaller build [AS-ONLY]

quillas/core/speech/engine_install.py gates every install (Kokoro, Vosk, Faster-Whisper, MP3) on pip being importable; a PyInstaller onedir has no pip, so all four fail with “This build cannot install X automatically.” The spec excludes those engines on the promise they install on demand - a promise that build cannot keep. This is the exact defect scripts/build_studio_portable.py was written to fix, yet scripts/build_release.ps1 still drives the broken path and both pipelines coexist with recent build logs. Decide which artifact ships and retire or fix the other.

2. Feature parity gaps vs QUILL

Confirmed intact: quillas/ui/audio_studio, core/speech (including dictation/ and providers/), core/audio_studio, core/publish, and all three keymap packs are byte-for-byte matches with upstream. Speech Hub, Manage Speech Models, pronunciation dictionaries, optional components, the command palette, and the update flow all made the jump.

Gaps, most valuable first:

  • Offline transcription and caption generation: fully vendored (quillas/ui/ai_transcribe_dialog.py, core/speech/transcribe.py, cloud_transcribers.py) but no menu item or command surfaces them. QUILL exposes “Transcribe Audio or Video (Offline)” and “Generate Captions (Offline)” (quill/ui/main_frame_menu.py:2235, 2707). For an audio-first app this is the most obviously in-scope missing feature, and it is nearly free to wire.
  • Watch-folder automation is half-vendored: the actions (watch_audiobook.py, watch_transcribe.py, watch_actions.py) came over, but the engine (quill/core/watch_service.py, watch_worker.py, watch_queue.py, watch_profiles.py, watch_profile_store.py) and the profile UI (quill/ui/main_frame_watch_profile.py) did not. Auto-narrate- a-dropped-folder is a natural Studio feature; currently the vendored actions are dead code. Vendor the engine or delete the actions.
  • Single-document translated-speech export (quill/ui/translated_speech_export_dialog.py + runner) was not vendored; only batch translation via the wizard survives.
  • Sound events configuration (quill/ui/sound_events_dialog.py) and the sound manager (quill/ui/sound_manager.py) are missing while the earcon core (sound_pack.py, earcon.py) is vendored - users cannot toggle individual earcons.
  • Hugging Face token management (tools.speech_hf_token upstream) has no confirmed standalone entry point (may be reachable inside Speech Hub; unverified).
  • Deliberately out of scope but now dead weight: the voice-interaction stack (dictation controller, wake word, voice commands, conversation), most of core/ai (assistant, agent catalog, tool gateway, harness), accessibility_agent, skill_pack. Reachability analysis (scripts/analyze_reachability.py) says 84 of 283 files are unreachable from the Studio entry points. Either surface a dictation/voice-command story later or trim the seed so re-vendors stop dragging ~30 percent dead code (and its maintenance surface) along.

3. Dependencies and packaging

3.1 Undeclared or never-installed dependencies

The portable pipeline installs only base + ui extras from pyproject; the following degrade silently (all imports are guarded):

  • feedback_hub: the accessible Report a Bug dialog never loads; the app always falls back to the online form (quillas/ui/app_shell.py:393-394). Note the contradiction: build_release.ps1:36-40 hard-fails the build if the feedback token is missing, yet the package that consumes the token is not bundled. The token is dead weight; the intended accessible dialog was clearly meant to work.
  • paramiko: declared under the [ssh] extra but the portable build never installs extras beyond ui, so SFTP publishing - an advertised 1.0 feature - reports paramiko missing in the portable build.
  • sounddevice: mic capture and live PCM playback of cloud TTS unavailable (core/speech/capture.py, core/ai/tts.py).
  • elevenlabs: the advertised “ElevenLabs cloud voices” provider is inert without it.
  • winrt-Windows.* (OCR): scanned-PDF/image text extraction backend absent.
  • sound_lib: earcons fall back to winsound; minor.
  • llama_cpp: local-LLM path dormant (Ollama is the documented local option, so arguably fine); note QUILL-AS has no requirements.txt with the extra index URL needed to resolve its wheel anyway.

3.2 Build pipeline holes

  • build_studio_portable.py stages ffmpeg/mpv by copying from the hardcoded prior-build path C:and only prints a warning if absent. A portable build on a clean machine ships without ffmpeg - compressed export, M4B chapters, and loudness all break - with no hard error. Make ffmpeg a hard requirement like build_release.ps1 does.
  • No offline wheelhouse: engine_install.py still looks for {app}/wheels/ (as QUILL’s Offline Edition provides) but neither QUILL-AS build script stages one, so on-demand engines always need PyPI.
  • pyproject has no force-include for package data (QUILL’s does: data/*.dat, schemas, sound packs, audio). PyInstaller collect_all and the portable copytree read the source tree so current builds are fine, but any wheel-based install silently drops voice previews, schemas, and sound packs. Latent trap.
  • Installer: no .quilljob file association despite double-click open being a shipped feature (CHANGELOG 1.0.0); QUILL’s installer registers associations and shell verbs. Uninstall behavior (never touches %APPDATA%) is correct and documented.
  • Assets verified present and tracked: 84 voice-preview mp3s, sound packs, schemas, keymap packs, thesaurus data. Good.

4. Vendor drift and re-vendor risk

4.1 Unprotected local edits (re-vendor clobbers all nine)

The PRESERVE list in scripts/vendor_from_quill.py protects only core/recent.py and ui/main_frame_speech_downloads.py. Unlisted local edits that a re-vendor today would revert:

Committed: - core/storage_mode.py - adds QuillAudioStudio.exe to portable detection. Revert loses portable-mode detection for the app’s own binary. - ui/optional_components_dialog.py - quillas.build_info import. Revert is a top-level ImportError at module load. - core/ai/init.py - trimmed vendored-slice docstring (incidentally survives because ensure_ancestor_inits skips existing files; not by design).

Uncommitted (the six modified files in git status): - core/keymap_format.py - quillas.branding. Revert is a top-level ImportError. - core/accessibility_agent.py - lazy shim around quill.core.glow, which is denylisted and not vendored. Revert is an ImportError. - core/diagnostics.py - quillas.build_info plus lazy glow fallback. - core/optional_components.py, stability/crash_report.py, platform/macos/macos_app.py - guarded import fixes; revert degrades gracefully.

Root cause: the rewrite regex (vendor_from_quill.py:113) only rewrites quill. followed by core|ui|io|stability|platform|assets|apps|tools| plugins|quillins_bundled. It misses quill.build_info, quill.branding, quill.__main__, and quill._feedback_token, so every re-vendor reintroduces broken imports that then get hand-fixed as perpetual working-tree edits. Extending the regex (or adding these files to PRESERVE) eliminates seven of the nine deltas. Also note core/feedback_token.py is listed in the design doc but not in PRESERVE, so it too reverts on re-vendor.

Immediate hygiene: commit the six working-tree edits so they cannot be lost independently of any re-vendor.

4.2 Upstream fixes not yet vendored

  • 4287997 fix(ui): guard AI dialog CallAfter callbacks against a destroyed dialog (ui/dialog_contract.py). Relevant - Workbench AI title proposals use CallAfter.
  • core/feature_command_map.py upstream gained “studio.play_queue”: “core.read_aloud” - an Audio Studio mapping the extraction itself missed.
  • 4fc3317 (stability/logging_config.py relocate_log) - radio-only, low priority.

Otherwise upstream has barely moved; no uncommitted upstream work touches vendored paths. core/recent.py’s remove_recent_audiobook_file has been upstreamed, so that delta can retire from the local-deltas list.

5. Misrepresentations (claims vs reality)

  • Safe Mode does not disable all downloads [DOCS + BOTH-LIVE gap]. README.md:26, userguide.md:231 and :347, and CHANGELOG.md:34 all say downloads are disabled in Safe Mode. Reality: download_dectalk_exe, download_piper_exe, download_espeak_exe (main_frame_speech_downloads.py:1332/1400/1569) and studio._download_piper_voice (1429) have no Safe Mode check, and both the Speech Hub and Download Optional Components menu items are reachable in Safe Mode. Upstream QUILL’s code is identical, so this is a documentation overstatement of a shared code limitation. Either gate the engine downloads or correct the docs - given Safe Mode’s purpose, gate the downloads upstream.
  • Workbench AI-titles error points to “AI > AI Hub” (chapter_workbench.py:607-616), a menu that exists in QUILL but not in the standalone (its AI menu has only “Set Up AI…”). Works upstream, stale here. [DOCS]
  • DECtalk download success text says “Open Manage Voices” (main_frame_speech_downloads.py:1353, 1388) - a surface the standalone does not have; the action actually opens the Speech Hub. Minor. [DOCS]
  • Publish dialog promises “macOS Keychain” credential storage (publish_dialog.py:113 via core/platform_nouns.py) but every secret save/load imports only platform/windows/credential_manager (lines 338, 347, 429, 515); on macOS the imports fail silently and nothing persists. A working platform/macos/keychain.py exists but is never wired in. Inherited unchanged from upstream. [BOTH-LIVE]
  • Resume-on-launch is documented as off by default (userguide.md:289) and the code comment says opt-in (studio.py:391), but the default is True (history.py:62, :97). [BOTH-HIDDEN default, AS-visible]
  • No reverse misrepresentations found: the one stated limitation (media keys Windows-only) is accurate. Verified accurate end-to-end: voice previews (bundled sample plus live synthesis), AI chapter titles, translated editions, cloud voice keys, SFTP/Auphonic/RSS publishing on Windows, ACX check from both entry points, update checks, and the Safe Mode gates for AI and publishing (module-level; see the _show_message_box crash in 1.5 for the publish refusal path).

6. UX polish (P2)

  • Resume-on-launch default (see above) drops users into the modal Workbench on every launch and can contend with the startup update prompt (both wx.CallAfter, studio.py:266-268). Missing-file resume is silent (studio.py:396-397).
  • Sleep timer: setting stays enabled after firing; on relaunch the watcher is never re-armed (loaded at studio.py:239 but only _on_sleep_timer starts it), so the dialog says enabled while nothing is armed. No remaining-time readout. Firing with no active player still claims “playback stopped”.
  • Modality trap: the Workbench is modal, so Ctrl+M, Sleep Timer, and Play Queue in the shell menu are unreachable exactly while a book is playing; with no book open Ctrl+M announces “No book open to mute.” userguide.md:155/283 documents muting from the shell.
  • Media keys are grabbed system-wide for the whole session (app_shell.py:209-232) but no-op without an active player (studio.py:467-481) - Studio swallows the user’s media keys while idle. Release them when idle, or make play/pause resume the last book.
  • Play Queue dialog: no announcements after Add/Remove/Clear/Next, no current/next marker on rows, selection and focus lost after Remove, no Delete-key handling, missing-file entries indistinguishable, and auto-advance stops silently at a missing file (studio.py:462).
  • Duplicate menu mnemonics: Help “&User Guide” vs “Check for &Updates” (studio.py:738/744); context menu “&Reveal…” vs “&Remove…” (588/596) and “Remove from &Favorites” vs “New &Folder” (590/594). Letter-press cycles instead of activating.
  • Safe Mode has no visible or spoken indicator (title set once at studio.py:228; _refresh_statusbar 1942-1950); users discover it only on refusal, and the Publish path makes them pick a file first (studio.py:1028-1049) before refusing (then crashes, per 1.5).
  • New Folder is only reachable from a book’s context menu (studio.py:582-585), so with an empty library folders can never be created.
  • Stale versions and doc mismatches: userguide.md:3/17 and prd.md:3/485/493 still say 1.0.0 while everything else is 1.1.0; userguide.md:23 omits the required data-mode.json marker for portable mode (core/paths.py:44-53) - a hand-made data folder silently uses %APPDATA%; “(missing)” library markers promised at userguide.md:42 do not exist.
  • Undocumented shipped features: Pronunciation Dictionaries menu (studio.py:713-720), the “Generating preview” cue and its setting (1714-1721), diagnostics-bundle save (1544-1570), palette commands for sleep/mute/queue (869-871).
  • Dead code and small inconsistencies: _on_library_key (556-564) never bound; two different missing-file messages (935-938 vs 810); context menu object leaked when selection is invalid (656-658).

7. Direction and enhancements (P3)

  • First-run: a new user sees three buttons, an empty (broken) tree, and one status line. SAPI5 means narration works out of the box - lean into that with a short welcome checklist (pick a voice, hear a preview, narrate a first document) and a pointer to the Speech Hub. This is the single highest-leverage UX investment after the P1 fixes.
  • Fix the library by design, not just by bug-fix: decide the ingestion story. The obvious model: every wizard output and every book opened in the Workbench is added to the library (Inbox), with Favorites/folders as curation on top. That one decision makes findings 1.1, 1.2, 1.9, and the New Folder gap fall out naturally.
  • Surface offline transcription and captions (section 2) - vendored, audio-first, near-zero cost to wire into Book Tools.
  • Decide the watch-folder story: vendor the engine (auto-narrate a dropped folder is a compelling Studio feature) or delete the orphaned actions.
  • Friendlier failure dialogs: _finish_background_task shows raw exception text (studio.py:1632); relegate detail to the diagnostics bundle.
  • Single-instance guard (studio.py:2108-2117): a second launch duplicates the tray icon and silently steals media keys.
  • Unify Kokoro readiness probes: Speech Hub uses kokoro_engine_ready (studio.py:1258), the wizard uses kokoro_onnx_ready (batch_speech_runner.py:122); the two surfaces can disagree.
  • Help menu: PRD is a developer document in a consumer menu (studio.py:739); Release Notes is hardcoded to release-notes-1.1 (studio.py:775) and will silently go stale; About box URL is non-activatable plain text (2026-2035).
  • Wire platform/macos/keychain.py into the publish dialog (upstream first) to make the macOS credential promise true.
  • Tray: verify keyboard invocation (Enter/context key) reaches both handlers (app_shell.py:166-169).

Part 3: Family-wide audit (QUILL, Radio, Cast, Audio Studio, qrm, Beacon)

Scope: S:, S:-radio, S:-cast, S:-AS, S:, S:-beacon. Goal: gaps, bugs, and a ranked unification plan so the apps genuinely shake hands on shared resources and a common stack.

15. The family today: four different sharing models

  • Thin wrapper (quill-radio, quill-cast): app frame lives in quill/apps/; the repo holds launcher, spec, installer, docs. Automatic code parity with QUILL, but requires the monorepo to develop, and the quill dependency is an unpinned git URL while release builds bundle whatever sits in S:.venv - two non-reproducible sources.
  • Vendored closure (QUILL-AS): full snapshot as quillas via vendor_from_quill.py. Reproducible and collaborator-friendly, but with the drift/regex/PRESERVE costs documented in Part 1 and a long-term schema-skew risk against the shared data store.
  • Manual adaptation (qrm): near-verbatim hand-port of quill/core/radio with import remaps and no tooling - a vendored closure without the vendor script.
  • Independent silo (quille-beacon): own engine, own SQLite store, own data dir (%APPDATA%), own sync layer (QuillSync) intended to become the family’s - but today no other app has an adapter and Beacon exchanges nothing with the family at runtime.

17. Consolidation strategy

17.1 The shared-store risk is confirmed, not theoretical

All Windows apps read and rewrite %APPDATA%.json and keymap.json through versioned_store.py. Two confirmed failure modes:

  • to_versioned serializes only the fields the running binary’s Settings dataclass knows, and load_with_migration rewrites the file whenever the content differs. A newer QUILL writes a new setting; an older vendored QUILL-AS launches, silently drops it, and rewrites the file - with no backup, because the schema_version matches (settings_migration.py ~116-137, versioned_store.py ~95-100).
  • merge_keymaps drops any binding for a command id not in the running app’s DEFAULT_KEYMAP and rewrites the cleaned file (keymap.py ~832-838). The oldest app launched last wins; newer apps’ custom bindings vanish.
  • No cross-process locking: concurrent QUILL + Radio sessions last-writer-wins on shared files.

Today quillas’s copies are byte-identical so the risk is latent - but it is activated by exactly the drift the vendoring model produces. This is the single most important “shaking hands” fix in the family.

17.2 Evidence of sharing-model costs

  • Double-fix: issue #1102 was fixed independently in QUILL (95e9368) and QUILL-AS (d7cdebb). Re-vendor churn commits exist (bbfa26a, 5c4baaa, d0dca99, f2639b7).
  • Quadruplicated packaging: four near-identical spec + iss + build_release.ps1 stacks (QUILL, radio, cast, AS) with divergent fixes (cast missing libmpv staging; AS carrying two rival pipelines).
  • Unpinned wrapper deps: radio/cast declare quill git HEAD with no tag, while release builds bundle S:.venv - neither reproducible.
  • Hand-port tax: qrm re-ported ~25 modules by hand; every upstream radio fix (including all of Part 2) must be re-ported.

17.3 Options considered

  • A. True monorepo: all app frames in quill/apps/, standalone repos become packaging shells. One fix lands once; every app inherits the GATE quality suite. Cost: the QUILL-AS collaborator must work in the monorepo; release cadence couples.
  • B. Shared quill-core library consumed as a pip dependency by all apps including QUILL. Cleanest long-term, but the seam is very wide (app_shell pulls settings, keymap, commands, safety, announce, task manager) and it doubles PR overhead for a small team. Do not start here.
  • C. Keep vendoring, fix the tooling: regex coverage, PRESERVE hygiene, dead-code trim, nightly re-vendor CI against a pinned SHA with the test suite as oracle, vendored-at stamp. Cheap (days), preserves collaborator independence, but does not fix double-fix cost or store skew.
  • D. Hybrid (recommended): C now as a bridge; harden the data store regardless; then reverse-vendor Audio Studio into quill/apps/studio.py and turn quill-audio-studio into a radio/cast-style wrapper pinned to a QUILL tag; consolidate the four packaging stacks into one parameterized toolkit; Beacon and qrm converge on their own schedules (Beacon’s PRD already targets quill/apps/beacon.py).

Recommendation: D, in the order data-store hardening -> vendor-tooling bridge -> packaging unification -> reverse-vendor. Option B only if a plugin ecosystem or multiple external collaborators materialize.

22. The shared-library question (raised 2026-07-17, pre-execution)

The owner asked whether to (a) start consolidating the quill/apps structure as part of the early work and (b) ship ONE shared core library that all apps utilize instead of each app shipping its own copy, while preserving per-app release flexibility for urgent fixes.

Framing that matters before deciding:

  • “One shared library” has two very different meanings. Build-time sharing: one codebase (quill/ as the single source), every app builds against a pinned tag and ships its own frozen copy inside its installer. Users never share code on disk; developers share 100% of it. Per-app releases = pin bumps. This is what the decided plan (Option D + pinned tags) already delivers. Runtime sharing: one installed copy of the core on the user’s machine (like a shared runtime), apps resolve it at launch. Smaller installs and one core update fixes all apps at once - but it introduces the compatibility-matrix problem: upgrading the shared core for app A can break app B that was tested against an older core. Safe versions of this (side-by-side versioned runtimes, per-app compat floors, garbage collection of old versions) are real engineering and a real support surface.
  • The family already runtime-shares the heavy assets: ffmpeg, libmpv, engine packs, neural voices, models all live once in %APPDATA% and are used by every app. The Python code each app would stop duplicating is tens of MB - the smallest part of an install. So the disk/size argument for runtime-sharing the code is weak; the strongest arguments are update-once (also achievable with per-app updates) and conceptual cleanliness.
  • Release flexibility requirement: hotfixing one app must not force releasing all apps. Build-time sharing satisfies this trivially (hotfix branch off the app’s pinned tag, cherry-pick, rebuild one app). Runtime sharing satisfies it only with side-by-side versioning.
  • Early quill/apps consolidation vs the Michael constraint: the P1 fixes that are in shared code get built in quill/ regardless. The question is only whether AS’s shell (studio.py) moves into quill/apps/ before or after Michael’s build. Before = one codebase sooner, but the packaging-toolkit work lands on the critical path of his build. After = fastest path to a working build, small re-vendor churn in the interim.

24. Installer strategy and execution state (2026-07-17, current)

Lean vs full: decided direction

One embeddable-Python-plus-pip payload, delivered as two installer variants - exactly what QUILL already does (standard vs Offline Edition; the two portable zips in S:prove it).

  • Standard installer = LEAN (the default). Ships the runtime + core + ffmpeg/mpv (basic audio must work offline), and DOWNLOADS neural engines (Kokoro, Whisper, Vosk) and optional voices on demand via Voices > Download Optional Components. Small download. This is the answer to “people want a smaller install and download components.”
  • Offline installer = FULL (a second, additive artifact). Same payload plus a staged wheelhouse (wheels, wheels-whisper, wheels, wheels) and the engine binaries, for field/ACB use without reliable internet. QUILL’s engine_install.py already looks for {app}<name>, so this is staging, not new code.
  • “Lean now, full later” is zero-risk to the now: the offline variant is a superset build that does not change the lean one. Lean ships first; offline improves later.

The hard prerequisite for lean to WORK is that the installer wraps the embeddable-Python-plus-pip payload (so on-demand downloads can run). This is the crux fix below.

The Audio Studio installer must switch payloads

Today build_release.ps1 produces BOTH the portable zip and the system installer from the PyInstaller freeze (dist, _internal, no pip).
