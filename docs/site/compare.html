QUILL or QUILL Lite: which editor should you install?

This page compares the two products, not two documents — QUILL has a document-comparison tool of its own, and this is not it. QUILL and QUILL Lite are two free editors for Windows, built from one codebase to one accessibility standard, and they are not the same thing. QUILL is a writing environment. QUILL Lite is that environment's editor with the environment taken off it: Notepad and WordPad, rebuilt so that they answer.

The short answer

Most people who write, read and file documents all day want QUILL. Most people who open a text file to change one line want QUILL Lite. Both are free, both are MIT-licensed, and installing one does not affect the other — they keep separate settings, separate folders and separate updates — so if the answer is not obvious, install both and let a week decide.

Choose QUILL Lite if this sounds like you

You want a replacement for Notepad or WordPad that speaks properly. You edit configuration files, logs, notes and letters. You want Ctrl+N to be instant and never to meet a setup wizard. You want either no Format menu at all, or exactly the formatting WordPad had. You have never needed to open a spreadsheet, a PDF or a braille file in an editor, and you would rather a program did nine things well than a hundred things at once.

Choose QUILL if this sounds like you

Documents arrive and you have to deal with them, whatever format they are in: Word, PowerPoint, Excel, PDF, EPUB, braille, DAISY, email archives. You write long things and want an outline, bookmarks you can export and a way to compare two drafts. You want a document read aloud in a voice that is not your screen reader, or transcribed, or turned into an audiobook. You read braille. You use AI with your own key or your own local model. You are on a Mac. Or you simply want all of it, because turning features off is easier than finding them one at a time.

One codebase, two front doors

This is worth saying plainly, because a "Lite" edition in this industry is usually a fork that quietly rots, and this one is not a fork. QUILL Lite's code lives inside the QUILL package rather than beside it, and it does not copy QUILL's editing surface — it uses it. The spell checker, the numbered bookmarks, the copy tray, the clip library, the free hosted AI, the dictation engine, the file-encoding logic and the F1 help engine are one implementation with two callers.

Three things follow from that, and all three are things you can feel.

  • A fix in one is a fix in both. The spell checker's suggestion ranking, and three separate bugs in how selection worked, were all found while QUILL Lite was being built — and were fixed in the shared code, so every QUILL user got them in the same release.
  • A key you learn in one works in the other. Every QUILL Lite command is mapped to the QUILL command that means the same thing, and a test fails the build if the two ever drift onto different keys without a written reason. There are ten such reasons today, and each one is a paragraph arguing its case rather than an accident nobody noticed.
  • QUILL Lite is never allowed to be ahead of QUILL. That is a family rule — the tenth of eleven — and it is enforced rather than hoped for: if QUILL Lite needs something QUILL cannot do, the capability goes into the shared package and QUILL gets a way to reach it in the same change. It is how QUILL ended up with numbered bookmarks, with six rich-text commands it had the engine for and no keys to, and with the entire free hosted AI.

Why subtraction only runs one way

QUILL Lite stays small by being switchable, not by being poor. Twenty whole feature areas can be turned off in Tools, Customize Features, and switching one off takes its menu and its keys with it — because a key that still fires for a feature you turned off is the feature not being off. Four named starting points do it in one move: Recommended (16 of the 20 areas), Everything (all 20), WordPad (5, and Ctrl+N makes a rich text document) and Notepad (2, and Ctrl+N makes a plain text one).

QUILL has the mirror image of that dial: eleven feature profiles, from Essential and Writer through Braille and Screen Reader Power User and Accessibility Professional to Full Quill. One of the eleven is called QUILL Lite, and it does what its name says: it reduces QUILL to nine menus — a plain-text editor with rich text, spelling, the line tools and the clipboard — and makes Ctrl+N produce a plain text document.

So the asymmetry is the whole design. You can make QUILL look like QUILL Lite. You cannot make QUILL Lite become QUILL. If you are genuinely unsure, that is an argument for starting with QUILL. The honest counter-argument is that an editor with nine menus is faster to learn, and nobody has ever got lost in it.

What is identical in both

Everything in this list is the same in both products, to the same standard, enforced by the same tests. If you are choosing between them, you are not choosing between an accessible editor and a less accessible one.

  • Every enabled menu item shows a keyboard route in its label, and no two items in one menu bar claim the same key. Both are build gates rather than intentions. Walking a menu to discover there is no shortcut is a cost you pay on every visit, and a key claimed twice means one of the pair silently never fires.
  • The app says only what your screen reader does not already say. Window titles, focus moves, control names, roles, states and list selections are the reader's job; a background result, a change on a control you are not sitting on, and the outcome of an action are the app's. Over-announcing is the failure nobody ever reports and everybody suffers, so there is a gate for it.
  • F1 answers everywhere, in every window, with what the window is for and then what the control you are on does.
  • F6 lands you in a status bar you can read cell by cell — line, word count, encoding, line endings — rather than a decoration you cannot reach.
  • Headings and lists announce themselves ("Heading 2, Installing"; "Bulleted list, 5 items"), which no Windows edit control can tell your screen reader on its own.
  • Spell check spells the word out, letter by letter or in the phonetic alphabet, because "receive" and "recieve" sound identical.
  • Your file comes back byte for byte, with the encoding and line endings it arrived with, and a window that lets you change either on purpose.
  • Unsaved work survives a crash, and the session comes back when you ask for it.
  • Every key is yours to change, in a manager that names the current owner of a key before it hands it over.
  • The same free AI, on the same five keys. Not a similar feature built twice — one implementation reached by both, so it cannot drift.
  • Free, for good. MIT-licensed, no paid tier, no trial, no account needed to use the editor. Donations cover what the AI service costs to run.

Where they genuinely differ

What you can open

This is the largest single difference, and the one most likely to decide it for you. QUILL Lite opens text and rich text: .txt, .rtf, .md, .log, .csv, .json, .py and .html. That is a deliberate boundary, not an unfinished one.

QUILL reads Word, PowerPoint and Excel; OpenDocument and Apple iWork; PDF, with local OCR for scans; EPUB and the proprietary e-book formats; braille in BRF, BRL, PEF and UEB, with translation and back-translation; DAISY and NIMAS talking books, which it also writes; email and mail archives, calendars and contacts; notebooks, subtitles, feeds, chat exports and saved web pages; TeX, reStructuredText, AsciiDoc and Org-mode; and files over FTP, SFTP, WebDAV, S3, HTTPS and GitHub. It writes Word and rich text in place, exports through Pandoc, converts in batches, and refuses at the file layer — not merely in the interface — to overwrite a PDF or a spreadsheet with text.

How documents sit on the screen

QUILL puts documents in tabs, in one or more windows: Ctrl+T for a new tab, Ctrl+Tab to move between them. QUILL Lite numbers them instead, as children of a single window, from 1, and never reuses a number while its document is open — because "Document 3" is a name you can hold in your head and say out loud, and "the other Untitled" is not.

That choice has a cost, and QUILL Lite states it rather than hiding it: numbered child windows do not appear in Alt+Tab, so the whole job of moving between documents falls on the app. It carries that four ways — Ctrl+F6, Ctrl+Tab, Alt+1 to Alt+9, and the Window menu — and every document's title leads with its number, because the title is the one string your screen reader reads on arrival.

Speech, and the decision not to have a voice

QUILL Lite speaks through a running NVDA or JAWS and nowhere else. No SAPI, no synthesised voice of its own — because a second voice talking over a screen reader is worse than silence. For anyone with no reader running, every message is also in the status bar, which is exactly why the status bar is focusable.

QUILL does have its own voice, on purpose and as a separate feature: Read Aloud in a secondary voice, offline speech engines that never touch the network, batch document-to-speech, audiobook building from a folder, offline transcription, and voice commands. If you want a document read to you while you do something else, that is QUILL.

Braille

QUILL has a Braille mode: it opens and writes BRF, BRL, PEF and UEB, translates and back-translates through liblouis, validates and repairs files, detects page structure, and drives braille-specific status cells on a display. QUILL Lite has none of it, and that is the clearest single reason a braille reader should install QUILL.

AI: the same five commands, and then everything around them

The free hosted AI is at parity, deliberately — summarising or explaining a passage is disproportionately valuable to somebody who cannot skim, which is why it was the one exception to QUILL Lite's no-AI rule. Both products have the same AI pad on Ctrl+Alt+G, the same document question on Ctrl+Alt+Z, the same Use My ChatGPT Subscription on Alt+F5, the same Ask About an Image on Ctrl+F5, the same web-search checkbox, the same conversations and the same ten writing tools — behind the same two gates: a privacy agreement you have to read, and a connection you have to make.

What QUILL adds is everything around that: bring your own key, a provider list with a default cascade, local on-device models, interchangeable agent harnesses, a prompt library, shareable prompt and skill packs, grammar checking, alt text for images, and a wizard to set it all up.

The environment itself

This is what the word "Lite" is really about. QUILL has Quillins — sandboxed extensions, twenty-three of them bundled, plus a community hub — the eight QuillVille companion apps on one launcher, Git and GitHub as first-class citizens, remote sites, accessible library and NLS BARD search, document compare, watch-folder automation, macros, timer events, sticky notes with global hotkeys, equations, tables and a table studio, Reveal Codes, Story Studio, an accessible notes vault with backlinks, an accessibility auditor that produces a conformance report, internet radio and podcasts inside the editor, and a nine-page wizard to introduce them. QUILL Lite has none of it, and opens instantly.

Five gaps in QUILL, found by building QUILL Lite

Five commands exist in QUILL Lite and not in QUILL: Print Preview, Unfold All, Paste Collected, Clear Collected, and closing one numbered child window. Under family rule 10 that is not a feature list, it is a bug list, and the codebase tracks it as one — capped, so it cannot quietly grow. It is on this page because a comparison that only flattered the larger product would not be worth reading. (A sixth entry, Underline, is on the internal list only because QUILL's Ctrl+U is wired straight into the editor instead of through the keymap. It works.)

Moving from QUILL Lite to QUILL

This is a supported path with a menu item behind it, not a migration you do by hand. QUILL's Bring my QUILL Lite settings shows you a plan before it does anything, and then treats two kinds of state differently, for a reason.

  • Content is shared from then on. Abbreviations, your personal dictionary, the copy tray, the clip library and per-file bookmarks are things you build up over months, so they are merged into QUILL's folder and QUILL Lite is pointed at it. After that, a change in either editor is a change in both.
  • Preferences are copied once, and then allowed to drift. Wrap, autosave, spell-check-while-typing and your rebound keys are about the editor you are in — and a chord you rebound in a nine-menu editor should not silently rebind something in a twelve-menu one.
  • Nothing you already have is lost. QUILL's own entry wins every collision, in every store, because anyone running the import has been using QUILL and what is already there is the more recent of the two.

The two products also store five settings under different names — QUILL Lite's autosave_seconds is QUILL's autosave_interval_seconds, for one — so the importer translates rather than copies. You never see any of that, which is the point of it being written down in one place and tested.

The full comparison, category by category

Eleven categories of capability, compared for QUILL 0.9.0 Beta 2 and QUILL Lite 1.1.2, as of 30 September 2026. In every table the first column names the capability, the second column is QUILL, and the third column is QUILL Lite. A dashed line down the left edge of a row means one of the two does not have that capability; the words in the row say which.

It is eleven tables rather than one long one so that heading navigation reaches every category, so that your screen reader's table list becomes a way to move between them, and so that you hear "row 5 of 18" instead of "row 82 of 152". What that costs is the ability to sweep the whole matrix in one pass, which is why each table opens with a sentence that answers it in words first.

Download either one

Both are free. Every installer and portable build is digitally signed, so Windows can confirm it has not been altered, and neither program takes over your file associations without being asked.
