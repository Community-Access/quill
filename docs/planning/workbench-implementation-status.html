GitHub and WordPress Workbench implementation status

Updated: 2026-11-17
Status: WordPress’s last requirements are in code (#1842). GitHub resumed on 2026-11-15 and is the current focus.

The accepted specifications are the GitHub Workbench PRD and WordPress Workbench PRD. This page records delivery state and later decisions; the PRDs remain the complete statement of accepted product requirements. The line-by-line checklist for both Workbenches is complete.md at the repository root (sections 7 and 10B); the WordPress progress log is section 18 of wordpress.md.

Current scope decisions

  • WordPress plugin-specific integrations in this implementation are QUILL Accessible Forms (QAF), Gravity Forms, Paid Memberships Pro, WooCommerce, The Events Calendar and Yoast SEO.
  • 2026-11-13: WooCommerce (wc/v3), The Events Calendar (tribe/events/v1) and Yoast SEO (yoast/v1 and the post meta it registers) are now supported integrations. Jeff’s newer instruction to get everything listed in wordpress.md 19 (Packages 8 to 13) replaces the earlier limit to QAF, Gravity Forms and PMPro. What each does, and what stays in wp-admin, is in wordpress.md’s progress log for that date.
  • QAF and Gravity Forms are the supported form systems. Paid Memberships Pro is supported through its documented WordPress Abilities API for levels, member memberships, orders, subscriptions, and search, with its older pmpro/v1 routes as the fallback and for discount codes and access checks. The site’s own capability checks remain authoritative for every operation.
  • The site administration sweep adds the Redirection plugin’s redirects and 404 log (redirection/v1), which is not a first-class integration. Every other area of running a site (backups, security, caching, multilingual, email, newsletters, courses, analytics, sharing) has a recorded disposition per site, shown in Administration Areas; which of them to make first-class is Jeff’s call.
  • Other plugin-specific form and membership integrations are outside the current delivery scope and are labelled deferred (MemberPress, Restrict Content Pro, WPForms, Ninja Forms, Formidable, Contact Form 7, Fluent Forms, Forminator). The general WordPress route and Abilities discovery features remain part of the Workbench.
  • The classic GitHub Items/Explore and WordPress management-window fallback choices are retired. The editor doors open the Workbench.

WordPress

Done

Everything below is in S:\QUILL, uncommitted on codex/workbench-combined-2026-11-10, as of 2026-11-13.

  • Frame and doors. The Workbench has its own rebindable APP_KEYMAPS entry, built from its menu table (workbench_window_menu.py). Delete, Shift+Delete and Ctrl+Z act on the list only. This Post in the Workbench (File > WordPress, both editors) opens the post’s list with it selected, and Insert > Picture from the Media Library opens the Workbench in picking mode. Updates, Membership Orders, Shop, Shop Orders and Podcast are real lists; no planned node is left.
  • Discovery and content model. Taxonomy bases, statuses and query enums are discovered; custom types have status nodes, New, filters and batch; the Content Model names the registrant; registered meta on terms, users and comments is editable in Properties; the seven plugin orderings have spoken labels.
  • What REST cannot do. Plugin, theme and Across Sites rows say what core REST cannot do (update, auto-update, theme activate and install) and offer Open in Dashboard; Install on Sites Missing It installs a plugin by slug after a preview.
  • Gravity Forms. Feeds (activate, rename, delete with undo), Results, entry Notes, Star, Read, Resend Notifications with a recipient preview, field filters in the Filter Builder, Test This Form through the validation route, a whole-form Copy to Site, and Change a Field Type, which now accepts Full access and reads the form back after saving.
  • Paid Memberships Pro. pmpro/v1 classified and used as the fallback; Discount Codes, Look Up a Discount Code, New Discount Code, Check Membership Access, Change Membership Level and Cancel Membership, each with a per-run preview of the subscription and gateway consequences. Card and billing fields are stripped from every row.
  • QAF spam. Spam and Not Spam go through QAF’s spam routes; a held response gives QAF’s reason; the site’s Properties has a read-only Spam page from qaf/v1/spam.
  • Site administration sweep. Site Health > Information and Security (an XML-RPC check); WordPress.org theme search and language pack status behind consent, with their own egress row; Redirects and 404 Log; Content Audit and Media Housekeeping with usage before trashing; Privacy Requests as exact wp-admin pointers; Search and Upkeep with each answer’s source; Administration Areas with every third-sweep row’s disposition.
  • By Name and Across Sites. Rename, split, merge, reassign, replace and find-missing over every By Name kind, including template parts; Make Them the Same for terms, plugins, settings, people, patterns, menus and themes; Compare Global Styles; Promote to Network on a multisite; Revoke Everywhere for application passwords; Fleet columns with known, unknown, unavailable and stale states; a classified scope matrix.
  • Bold workflows. Copy to Site, Compare Sites, snapshots and Put Back from a Snapshot, Calendar and Move to Another Day with daylight-saving checks, the editorial queue (Assign a Reviewer, Send Back, Approve and Schedule), Read Site as Document, Watches (site down, review and health added), the REST Console (Accepts, What It Returns, saved requests), list export and import, Import a Folder of Documents, and the Plain-Language Batch.
  • People. Their Application Passwords, Sign Out Everywhere (a wp-admin pointer) and Invite from a Spreadsheet.
  • Practice Site. Bundled CLI, PHP and WordPress core, loopback only on 127.0.0.1:9400, plain HTTP allowed to that address alone, a full reset warning, and three practice-only tutorials in QUILL. The 2026-11-13 source run passed start, handoff, sign-in, restart, Workbench close and reset.
