Appendix A: What GitHub needs for each part of the Workbench

What this appendix covers

You are looking after an organization and deciding what to let people do, or a command said it could not do something and you want to know why. This appendix is for you.

The Workbench can do anything GitHub lets your account do, and nothing more. Three things decide what that is, and this appendix lists, part by part, what each one needs:

  • Your role on the repository or organization: read, triage, write, maintain or admin on a repository; member or owner in an organization. A custom role counts as whatever it grants.
  • Your sign-in’s permissions, called scopes. Sign In with GitHub asks for every scope the Workbench uses (Chapter 1). A token you made yourself has only what you gave it. Account > GitHub Permissions… (Ctrl+Shift+P) lists them all, and which you have.
  • Your Workbench level, Read Only, Organize or Full, which QUILL checks before GitHub is asked (Chapters 1 and 13).

Some parts also need a feature GitHub turns on only for certain repositories, organizations or plans. Those are named in the last column.

How to read it

  • Role is the role the Workbench checks for before it offers a command, which is the smallest role GitHub asks for. An organization can make GitHub stricter; GitHub’s answer always wins.
  • Workbench level. Read Only reads everything. Organize adds organizing changes, such as labels, reactions and stars, and changes other people will see, such as comments, merges and re-runs. Full adds access and settings changes, and anything destructive or hard to reverse, such as deleting. Shift+F1 on a command says the level it needs.
  • When it is missing. QUILL does not guess. A place you cannot read says why on its one row, and a command you cannot use is greyed, and Shift+F1 says why. When GitHub itself refuses, QUILL says so and names the permission or scope GitHub asked for (Chapter 10).

Enterprise Server

An account on a GitHub Enterprise Server reaches the same parts, if that server’s GitHub has them. When it does not, QUILL says “This server’s GitHub does not have” that part, with the server’s name and version, and sends nothing more for it. Enterprise accounts, and administering the server itself, are not part of the Workbench.

Outside GitHub

Two commands read something other than GitHub, and both say so first:

  • Help > GitHub Service Status… (Ctrl+Alt+F1) reads www.githubstatus.com, only when you ask.
  • Use GitHub CLI Sign-In… asks the gh program on your computer for its sign-in. Nothing leaves your computer for it.
