Chapter 11: Keyboard reference

What this chapter covers

Every key the workbench answers to, one window at a time. Keys marked as access keys are the underlined letters of a control, pressed with Alt; they work while that window has focus. Keys that open the windows themselves are in Chapter 1. QUILL’s GitHub menu commands have no keys out of the box, and you can give them some in the Keymap Editor.

Throughout, Shift+F10 or the Applications key opens the context menu of whatever has focus, and Escape closes the window you are in. The Workbench itself is the exception: Escape never closes it, and Alt+F4 does.

The GitHub menu, in workbench mode

GitHub Workbench Mode is View > GitHub Workbench Mode: Alt+V, then K. While it is on, Alt+G opens the GitHub menu, and these letters choose a row in it. They are the same in both apps; the rows marked QUILL only are not in QUILL Lite’s menu.

None of these rows, and not the mode itself, has a key out of the box. A key you give one in the Keymap Editor works in both modes.

The line or lines you are on, on GitHub (Chapter 7). In QUILL it is a submenu of the GitHub menu (R), and of Tools > Git and GitHub > GitHub (L) when workbench mode is off; in QUILL Lite its rows are in the GitHub menu itself.

An issue form

An issue form’s fields are named by the form itself, so they have no access keys; Tab moves through them in order. Enter, outside a large text box, is Create Issue, and Escape closes without sending.
