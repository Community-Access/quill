# Chapter 15: Help, updates and support

This last chapter is about the help that is always within reach. You will meet
the Help menu, the F1 key that explains whatever you are standing on, the
guided tutorials, and the support form that puts you in touch with a real
person. It also covers keeping QUILL up to date. Read it early if you like to
know where the safety rails are, or come back to it the first time you feel
stuck.

## The Help menu

The **Help** menu is where QUILL turns into a guide. It is not a dead end with
an About box at the bottom: most of what is on it does real work. The welcome
guide teaches the basics, the keyboard reference shows the keys you actually
have, the user guide gives you the full map, diagnostics capture what QUILL is
doing right now, and **Get Help from Support...** turns all of that into a
message somebody can answer.

The menu stays steady while you arrow through it quickly. QUILL waits until
the menu closes before it updates anything on it.

### Guides and references

- **Help on This Control** (`F1`) tells you about whatever you are on. Chapter
  2 has the details.
- **Announce Mode Shortcuts** (press the QUILL key, then `Shift+H`) says the
  handful of keys that matter where you are right now: the browse-mode keys
  while you are in QUILL browse mode, the status bar keys while you are on the
  status bar, and the everyday editing keys otherwise.
- **Show Spoken Echo** (`Alt+Shift+E`) shows the last things QUILL said, so
  you can read them at your own pace. Chapter 11 has more.
- **Open User Guide** (`Ctrl+Shift+F1`) opens this guide in your web browser.
  It is found beside the program, so it opens the same way however you started
  QUILL, even when you opened a file with it from File Explorer.
- **Open GitHub Guide** (press `Alt+H`, then `I`) opens the GitHub Guide, the
  book about doing GitHub work in QUILL with a screen reader, in your web
  browser. It has no shortcut key, because you open a manual to learn rather
  than while you write. Pressing `F1` in GitHub Items, Explore GitHub or the
  review window offers it too.
- **Open Welcome Guide** opens a lighter getting-started document that knows
  which feature profile you are using.
- **Open Keyboard Reference** (the QUILL key, then `Shift+K`) builds a fresh
  list of shortcuts from the keys that are bound right now, so it always
  matches your setup.
- **Tutorials...** (`Ctrl+Alt+F1`) opens the guided lessons. They have their
  own topic, [Tutorials](#tutorials), later in this chapter.
- **What Can I Do Here?** gives help that fits what you are doing at the
  moment.
- **Why Don't I See a Feature?** explains why a command is hidden by your
  feature profile.

### Activity and Repeat Last Result (Shift+F9 and F9)

**Activity...** (`Shift+F9`) lists everything QUILL told you in this session,
newest first. Each row says what you can do about it, with these buttons:
**Retry**, **Open Folder**, **Copy Details** and **Clear List**.

- If a settings file could not be saved, QUILL says so once, with the reason.
  Its row has a Retry that saves again and an Open Folder that shows you the
  folder on disk. When a later save works, QUILL tells you that too.
- Background work that finishes after you closed its window lands here as a
  row to review, so the result is not lost.
- Nothing in the list leaves this computer, and no document text is ever in
  it.

**Repeat Last Result** (`F9`) says the newest result that mattered again. That
is the last thing QUILL itself told you, not the last thing your screen reader
read. It also names what Activity offers for that result. The same two keys
do the same thing in QUILL Lite, Quill Radio and QUILL Cast.

> **QUILLBee's tip:** Missed what QUILL just said because your screen reader
> talked over it? Press `F9` and you will hear it again.

### Status, diagnostics and setup

- **Status Page** opens a live view of what QUILL is doing right now. The
  Application Status page topic in this guide describes it.
- **Save Diagnostics...** writes a diagnostics bundle on this computer. You can
  look through it before you share it with anyone.
- **Copy Log** puts this session's log file, `quill.log`, on the clipboard,
  ready to send to support. [Sending your log to
  support](#sending-your-log-to-support) explains how to use it.
- **Feature Profiles** gathers the profile commands:
  - **Switch Profile...** (`Alt+Shift+P`) chooses another profile.
  - **Profile Health Check...** gives a short report on your profile: which
    one is active, and whether any command has been left without a feature to
    belong to, or switched off when it should not be. Most of the time it
    ends with "No coverage problems found". It is mainly useful when support
    asks you to read it to them.
  - **Manage Individual Features...** (`Ctrl+Alt+F10`) turns single features
    on and off.
  - **Undo Last Profile Change** puts back the profile you had before your
    last change. If there is nothing to undo, it says so.
  - **Reset to Essential Profile** goes back to the smallest, simplest
    profile. It asks first, with **No** already chosen.
- **Personalise QUILL...** is the first-run setup wizard. Run it again whenever
  you like to adjust your keyboard pack, feature profile, remote access, AI,
  reading and accessibility, writing tools, data location, and startup
  behaviour. [Personalising QUILL](#personalising-quill) walks through it.
- **Get Help from Support...** (`Ctrl+Alt+F2`) opens the support form. When you
  have filled it in, QUILL hands the message to your own mail program,
  addressed to **support@community-access.org**. A person reads and answers
  it. It is not a public issue tracker, and you do not need an account
  anywhere. The steps are in
  [Get Help from Support, step by step](#get-help-from-support-step-by-step).

### Updates, About and notices

- **Check for Updates...** checks the signed update list, offers you the
  download, and can close QUILL so setup runs straight away. Installed and
  portable copies are handled differently;
  [Checking for Updates](#checking-for-updates) explains both.
- **What's New** (the QUILL key, then `W`) opens QUILL's changelog, the list
  of everything that changed in each version, in your web browser. The other
  QuillVille apps use `Ctrl+Shift+F1` for it, but that is the User Guide here,
  so QUILL's key is on the QUILL key instead; `Alt+H`, then `W`, works too.
  Every QuillVille app has the same command on its Help menu.
- **About Quill** shows the version, publisher details, and the third-party
  components QUILL uses, each with its license and version. The version has a
  build number, such as 1.0.0 (build 2): the build number tells you which build
  of a version you have, and a fix shipped without a new version number comes
  as a newer build that Check for Updates offers you.
- **Open Third-Party Notices** opens the full notices document, with tables of
  those components and the text of every bundled license.

### On a Mac

On macOS the **Help** menu is the system Help menu, so the usual `Cmd+?`
shortcut opens it. (See Appendix D, Notes from earlier versions.)

## Help, Learning, and Daily Confidence

Nobody remembers everything, and QUILL does not expect you to. There are
several layers of help, and you can reach each one from the keyboard.

- **F1** gives help on the control that has focus. It works anywhere in QUILL.
- **Open User Guide** (`Ctrl+Shift+F1`) is for when you want the full map.
- **Open Welcome Guide** is for when you want a lighter introduction.
- **Open Keyboard Reference** (the QUILL key, then `Shift+K`) is for when you
  want the exact keys you have now.
- **Key Cheatsheet** gives you a quick list of shortcuts. It has no menu
  row: press `Alt+Shift+/` (or `Ctrl+F1`), or find it in the Command Palette.
- **What Can I Do Here?** (`Ctrl+Alt+Shift+F1`) gives help on the spot, for
  the document you are in.
- **Why Don't I See a Feature?** is for when a command seems to have
  disappeared.
- **Why Is This Unavailable?** (`Alt+F1`) is for something you can see but
  cannot use. Move to the greyed-out button or menu item and press `Alt+F1`,
  and QUILL tells you why it is turned off.

That last one is worth remembering. When something you expected is missing,
it tells you why, usually because your feature profile hides it, so you are
not left guessing.

### Context-Sensitive Help (F1)

Press `F1` on any control in QUILL that can take focus, and a small help
window opens. It tells you:

1. **The dialog you are in**, when you are inside one: its name and a plain
   summary of what it does, so you always know where you are.
2. **The focused control**: what it is, how it works, and which keys apply to
   it.

All of that text is in one read-only field, so your screen reader reads the
whole thing in one go when the window opens. There are no headings to move
past.

From the help window:

- Press **Escape**, or **Enter on Close**, to go back to where you were.
- **Tab to Open User Guide** and press it to jump to the part of this guide
  that covers the control.
- In a GitHub window, the button is **Open GitHub Guide** instead, and it opens
  the GitHub Guide.

Here is how the Help keys fit together:

| Key | What it does |
|-----|--------------|
| `F1` | Help on the control that has focus |
| `Ctrl+Shift+F1` | Open the full User Guide |
| `Ctrl+Alt+Shift+F1` | Open What Can I Do Here? for the document you are in |
| `Ctrl+F1` | Open the Key Cheatsheet |
| `Shift+F1` | Open About Quill |

A few things worth knowing:

- In the main editor, F1 tells you the editor shortcuts and some writing tips.
- In dialogs such as Preferences, Find/Replace and Spell Check, F1 names both
  the dialog and the setting you are on.
- In the Personalise QUILL wizard, F1 on any control explains what that
  setting does and what you can change later.
- When you use a menu and come back to the editor, QUILL remembers which
  control had focus, so F1 still talks about the right one.

### Personalising QUILL

The **Personalise QUILL** wizard runs on its own the first time QUILL starts.
You can run it again at any time from **Help > Personalise QUILL...**.

It has six short pages, or five if you leave AI writing help off on the
Extras page:

1. **Welcome** introduces what the wizard covers.
2. **Intent** is the page that matters most. It asks one question: *What kind
   of writing do you do?* and shows a list of seven starting points. Arrow up
   and down the list. As you move, a large read-only text area below it
   changes to tell you, in plain English, exactly what you will get if you
   choose that one. No feature codes, no jargon, and no list of what you will
   miss out on. Just what you get.
3. **Extras** offers a few optional extras, such as AI writing help, Braille
   Mode and typing automation. You only see the ones your starting point does
   not already include. Each is a single checkbox, and checking one adds a
   sentence to the preview, so you always know what you are agreeing to.
4. **AI Provider** appears only if you turned AI on in Extras. It asks for
   your provider and your API key. The providers are Anthropic (Claude),
   OpenAI (GPT), Google Gemini, OpenRouter (many models), and Ollama, which
   runs models on your own computer or connects to an Ollama-compatible cloud
   host. Your key is kept safely in the Windows Credential Manager, not in a
   settings file. You can skip this page and add a key later.
5. **Keyboard and Sound** is where you choose a keyboard pack and whether
   QUILL plays sound cues. QUILL detects your screen reader and picks
   accessible defaults for you.
6. **Summary** lets you check every choice before anything happens. It is
   plain text: your profile name, which features are on, which Quillins are
   turned on, your keyboard pack and your sound setting. Use Back to change
   any page. Nothing in QUILL changes until you press Finish.

Every page starts with a heading that takes focus, so you land on the page
title first. The preview is a read-only document, so VoiceOver on the Mac
does not call it an editable text field.

**Important:** nothing is saved until you press Finish. If you close or cancel
the wizard, none of your settings change.

#### Profiles explained

QUILL comes with eleven built-in feature profiles: the ten described under
Choosing a profile, plus the QUILL Lite profile. Each one starts you at a
different amount of features and a different level of accessibility support.
The wizard offers seven plain-English starting points that lead to them; its
Writer starting point is the Casual Writer profile. You can
switch profile at any time from **Tools > Customize and Support > Profiles and
Features...** or by pressing `Alt+Shift+P`.

Choosing a profile, earlier in this guide, says who each one is for.

## Tutorials

**Help > Tutorials...** (`Ctrl+Alt+F1`) opens 29 guided tutorials: 159 steps,
about 147 minutes in all. They cover the parts of QUILL worth learning first,
in the order you would naturally learn them. They are not a second copy of
this guide. A guide can tell you what something does. It cannot tell you what
to do next, because it cannot see what you have already done. The Tutorials
window can.

### How the lessons work

- **They show the keys you have.** A step names the command it is about, and
  the key is filled in when the step is shown. If you have rebound a key, the
  tutorial says your key.
- **Try it runs the step.** Any step that names a command can be carried out
  from the lesson. A tutorial can open a window for you and then talk you
  through what you are looking at.
- **Follow me notices when you have done it.** Check **Follow me** and the
  lesson keeps an eye on QUILL, once a second. It watches what changed, never
  which key you pressed, so however you do the step, it says what it saw
  ("Done: the document changed") and reads you the next one. It never takes
  over the keyboard, and nothing is marked. Every step still has **Next**, so
  if the check never notices, it costs you one keypress.

The Tutorials window is an ordinary window, not a wizard. Leave it open, go to
your document, do the step there, and hear the lesson move on in the
background.

### Finding a lesson

The lessons are in six tracks, in teaching order. Each row says how many steps
it has, about how long it takes, and whether you have finished it. The filter
box narrows the list: every word you type has to appear somewhere in a
tutorial. Type **here** to see only the tutorials about the window you came
from.

### Your place is kept

Close a lesson half way through and it opens at the same step next time.
Finishing a lesson is remembered separately from where you are in it. **Forget
my progress** clears all of that and changes nothing else. Nothing about your
progress leaves this computer.

### Reading instead of doing

**Read it all** shows a whole tutorial as one page of text. **The whole book
as a document** opens all 24 as one page. It is made from the same lessons the
window teaches, so the two always agree. It also comes as `tutorials.md`
beside this guide. The document gives the keys QUILL comes with; only the
window knows the ones you have rebound.

Quill Radio, QUILL Cast and Quill Weather each have their own lessons, opened
with the same `Ctrl+Alt+F1` in every app. QUILL's own set covers your first
hour, writing, reading, how much QUILL says, the assistant, and the things you
meet in your second week. The menus and the command palette cover the rest.

### QUILL, Step by Step

Prefer to learn by listening? [QUILL, Step by Step](../quill-step-by-step.md) is
a separate, slower manual written to be read aloud. It has seventeen short
chapters, one skill each, with practice moments and recaps, and none of this
guide's reference tables. It comes beside this guide as Markdown, HTML and
EPUB. The EPUB opens straight into ElevenReader, Voice Dream or any reading
app, so it can talk you through QUILL while your hands stay on the keyboard.

## Get Help from Support, step by step

Use this whenever QUILL does something you did not expect, when you are
stuck, when you have a question, or when you want to suggest something. It is
the same form QUILL Lite and Quill Radio use, and it reaches a person at
**Community Access**, not a public issue tracker.

1. Choose **Help > Get Help from Support...**, or press `Ctrl+Alt+F2` from
   anywhere in QUILL. On the Help menu its letter is **L**, because **G**
   already opens the user guide. If you gave it a different key in the past,
   that key still works.
2. The form opens on **What kind of message**. Choose one of: something is
   broken, a question, an accessibility problem, or an idea or request. This
   only helps the message reach the right person.
3. Tab to **Subject** and type one short line, as you would for an email.
4. Tab to **What happened** and describe it in your own words. This is the
   part a person reads first.
5. **What you expected** and **Steps to reproduce** are optional. If you can
   give steps, they help more than anything else.
6. **Your email address** is optional too. The message goes from your own
   mail account, so support can already reply to you there. Only fill this in
   if you want the reply to go somewhere else.
7. **Screen reader** is filled in from whatever is running. Change it if it is
   wrong.
8. Below the fields, QUILL tells you what else is included: its version, your
   Windows version and, when this computer is connected to QUILL's free AI,
   your **QUILL AI support ID**. That is the number support asks for first.
9. Press **Send** (or Enter). Your own mail program opens with the whole
   message written and addressed to **support@community-access.org**.
   **Nothing is sent until you press Send in your mail program.** Read it
   over, attach a diagnostics bundle if you like, or close it if you change
   your mind. Pressing Escape in the form cancels without writing anything.

### If something gets in the way

- If a required field is empty, QUILL tells you which one and leaves you in
  the form.
- If the message is too long for a mail link, your mail program opens with the
  start of it. QUILL puts the complete text on your clipboard and tells you to
  paste it in with Control V.
- If this computer has no mail program set up (you only use webmail, say),
  QUILL shows you the address and puts the whole message on your clipboard,
  so nothing you typed is lost.
- Writing to **support@community-access.org** yourself always works just as
  well.

Want to share more detail? **Help > Save Diagnostics...** writes a bundle with
private details removed, which you review and can attach to the email.

### Sending your log to support

Sometimes support asks for QUILL's log: the running record QUILL keeps of what
it did while you were working. Finding that file by hand means knowing where
QUILL keeps its data, which nobody should have to remember. **Help > Copy Log**
(just after Save Diagnostics) does it for you. It has no key, because you will
only want it now and then.

Choose it and QUILL puts this session's log, `quill.log`, on the clipboard in
two ways at once, and says "Copied the log, quill.log, to the clipboard. Paste
it into an email to attach the file, or into a document for its location".

- **Paste into an email** (in Outlook, Thunderbird or most other mail
  programs) and the log goes in as an attachment, as if you had dragged the
  file in.
- **Paste into a document, a web form or a plain text box** and you get the
  file's full path instead, so you can tell support where it is, or open the
  folder yourself.

So the usual steps are: choose **Help > Get Help from Support...**, press
Send to open the message in your mail program, then choose **Help > Copy
Log** and paste with `Ctrl+V` into the message before you send it.

If QUILL has not written a log yet in this session, you hear "No log has been
written yet", and the clipboard is left as it was. The log is plain text, and
it can name the files you worked on, so have a read of it first if you like:
paste the path into **File > Open** and it opens in QUILL like any other text
file.

### No more GitHub reports

QUILL no longer files GitHub issues for you, and no copy of QUILL carries a
built-in GitHub "reporting token". Your own GitHub sign-in, for QUILL's GitHub
features, is separate and has not changed. Check for Updates used to offer to
"restore the token" by reinstalling the same version; that offer has gone
too, and Check for Updates now only ever offers a newer version.

## Checking for Updates

QUILL can check for updates and install them while you carry on working.

### Manual update check

To check for updates now:

1. Press `Alt+H` to open the **Help** menu.
2. Press `U` for **Check for Updates**.
3. If a newer version is out, QUILL tells you and asks whether to download it.
4. If you say yes, QUILL downloads it in the background and tells you when it
   is ready.
5. The next time you close and reopen QUILL, the update is applied for you.

### Automatic update checks

QUILL can check for updates each time it starts:

1. Press `Alt+E` to open the **Edit** menu.
2. Press `Shift+S` for **Settings**.
3. In the **Updates** section, turn on **Check for updates on startup**.

With automatic checks on, QUILL lets you know quietly when a new version is
available, and you download it when it suits you.

### Update size and speed

QUILL uses small incremental updates ("micro-updates") instead of a full
reinstall. They often download in seconds, and your settings, documents and
preferences are kept.

### Updating a portable copy

If you run the **portable** copy of QUILL, Check for Updates notices and
offers the portable `.zip` for the new version instead of the installer. It
downloads to your updates folder.

On Windows, choose **Install and restart now** and QUILL closes, puts the new
version in place of the old folder, moves your `data` folder across, and opens
again. The old version is kept beside it, as a folder ending in `.previous`,
until the new one has started three times or for a week, so that a failed
update can put it back. If a file in the folder is still open and the folders
can't be swapped, QUILL copies the new version over the old one instead, and
your `data` folder is left alone either way.

If you would rather do it yourself, choose **Extract now**: QUILL unzips the
update into a ready-to-run folder next to your current one. Copy your `data`
folder into it and start QUILL from there.

Installed copies keep getting the installer, which puts itself in place
quietly. It doesn't ask for administrator permission, because QUILL is
installed for you alone; if you installed it for everyone on the computer,
Windows may ask for permission.

### Staying on a release channel

By default, QUILL follows the Stable channel and only offers you finished
versions. To try new features early, see [Release Channels](#release-channels)
below.

## Release Channels

QUILL comes in three flavours, and you choose which one this copy follows. They're called release channels.

- **Stable** is the version we recommend. It has been checked with JAWS and NVDA, and it's what most people use. Every copy starts here.
- **Beta** gets new features a few weeks early. It's mostly finished, but some things may not work right yet.
- **Dev** is the work in progress, sometimes several builds a week. Things will break. Only choose it if a developer asked you to, or you enjoy testing.

### Choosing a channel

1. Open the **Help** menu, then choose **Release Channel...** (press **Alt+H**, then **I**). You can also get there from Settings: on the **Administration** page, the **Release channel** row has a **Change release channel...** button.
2. Arrow through Stable, Beta and Dev. As you move, the box below tells you what each one means and what choosing it would do. Nothing changes yet.
3. Press **Switch** to move. Press **Close**, or Escape, to leave everything as it was.

If you choose Beta or Dev, QUILL shows a short warning first: what could go wrong, how your settings are protected, and how to come back. Read it, check the **I understand** box, then choose **Move to Beta** (or **Move to Dev**). **Stay on Stable** changes nothing, and so does Escape.

Beta and Dev versions aren't signed, so when you install one, Windows SmartScreen may warn that it comes from an unknown publisher; that's expected, and choosing **More info**, then **Run anyway**, installs it.

### What happens when you move to Beta or Dev

- QUILL saves a copy of your settings, keys and preferences first. If it can't, it stays where it is and tells you why. Your documents aren't copied, and updates don't change them.
- QUILL then checks for updates on the new channel straight away, and offers you the newest Beta or Dev version if there is one. Nothing is installed unless you say so.
- From then on, Check for Updates offers you versions from your channel. On Stable, you're never offered a test version.

If you installed a Beta version yourself, QUILL notices the first time it checks for updates. It puts itself on the Beta channel and tells you so, and you can change it in the Release Channel window whenever you like.

### Updates on Beta and Dev

When QUILL's startup check finds a new version, it downloads it for you, as it always has, so it is ready when you are. It never installs anything without
asking: when the download is done, it says so and shows you what's new, and you
choose when to install.

On Beta and Dev, it waits instead of downloading on a metered connection, during Quiet Hours, and while Quill Radio is recording. The notifications list and Update History tell you why it waited.

### If an update doesn't start

After an update, QUILL checks that the new version really opens. If it doesn't
open within two minutes, the update undoes itself and puts back the version you
had: if the new version is still running but stuck, it's closed first. The
next time QUILL starts, it tells you so. Nothing of yours is changed, and
Update History has the details. A portable copy goes back by swapping its old
folder back in; an installed copy goes back by reinstalling the version you
had.

If the installer itself doesn't finish, nothing is changed: QUILL opens again
straight away as the version you had, and tells you the update could not be
installed. Update History has the details, and you can try again from Check
for Updates.

To make this possible, QUILL keeps a copy of the installer for the version you
have: on Beta and Dev for as long as you have that version, and on Stable for a
week or three starts after each update. That copy takes about 200 MB of disk
space, which Stable gives back once the week or the three starts are up. After
an update, the previous installer is kept until the new version has started
three times, or for a week, and then it is deleted.

### Coming back to Stable

Open **Release Channel** again and choose **Stable**.

- If the version you have is already a Stable one, you're back straight away,
  and nothing is installed.
- If you have a newer Beta or Dev version, QUILL checks whether Stable can read
  everything you have saved. If it can, choose **Go back to** (the Stable
  version) **now**, and QUILL downloads Stable and offers to install it. Your
  settings and keys come with you.
- If Stable can't read something yet, QUILL says so and gives you two safe
  choices. **Wait for Stable** keeps the version you have, stops test versions,
  and moves you to Stable by itself as soon as Stable catches up. It tells you
  when that happens. **Use the copy from** (the day you joined) puts back the
  copy of your settings and keys saved when you joined, then installs Stable.
  Anything you changed since then won't be in it, but a copy of how things are
  right now is saved first, so nothing is thrown away.
- If there's no saved copy, waiting is the only choice, and the window says so.

### Moving your other apps together

If QUILL Lite, Quill Radio or QUILL Cast is on this computer too, the Release Channel window lists it under **Also move my other QuillVille apps on this computer**. Check any you'd like to move in the same step. Every box starts unchecked.

Those apps run on one shared engine. When one of them moves to Beta or Dev, it gets its own copy of that engine, so the apps you leave on Stable are never touched. That copy takes about 335 MB of disk space, and it goes away by itself when the last of them comes back to Stable. QUILL itself doesn't use the shared engine, so moving QUILL on its own needs no extra space.

### Update History

The **Update History** button in the Release Channel window shows what the updater has done for QUILL: channel changes, the copies of your settings it saved, and so on. It's a record to read; nothing in it changes anything.

### Your privacy

Switching channels sends nothing about you. When QUILL checks for updates, the only thing it sends is a request for the list of versions.

## Secure connections and certificates

QUILL trusts the same security certificates Windows trusts. Whenever it goes
online, to check for updates, download something, talk to an AI service or
open a web address, it checks the site's certificate the way your web browser
does. A site that opens in Microsoft Edge should open in QUILL too. QUILL
Lite, Quill Radio, QUILL Cast and the other QuillVille apps all check the same
way.

If QUILL says "The site's security certificate could not be verified":

1. Check that this computer's date and time are right. A clock that is off,
   even by a day, is the most common cause.
2. Run Windows Update. It keeps the list of certificates Windows trusts up to
   date.
3. If your antivirus scans secure web pages, or you are on a work or school
   network, that software looks inside secure connections, and Windows has to
   trust its certificate for QUILL to trust it. Most antivirus programs set
   that up when they are installed. If yours did not, or you are at work, ask
   whoever looks after your computer or network.

QUILL does not skip the check to get past this message. When a certificate
cannot be verified, someone may be sitting between you and the site, so QUILL
stops before sending anything.

## Beta Feedback and Bug Reporting

QUILL is ready for serious beta use, and it has a real support starting point
built in.

### What you can use today

- Recovery state.
- Notifications.
- Extraction review.
- Exporting a bad-extraction package, for problems with extraction.
- **Save Diagnostics...**, a general command that writes a bundle on this
  computer.
- **Get Help from Support...** (`Ctrl+Alt+F2`), which writes a message to
  support@community-access.org in your own mail program, with details about
  your setup already filled in. It used to be called **Report a Bug...**.
- A diagnostics runbook and a documented support process.

QUILL helps you gather diagnostics on your own computer, check what you are
about to share, and start a clear support message without leaving QUILL.

### What is still to come

QUILL does not yet have a secure way to upload straight from the app without
signing in anywhere. For now, the **Help > Get Help from Support...** form is
the one route: it emails support through your own mail program and never
files anything on GitHub. A fuller route that needs no GitHub sign-in is
planned:

1. a Community Access feedback form on a secure (HTTPS) web page,
2. an optional upload of a diagnostics bundle you have reviewed,
3. a plain-language bug template with a summary of your setup and the steps
   to reproduce the problem,
4. alongside the in-app **Help > Get Help from Support...** form.

## What you learned, and where to go next

You now know your way around the Help menu, including Activity (`Shift+F9`)
and Repeat Last Result (`F9`). F1 explains any control, What Can I Do Here?
helps on the spot, and the Personalise QUILL wizard can be run again whenever
your needs change. You can send a message to a real person with Get Help from
Support (`Ctrl+Alt+F2`), and you know how to check for updates.

unstuck" and "Do anything by name" from the Your first hour track. On the

covers the same ground at a gentler pace.

help, for whenever you need them.
