How AI requests are routed

The family has two ways of deciding where an AI request goes.

  • Hosted AI. Used by QUILL, QUILL Lite and every app's own AI menu (Weather, Converter, Player, Inkwell, Transcribe, Cast, Studio and WordPress). Every request goes through ConnectionRouteMixin.request_connection in quill/ui/hosted_ai_connection_route.py. That function reads the one stored choice, ai_connection, and does three things:

    • it refuses with a sentence when the chosen AI is not ready or cannot do the request (connection_choice.py, GATE-CAPS);
    • it asks "Send to a Different AI?", with No as the default, before a different company is used (hosted_ai_route_guard.py);
    • under Auto, it names the recipient before sending ("Auto chose X. Your request will go to Y."), and any retry is a Yes/No question.

    Which AI Am I Using and Choose Your AI describe this route accurately.

  • Advanced AI, QUILL only. Used by spell check, grammar, translate, Document Q&A, thesaurus, metadata, rewrite, summarize, Describe Image and similar commands, plus agents, Ask Quill and Improve Reading Order. The route comes from assistant_connection.json and the legacy key, through _ai_require_connection (main_frame.py near 10536), ProviderChatBackend() or make_default_backend(). This route never reads ai_connection, and Which AI Am I Using does not describe it.

Most of the gaps below come from the second route, or from features that pick a provider on their own.

Suspected silent switches and gaps, not yet verified

The first ten are the ones where the person's data could go somewhere they did not choose.

  1. Cached assistant keeps the old provider. _get_assistant builds the assistant once (main_frame.py near 10026), and nothing resets it when the provider changes. After a switch from a cloud AI to Ollama, the old cloud provider keeps receiving requests until restart from:
    • Improve Reading Order, whose confirmation names the new provider;
    • watch-folder AI actions;
    • Train Writing Style;
    • chapter inference.
  2. make_default_backend ignores "Off". At assistant.py:184 there is no else branch, so the default provider is then used with no note. The watch folder only checks load_ai_enabled, so file text could reach a cloud provider after the person chose Off.
  3. Signing out of an Ollama own key moves requests to OpenAI. This is a local-to-cloud switch. hosted_ai_own_key_route.py:76-83 sets ai_own_key_provider = OPENAI, and ai_connection stays own_key. If an OpenAI key or OPENAI_API_KEY exists, route_chosen() records that as the person's choice, so the route guard never asks. Meanwhile the announcement says "No AI is in use".
  4. Ask About an Image names the wrong company and asks no consent. hosted_ai_image.py:57-61 always says OpenAI and ChatGPT, whatever the connection is. cmd_ai_image never calls ask_picture_consent.
  5. Share consent is enforced only in Ask Quill. _ai_require_connection, ProviderChatBackend users and Describe Image skip provider_consent_granted. A key saved through Use My Own AI Key never gets that consent, yet the advanced commands send to it.
  6. Agent engine fallback is status-only. In agent_responder_selection.py:36-46, "X is not set up; using Native." Native is the assistant provider, which may be a different company. There is no Yes/No.
  7. Advanced features do not follow Choose Your AI. This is the second route described above. It is a design question as well as a defect; see the decisions section below.
  8. Signing out of an own key leaves the legacy key mirror. clear_provider_api_key removes only the per-provider key. Advanced commands keep sending to that provider after "Signed out".
  9. Picture Maker bypasses the chosen connection. picture_maker.py:130-143 falls through to the advanced provider. The consent box does name the company, but the description step goes to settings.host while the box shows DEFAULT_HOSTS.
  10. GitHub Summarize Discussion and Explain Selected Change use _ai_require_connection, which is the legacy route: the provider is not named and there is no per-request consent.
    • Explain Selected Change also wraps its prompt inside the "Summarize this GitHub discussion" prompt (github_pr_diff_dialog.py:286 into thread_summary.py:73).
    • Its help text promises consent that does not happen.

Further gaps:

  1. Review Dictation under Auto names the wrong recipient in its consent question (windows_dictation_review.py:98-112). Under Auto it falls through to "OpenAI, with your own key".
  2. Studio Generate Captions (Offline) can upload audio. studio.py:1667-1685 _speech_provider returns a cloud Quillin transcriber when one is chosen in Speech Hub. There is no requires_network check and no consent. QUILL has the same pattern at main_frame_speech.py:42-54.
  3. A legacy key can be sent to the wrong company. provider_backend.py:48 uses load_provider_api_key(provider) or load_assistant_api_key(), and the legacy store can hold another provider's key.
  4. A new app's first choice is made silently. migrate_choice stores an own-key route, and the direct route then skips the privacy agreement. This is arguably by design.
  5. Low severity.
    • make_default_backend runs on a worker thread while mutating module state that is documented as UI-thread only.
    • resolve_dictation_provider calls _speech_provider(registry=...), which takes no arguments. That is a probable TypeError, but not a privacy issue.
    • The WordPress Ask the Site help says QUILL asks before an ability's result is sent back, and it does not.
    • Several WordPress commands say "your chosen AI" where ai_name() is available.

Already guarded, no change needed:

  • fallback.plan_fallback and plan_substitution only build offers.
  • The Ask Quill substitution hold (backend_substitution).
  • The hosted route guard and Auto's announcement and retry question.
  • Strict cloud-voice and diarization dispatch.
  • Player recap, Cast chapter cues and Studio chapter-title transcription stay local.
  • Voice-reply fallbacks are announced.
  • Windows dictation asks before sending to OpenAI.

Decisions for Jeff

  • Should the advanced route follow Choose Your AI? If it should, gaps 1, 2, 5, 7, 8, 9 and 10 mostly fall away. If it stays separate on purpose, Which AI Am I Using should describe both routes, and each advanced command should name its provider before sending.
  • Gap 14. Should a new app's first AI request ask, rather than inherit the family's own key silently?
